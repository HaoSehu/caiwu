### 5.1 backend

#### 5.1.1 执行结论

- 后端全量测试未全绿
- 至少存在 1 个已复核失败项
- 已复核失败项位于：
  - `Tests\Feature\ProvisionServiceHostnameTest::ensure_local_service_uses_resolved_hostname_as_instance_name`

#### 5.1.2 已复核失败详情

- 测试类：`ProvisionServiceHostnameTest`
- 测试方法：`ensure_local_service_uses_resolved_hostname_as_instance_name`
- 失败类型：`QueryException`
- 实际报错：
  - `services.product_id` 外键约束失败
  - 插入 `services` 时引用了 `product_id = 501`
  - 当前数据库中该 `products.id` 记录不存在

失败堆栈显示：

- 业务代码触发点：`backend/app/Services/ProvisionService.php:257`
- 测试触发点：`backend/tests/Feature/ProvisionServiceHostnameTest.php:587`
- 测试数据构造位置：`backend/tests/Feature/ProvisionServiceHostnameTest.php:371` 与 `:425`

#### 5.1.3 当前可信结论

可以确认的事实：

- 该失败真实存在
- 失败由测试场景中的 `product_id=501` 引用和数据库外键约束冲突触发

本报告不再沿用“`Product` 模型 `$guarded` 阻止写入显式 ID”这一说法，因为当前 `Product` 模型实际定义的是 `$fillable`，未见该结论所依赖的证据。

## 6. 失败与阻塞项

### 6.1 FAIL-01 后端测试失败

- 标题：`ProvisionServiceHostnameTest` 中本地服务创建场景失败
- 模块：`backend / ProvisionService / 测试场景数据构造`
- 级别：`P2`
- 复现命令：

```bash
cd backend
php artisan test --filter=ProvisionServiceHostnameTest --stop-on-failure
```

- 实际结果：
  - `ensure_local_service_uses_resolved_hostname_as_instance_name` 失败
  - `services.product_id` 外键约束报错
- 预期结果：
  - 测试通过，服务记录可正常创建
- 当前可确认定位：
  - 问题与测试场景中 `product_id=501` 的引用相关
  - 不能仅凭现有证据断定是生产代码问题，还是测试构造问题
- 影响：
  - 后端自动化测试未全绿
  - 当前版本不应宣称“后端全量自动化通过”

### 6.2 FAIL-02 用户端测试断言与实现不一致

- 标题：`machineSpecOptions.test.mjs` 与 `machineSpecOptions.js` 行为不一致
- 模块：`frontend-client / machineSpecOptions`
- 级别：`P2`
- 复现命令：

```bash
cd frontend-client
node tests/machineSpecOptions.test.mjs
```

- 实际结果：
  - 测试期望 `cpuOptions.map(item => item.id)` 为 `['2核', '4核']`
  - 当前实现实际返回 `['2', '4']`
- 证据：
  - 测试断言位置：`frontend-client/tests/machineSpecOptions.test.mjs:40`
  - 实现位置：`frontend-client/src/views/website/products/machineSpecOptions.js:6`
- 当前可信定位：
  - “测试与实现不一致”是确定事实
  - 不能仅凭本轮结果直接下结论说“一定是测试过时”或“一定是生产代码错误”
- 影响：
  - 用户端自动化测试未全绿
