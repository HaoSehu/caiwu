## 二、前端三端并存

真实前端不是单一 `frontend/`，而是三个并列目录。

### 2.1 `frontend-admin`（管理端）

- 端口：`127.0.0.1:5174`
- 启动：`npm run dev`
- 技术：Vue 3、Vite、Element Plus、Pinia、axios、Sass
- 视觉基线：亮色企业控制台，列表页默认是页头 -> 筛选区 -> 表格卡片 -> 分页
- 鉴权存储：
  - `localStorage.admin_token`
  - `localStorage.admin_last_active_at`
- 说明：`userType` 是运行时 store 状态，不是当前持久化鉴权入口

### 2.2 `frontend-client`（用户端 + 官网）

- 端口：`127.0.0.1:5173`
- 启动：`npm run dev`
- 技术：Vue 3、Vite、Element Plus、Pinia、axios、Sass
- 视觉分区：
  - 官网首页、产品页、登录页允许更强视觉表达
  - 用户中心、账单、服务、工单仍以浅背景 + 白卡片 + 品牌蓝为主
- 鉴权存储：
  - `localStorage.client_token`
  - `localStorage.client_last_active_at`

### 2.3 `shared`

当前主要承载跨端通用状态展示能力：

- `shared/statusConfig.js`
- `shared/extraStatusMaps.js`
- `shared/components/StatusTag.vue`

涉及状态文案、状态色和状态标签时，优先复用这三处，不再平行写一套。

## 三、后端架构形态

### 3.1 框架与运行时

- PHP 8.2
- Laravel 12
- 鉴权：Sanctum Token
- 缓存驱动：Redis（`CACHE_STORE=redis`）
- 队列驱动：database（`QUEUE_CONNECTION=database`）
- 会话驱动：file（`SESSION_DRIVER=file`）
- 本地统一入口命令：`php artisan app:serve`

### 3.2 认证链路

管理端和客户端都使用 Sanctum Token：

- 登录接口：
  - `POST /api/admin/login`
  - `POST /api/client/login`
- 签发方式：`$user->createToken(...)->plainTextToken`
- 守卫中间件：`auth:sanctum` + `ensure.admin` / `ensure.client`
- 权限中间件：`permission:{code}`
- 回调验签中间件：`verify.callback`

### 3.4 路由分工

- `routes/admin.php`
  - 管理端鉴权、权限、用户、商品、发票、工单、设置、日志、内容等接口
- `routes/client.php`
  - 客户端登录、实名、发票、充值、服务控制台、工单、返佣等接口
- `routes/api.php`
  - 公开站点接口，主要是 `/api/site/*` 和 `/api/health`
- `routes/web.php`
  - 根路径、注册页兼容入口、受控资源查看等非 API 路由

### 3.5 统一响应

- Trait：`App\Traits\ApiResponse`
- 构造器：`App\Support\ApiResponseBuilder`
- 成功响应：`{"code": 0, "message": "...", "data": ...}`
- 分页响应：`{"code": 0, "data": {"list": [...], "total": N, "page": N, "page_size": N}}`

## 四、数据库现状

### 4.1 当前实库基线（2026-04-22）

- 库名：`idc`
- `information_schema.tables` 中基础表数量：**42 张**
- 当前仓库数据库结构文档分两层：
  - `文档/数据库/当前数据库结构.md`：当前 `idc` 实库结构的可读化摘要
  - `文档/数据库/数据库结构说明-idc-2026-04-17.md`：带日期的历史快照

- 已确认 `media_files` 是当前真实表，不是旧文档遗漏项

### 4.2 当前基础表清单摘要

当前 42 张基础表包括：

- 账户与权限：`users`、`user_accounts`、`admin_users`、`admin_user_roles`、`roles`、`personal_access_tokens`
- 交易：`orders`、`invoices`、`invoice_items`、`payments`、`payment_callbacks`
- 服务与商品：`products`、`product_groups`、`suppliers`、`services`
- 内容与媒体：`content_articles`、`content_categories`、`media_files`
- 营销与返佣：`coupons`、`coupon_campaigns`、`user_coupons`、`referral_rewards`、`referral_account_logs`、`referral_withdrawals`、`member_levels`
- 运维与日志：`operation_logs`、`automation_logs`、`notification_logs`、`email_logs`、`sms_logs`
- 工单与系统：`tickets`、`ticket_replies`、`settings`、`servers`、`jobs`、`failed_jobs`、`sessions`、`password_reset_tokens`、`migrations`
- 账户流水与实名：`balance_logs`、`account_transactions`、`verification_histories`

### 4.3 迁移现实

仓库中的迁移文件名与实库最终状态并不完全等价，当前要点如下：

1. 实库 `migrations` 记录已经推进到 `2026-04-22`，不是只停留在 `2026-04-17`。
2. 已应用的近期迁移包括：
   - `2026_04_21_000001_sync_user_accounts_cash_balance_from_users_balance`
   - `2026_04_22_000001_add_order_fields_to_invoices_table`
   - `2026_04_22_000001_expand_notification_log_content_columns`
   - `2026_04_22_000002_migrate_services_to_invoice_drop_orders`
   - `2026_04_22_020000_drop_orders_and_order_id_columns`
3. 迁移文件名可能带有更激进的意图，但实库当前仍保留 `orders`、`referral_account_logs` 等表，因此任何结构判断都必须回到 `information_schema`。

### 4.4 当前处理原则

- 不要看到旧迁移文件就直接补跑
- 不要只看迁移文件名就推断表已经删除
- 先查 `information_schema.tables`
- 再查 `migrations`
- 最后对照当前代码里的 Model、Service、Controller 和路由

## 五、本地启动

按 `启动指南.md` 执行，不要使用历史蓝图里的 `php artisan serve`：

```bash
# 后端：统一入口，托管 HTTP、VNC Relay、Queue Worker
cd backend
php artisan app:serve

# 本地需要一起跑计划任务时：
php artisan app:serve --with-schedule

# 用户端
cd frontend-client
npm run dev

# 管理端
cd frontend-admin
npm run dev
```

说明：

- `app:serve` 的实现位于 `backend/app/Console/Commands/ServeBackendStackCommand.php`
- 该命令对外提供统一入口，内部再代理 Laravel HTTP 与 VNC Relay

## 六、生产部署

- 运行环境：宝塔面板，PHP-FPM 指向 `backend/public`
- 计划任务：宝塔每分钟执行一次 `php artisan schedule:run`
- 队列：未单独常驻 `queue:work`，消费并入 `schedule:run`
- 异步任务：存在约 0 到 60 秒延迟
- 前端：分别构建 `frontend-admin` 与 `frontend-client` 后发布

## 七、外部对接

- 供应商侧当前明确存在：
  - 极点云
  - 美得云
- 当前运行时供应商驱动 key：
  - `hosting_panel_api`
  - `mofang_finance_api`
- `mofang_finance_api` 已作为独立魔方财务适配驱动注册，不再归一化或别名成 `hosting_panel_api`
- 核心业务通过 `MofangFinanceAdapter` 能力对象访问魔方能力；当前底层协议仍委托主机面板传输层，魔方云配置项模板收敛到 `App\Integrations\Mofang\Support`
- 魔方兼容逻辑按中间层隔离：
  - Provider 解析与注册：`Services/Upstream`
  - 魔方驱动：`Services/Upstream/Drivers/Mofang`

- 服务开通、控制台、同步等业务只消费 provider 能力或 adapter，不直接判断魔方协议字段；后续新增魔方差异时优先补 adapter/support 测试

## 八、与历史蓝图的关键差异

| 维度 | 历史蓝图 | 当前真实 |
| --- | --- | --- |
| 前端目录 | 单一 `frontend/` | `frontend-admin` + `frontend-client` + `shared` |
| 鉴权 | 管理端 Session、客户端 Sanctum | 两端都走 Sanctum Token |

| 前端请求封装 | 蓝图示例 `useCrud` | 各端 `src/utils/request.js` + `src/utils/auth.js` |
