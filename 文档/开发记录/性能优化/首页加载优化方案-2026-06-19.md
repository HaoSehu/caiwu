# 首页加载性能优化方案

**日期**: 2026-06-19  
**问题**: 首页加载耗时过长，API 响应慢（1.8-2秒），视频资源重复加载  
**影响**: 用户首次访问体验差，白屏时间长

---

## 一、问题诊断结果

### 1.1 性能测试数据

**API 请求耗时（并发）**:
- `/api/site/home`: 1856ms
- `/api/site/home-hero`: 1912ms  
- `/api/site/product-types`: 1993ms

**资源加载**:
- hero-1.mp4 (5.95MB): 首次 542ms，第二次 1993ms（重复加载）
- Element Plus 样式编译: 696ms（开发环境）
- 总请求数: 745 个（开发模式）

**页面加载时间**:
- DOMContentLoaded: 1151ms
- Load Complete: 1200ms
- 刷新超时: 10秒未达到 networkidle

### 1.2 根本原因

#### 后端问题（优先级：🔴 最高）

1. **缓存策略不合理**
   - `SiteHomeService::overview()` 缓存 TTL 仅 120 秒
   - `ProductSiteService` 缓存 TTL 300 秒
   - 缓存失效后需要重新执行复杂查询

2. **数据库查询未优化**
   - 多表 JOIN 查询（first_groups、second_groups、third_groups、products）
   - 统计计算（COUNT、GROUP BY）在每次请求时执行
   - `groupCatalogMap()` 可能触发 N+1 查询
   - 缺少必要的数据库索引

3. **API 设计问题**
   - `/api/site/home` 和 `/api/site/home-hero` 数据重复
   - 三个 API 并发请求，但每个都需要 1.8-2 秒
   - 未使用 HTTP/2 Server Push 或预加载

#### 前端问题（优先级：🟡 中等）

1. **视频资源管理**
   - hero-1.mp4 被加载两次（组件重新渲染）
   - 5 个视频总大小 13.56 MB
   - 未实现视频预加载策略

2. **图片加载**
   - 跨域图片加载失败（ERR_BLOCKED_BY_ORB）
   - `http://admin.sw7111.top/uploads/content/...` 跨域资源

3. **开发环境开销**
   - Element Plus 样式实时编译 696ms
   - 745 个模块请求（HMR）

## 二、优化方案

### 2.1 后端优化（预计提升 60-80%）

#### 方案 A：缓存优化（立即见效）

**目标**: 减少 80% 的数据库查询

**措施**:
1. 增加缓存 TTL
   - `SiteHomeService::overview()`: 120s → 600s（10分钟）
   - `ProductSiteService`: 300s → 900s（15分钟）
   - `HomeHeroService`: 保持 300s

2. 使用 Redis 缓存标签
   - 添加缓存标签便于批量清理
   - 产品更新时只清理相关缓存

3. 实现缓存预热
   - 在 `schedule:run` 中添加预热任务
   - 每 5 分钟刷新首页缓存

**预期效果**: API 响应时间从 1.8s → 50-100ms（缓存命中）

#### 方案 B：数据库查询优化（中期）

**目标**: 减少查询复杂度和次数

**措施**:
1. 添加数据库索引
   ```sql
   -- 产品分组索引
   CREATE INDEX idx_second_group_visible ON second_product_groups(is_visible, sort_order);
   CREATE INDEX idx_third_group_visible ON third_product_groups(is_visible, second_product_group_id);
   
   -- 产品查询索引
   CREATE INDEX idx_product_onsale ON products(status, first_product_group_id, second_product_group_id);
   CREATE INDEX idx_product_group ON products(second_product_group_id, third_product_group_id, status);
   
   -- 内容索引
   CREATE INDEX idx_article_published ON content_articles(status, publish_at, is_pinned);
   ```

2. 优化 `groupCatalogMap()` 查询
   - 使用批量查询替代循环查询
   - 添加查询结果缓存

3. 使用 Eager Loading 避免 N+1
   - 预加载关联关系
   - 使用 `with()` 替代循环查询

**预期效果**: 缓存未命中时从 1.8s → 300-500ms

#### 方案 C：API 合并优化（中期）

**目标**: 减少请求数量和数据冗余

**措施**:
1. 合并 `/api/site/home` 和 `/api/site/home-hero`
   - hero 数据已包含在 home 响应中
   - 减少一次 HTTP 请求

2. 实现增量更新
   - 返回数据版本号
   - 前端缓存数据，仅请求变更部分

3. 使用 GraphQL 或自定义字段选择
   - 允许前端指定需要的字段
   - 减少传输数据量

**预期效果**: 请求数从 3 → 2，减少网络往返

### 2.2 前端优化（预计提升 20-30%）

#### 方案 D：视频资源优化（立即见效）

**目标**: 防止视频重复加载，优化加载策略

**措施**:
1. 修复视频重复加载问题
   - 使用 `key` 属性稳定视频组件
   - 添加 `v-show` 替代 `v-if` 控制显示
   - 实现视频实例复用

2. 实现视频预加载策略
   - 首屏只加载第一个视频
   - 其他视频延迟加载（Intersection Observer）
   - 使用 `preload="none"` + 手动预加载

3. 视频格式优化
   - 转换为 WebM 格式（减少 30-50% 体积）
   - 提供多种分辨率（响应式加载）
   - 使用视频压缩工具优化现有文件

**预期效果**: 视频加载时间减少 50%，带宽节省 30%

#### 方案 E：图片优化（中期）

**目标**: 解决跨域问题，优化图片加载

**措施**:
1. 修复跨域图片问题
   - 使用相对路径或同域代理
   - 配置 CORS 头允许跨域
   - 迁移图片到本地存储

2. 实现图片懒加载
   - 使用 `loading="lazy"` 属性
   - 添加占位图和渐进式加载
   - 使用 Intersection Observer

3. 图片格式优化
   - 使用 WebP 格式
   - 提供响应式图片（srcset）
   - 压缩图片质量

**预期效果**: 图片加载失败率降至 0，加载速度提升 40%

#### 方案 F：代码分割优化（中期）

**目标**: 减少首屏 JS 体积

**措施**:
1. 路由级代码分割
   - 首页组件单独打包
   - 解决方案、新闻区块延迟加载
   - 使用动态 import()

2. 第三方库优化
   - Element Plus 按需引入
   - 抽取公共依赖到 vendor chunk
   - 使用 Tree Shaking

3. 预加载关键资源
   - 使用 `<link rel="preload">`
   - 预加载首屏字体、CSS
   - 预连接 API 域名

**预期效果**: 首屏 JS 体积减少 30-40%

### 2.3 基础设施优化（长期）

#### 方案 G：CDN 和缓存策略

**目标**: 利用 CDN 加速静态资源

**措施**:
1. 静态资源 CDN 化
   - 图片、视频上传到 CDN
   - 配置长期缓存（1年）
   - 使用版本号或哈希控制缓存

2. API 响应缓存
   - 配置 Nginx 缓存
   - 使用 Redis 缓存热点数据
   - 实现缓存分层策略

3. HTTP/2 优化
   - 启用 HTTP/2 多路复用
   - 配置 Server Push
   - 减少连接建立开销

**预期效果**: 静态资源加载速度提升 50-70%

## 四、风险评估

### 4.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 缓存 TTL 过长导致数据不及时 | 中 | 实现缓存标签，数据更新时主动清理 |
| 数据库索引影响写入性能 | 低 | 在低峰期添加索引，监控写入性能 |
| 视频格式兼容性 | 低 | 提供 MP4 降级方案 |
| 代码分割导致加载顺序问题 | 中 | 充分测试，使用预加载 |

### 4.2 业务风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 缓存数据与实际不一致 | 高 | 实现缓存版本控制，关键操作清理缓存 |
| 优化过程中服务不可用 | 高 | 分阶段发布，保留回滚方案 |
| 性能优化影响功能 | 中 | 充分测试，灰度发布 |

## 五、监控指标

### 5.1 关键指标（KPI）

**后端指标**:
- API 平均响应时间 < 100ms
- 缓存命中率 > 90%
- 数据库查询时间 < 50ms

**前端指标**:
- 首屏加载时间（FCP）< 1s
- 可交互时间（TTI）< 1.5s
- Lighthouse 性能分数 > 85

**资源指标**:
- 首屏资源总大小 < 2MB
- 视频加载时间 < 500ms
- 图片加载成功率 > 99%

1. **后端监控**

2. **前端监控**

   - API 响应时间 > 500ms 告警
