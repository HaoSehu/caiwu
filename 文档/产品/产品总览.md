# 产品总览

- 文档性质：现行方向
- 对齐时间：`2026-04-23`
- 读者画像：产品经理、项目负责人、研发、测试、客服、运营

## 1. 产品定位

这是一个面向 IDC / 云服务场景的综合业务平台，覆盖：

- 官网商品展示
- 用户注册与登录
- 实名认证
- 商品选购与报价
- 账单创建与支付
- 服务实例开通、续费、运维操作
- 优惠券与推荐返佣
- 工单与内容中心
- 管理后台运营与配置

一句话概括：

用户在官网选购云服务，系统生成账单并完成支付，随后交付为服务实例，后续通过用户中心持续管理和续费。

## 4. 核心业务链路

### 4.1 选购到开通

1. 用户浏览官网商品
2. 用户查看商品详情并获取报价
3. 用户创建账单
4. 用户选择余额支付或支付宝支付
5. 支付成功后进入开通/交付流程
6. 生成服务实例
7. 用户进入服务控制台做后续操作

### 4.2 续费

1. 用户在服务实例页查看续费预览
2. 用户发起续费
3. 系统生成续费账单
4. 支付成功后延长服务周期

### 4.3 流量包加购

1. 用户在服务实例页查看可用流量包
2. 获取报价
3. 创建加购单
4. 成功后变更服务资源额度

### 4.4 充值

1. 用户创建充值单
2. 支付成功
3. 余额到账
4. 后续用于账单支付

### 4.5 客服与售后

1. 用户发起工单
2. 管理端分配 / 回复 / 关闭
3. 用户继续追问或确认结束

## 5. 当前产品术语口径

这是当前文档里最容易混乱的部分，必须统一：

### 5.1 商品（Product）

- 指可售卖的业务项
- 由官网展示和后台商品管理共同维护

### 5.2 账单（Invoice）

- 当前用户侧与管理侧的主收费对象
- 新购、续费、支付动作都优先围绕账单展开
- 用户侧当前主要看 `/api/client/invoices*`

### 5.3 订单（Order）

- 当前仍存在于后端与数据库中
- 更偏历史或内部承载对象
- 不能再默认把它当成当前用户最主要的产品语言
- 对产品、客服、运营口径，优先说“账单”，不是“订单”

### 5.4 服务实例（Service）

- 用户支付成功后真正交付的业务实例
- 后续续费、监控、VNC、NAT、安全组等都围绕实例展开

## 6. 当前产品边界与约束

### 6.1 实名是部分链路的前置条件

- 某些能力需要完成实名认证才能继续
- 文案、流程和客服说明都要明确这一点

### 6.2 异步任务不是实时完成

- 当前生产通过 `schedule:run` 触发异步消费
- 最坏延迟大约 60 秒
- 所以支付成功后，不应向用户承诺“绝对秒级完成”

### 6.3 上游供应商不是单一节点

- 当前已启用至少两家供应商
- 平台本身是统一售卖和统一管理入口
- 上游差异由后台和服务层屏蔽

### 6.4 官网与用户中心不是两个独立产品

- `frontend-client` 同时承载官网和用户中心
- 产品体验上要连续，不要把两者当作完全独立系统设计

## 10. 当前商品目录层级真相

- 官网和用户侧商品目录的真实层级不是“商品类型 = 一级菜单”。
- 当前稳定口径应按下面这条链路理解：
  `产品类型(product_type)` -> `一级菜单(rootGroups)` -> `二级菜单(childGroups)` -> `具体商品(products)`
- 其中：
  - `product_type` 是商品大类，也是前台最外层切换项，常见值如“云服务器”“裸金属”“NAT/云电脑”。
  - `rootGroups` 是一级菜单，对应 `product_groups` 表里 `parent_group_id` 为空的节点，例如“美国”“香港”“轻量云”“裸金属”。
  - `childGroups` 是二级菜单，对应 `product_groups` 表里 `parent_group_id` 指向某个一级菜单的节点，例如“三网精品”“高性能”“家宽”“高防”。
  - `products` 是最终可售商品，挂在当前一级菜单或二级菜单节点下，对应 `products.product_group_id`。
- 后端真实数据结构：
  - 菜单树模型是 `App\Models\ProductCategory`，底表为 `product_groups`。
  - `parent_group_id` 为空表示一级菜单；有值表示该节点隶属于某个一级菜单。
  - `product_type` 决定该菜单节点属于哪个商品大类。
- 前台真实取数链路：
  - `GET /api/site/product-types` 读取 `product_type` 列表。
  - `GET /api/site/product-groups?product_type=...` 读取某个商品类型下的一级菜单 `rootGroups`。
  - `GET /api/site/product-groups/{groupId}/catalog` 读取当前一级菜单下的二级菜单 `childGroups`，以及对应商品列表。
- 代码排查入口：
  - 菜单树模型：`backend/app/Models/ProductCategory.php`
  - 前台目录服务：`backend/app/Services/ProductCatalog/ProductSiteService.php`
  - 用户侧目录状态：`frontend-client/src/views/website/products/useWebsiteProductsCatalog.js`
- 排查商品“挂在哪一层”时，不要只看 `product_type` 文案；必须同时看：
  - 当前商品的 `products.product_group_id`
  - 该菜单节点在 `product_groups` 中是否有 `parent_group_id`
  - 前台当前请求走的是 `productTypes`、`rootGroups` 还是 `childGroups`
