## 3. 各规范项详细审查

### 3.1 UI 框架纯净度 ✅

- 全仓 `grep` 检索 `element-plus` / `@element-plus/icons-vue` / `el-button` / `el-table` / `el-input` 均无匹配。
- 全仓未出现 `defineComponent` + `export default {}` 写法的业务页面（仅 `layouts/frame`、`FrameBlank` 这类 Starter 基底组件保留），所有业务页面统一 `<script setup lang="ts">`。

### 3.2 头部说明卡片 / Hero 禁令 ✅

- 全仓 `grep` 检索 `page-head` / `page-hero` / `hero-section` / `PageHead` / `HeroSection` / `hero-banner` 均无匹配。
- `class="slides-section-head"` 仅出现在 [settings/index.vue](frontend-admin-v3/src/pages/settings/index.vue#L116) 官网轮播配置卡片**内部**的分区标题，用于"轮播项 / 底部特色卡片"两段配置的标题与操作按钮，属于表单分区标题，不是被禁的"页头说明卡片"。
- [dashboard/base/index.vue](frontend-admin-v3/src/pages/dashboard/base/index.vue) 使用 `TopPanel` 渲染 4 张指标卡，属于仪表盘指标区，规范允许"列表页从筛选、指标、工具栏、表格卡片开始"。
- [users/detail/index.vue](frontend-admin-v3/src/pages/users/detail/index.vue#L24) 顶部是 `detail-action-bar`（返回 + 操作按钮的紧凑工具栏）+ `user-detail-stats` 指标卡，属于详情页允许的工具栏与指标区。

### 3.3 API / 请求 / Auth 复用 ✅

- 22 个 API 模块位于 [src/api/](frontend-admin-v3/src/api/)，按域拆分（`admin/*`、`user.ts`、`product.ts`、`service.ts`、`supplier.ts`、`auth.ts`）。
- 22 处页面 import 均从 `@/api/*` 消费，未发现页面内 `import axios` / `axios.create` / `Http::*`。
- 未发现页面内直接读写 `localStorage` / `sessionStorage`，token 走现有 `src/utils/auth.js` 等价模块。
- 未发现硬编码 `http://` / `https://` / `127.0.0.1` / `localhost`。

### 3.4 状态展示复用 ✅

7 个含业务状态的列表/详情页全部复用 `StatusTag` + `@shared/statusConfig`：

- [finance/recharges/index.vue](frontend-admin-v3/src/pages/finance/recharges/index.vue#L69) — `PAYMENT_STATUS_MAP`
- [finance/orders/index.vue](frontend-admin-v3/src/pages/finance/orders/index.vue#L83) — `ORDER_STATUS_MAP`
- [finance/orders/detail/index.vue](frontend-admin-v3/src/pages/finance/orders/detail/index.vue#L255) — 同时复用 `getStatusLabel` / `getStatusTagType`
- [finance/invoices/index.vue](frontend-admin-v3/src/pages/finance/invoices/index.vue#L73) — `INVOICE_STATUS_MAP`
- [services/index.vue](frontend-admin-v3/src/pages/services/index.vue#L73) — `SERVICE_STATUS_MAP`
- [dashboard/base/index.vue](frontend-admin-v3/src/pages/dashboard/base/index.vue#L34) — `INVOICE_STATUS_MAP`
- [users/detail/index.vue](frontend-admin-v3/src/pages/users/detail/index.vue#L658) — 多个状态 map

其余 `t-tag` 使用均为标签型字段（角色名、HTTP 方法、会员等级百分比），不属于业务状态枚举，无须强制走 `StatusTag`。

### 3.5 视觉 token / 间距体系 ✅

- 样式入口统一走 `src/style/` Less 与 Starter `tvision-color` 体系。
- 检索 `paddingLR-s` / `paddingTB-m` / `padding: 8px` 的 18 处命中均为**表格单元格、tag 内边距、抽屉面板内边距**等组件内部尺寸，不构成页面级间距违规。
- 管理端不受 `frontend-user-v4-console` 的"页面根 12px"强约束；现有列表页根容器均使用 `t-card :bordered="false"` 包裹筛选 + 表格的标准结构，与 `页面风格.md` 一致。

### 3.6 页面逻辑下沉 ⚠️ 部分可改进

**已良好下沉：**

- `products/` 拆出 `components/`（`ProductCatalog`、`Suppliers`、`TrafficPackages`）与 `composables/useProductShared`，页面入口 [products/index.vue](frontend-admin-v3/src/pages/products/index.vue) 仅做 tab 路由切换（30 行）。
- `users/` 拆出 `components/VerificationPanel.vue`，[users/index.vue](frontend-admin-v3/src/pages/users/index.vue) 体量合理。
- 全仓 19 处复用 `@/hooks/useMediaQuery` 做响应式判断，4 处复用 `@/hooks/useProductBindingTree`。

**可改进项：**

1. **`useListPage` hook 未被采用**：[src/hooks/useListPage.ts](frontend-admin-v3/src/hooks/useListPage.ts) 已存在，但 22 个列表页均自行维护 `loading` / `pagination` / `filters` / `handleSearch` / `resetFilters` 的模板代码。建议在新页面或下次重构时采用 `useListPage` 收敛列表状态，减少重复模板。
2. **users/detail/index.vue 1834 行**：单文件聚合了基本信息、推荐、服务、账单、余额记录、工单、通知 7 个 tab 的查询与展示。建议按 tab 拆出 `components/UserBasicTab.vue`、`UserServicesTab.vue`、`UserInvoicesTab.vue` 等，或下沉到 `composables/useUserDetailTabs.ts`。
3. **logs/index.vue 1017 行**：聚合了列表筛选、详情抽屉、告警卡片三块。建议抽 `components/LogDetailDrawer.vue` 与 `composables/useLogFilters.ts`。
4. **notifications/index.vue 676 行**：通知列表 + 模板列表 + 模板编辑三态合一，建议抽 `components/TemplateList.vue` 与 `composables/useNotificationTemplates.ts`。
5. **settings/index.vue 850 行**：站点设置、邮件、官网轮播多表单混在同一文件。建议按设置分组抽 `components/SiteSettingsForm.vue`、`EmailSettingsForm.vue`、`HeroSlidesForm.vue`。

> 以上均为可读性 / 可维护性建议，未违反硬性禁止项，不阻塞发布。
