## 1. 先读什么

按当前仓库规则，建议阅读顺序如下：

2. `启动指南.md`
3. `开发规范.md`

5. `文档/开发文档/架构/架构现状说明.md`

## 3. 文档分区

`文档/` 只保留长期辅助开发者开发、联调、部署和维护的文档：

- `文档/开发文档/架构/`：架构现状、插件架构说明和测试指南。
- `文档/开发文档/前端/`：前端项目规范。
- `文档/开发文档/后端/`：API 格式、后端目录、接口清单和后端工程治理。
- `文档/开发文档/数据库/`：当前结构、数据库说明和本地迁移流程。
- `文档/开发文档/集成/`：本地对接、魔方财务 API 参考和插件开发指南。
- `文档/开发文档/部署与调度指南.md`：部署、调度和队列运行口径。

阶段性执行记录、审查快照、一次性报告、临时计划不再作为长期文档保留；仍有效的规则应沉淀到 `文档/开发文档/` 对应真源。

## 5. 维护原则

- 文档与当前代码现实冲突时，先以当前代码、路由和目录结构为准。
- 不要把旧前端目录名重新写回现行文档。
- 自动生成类文档按仓库规则通过脚本更新，不手工伪维护。
- 新增长期规则先检查是否已有真源，优先更新现有文档，不新增同主题副本。
- 一次性材料不要提交到 `文档/`；确需保留时先提炼为长期规则或操作指南。
