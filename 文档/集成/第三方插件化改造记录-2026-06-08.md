# 第三方插件化改造记录

- 日期：`2026-06-08`
- 阶段：第一阶段，支付网关插件化骨架落地；第二阶段，实名/短信驱动注册工程化；第三阶段，实名/短信 DTO 与错误映射；第四阶段，上游能力声明；第五阶段，支付 gateway 编码隔离；第六阶段，上游 provider 元数据 DTO
- 范围：支付网关抽象、支付宝当面付 driver、实名/短信 driver tag 注册、实名/短信 DTO、上游 provider 能力声明、上游 provider 元数据 DTO、支付业务 gateway 与插件 key 常量隔离、插件注册、最小业务接入

## 已完成

1. 新增支付能力接口：`App\Contracts\Integrations\Payments\PaymentGatewayInterface`。
2. 新增支付请求/响应 DTO：
   - `PaymentPrecreateRequest`
   - `PaymentPrecreateResult`
   - `PaymentQueryResult`
   - `PaymentRefundRequest`
   - `PaymentRefundResult`
3. 新增支付网关注册与解析：
   - `PaymentGatewayRegistry`
   - `PaymentGatewayManager`
4. 新增支付宝当面付 driver：`AlipayFaceToFaceGateway`。
5. 新增 `IntegrationServiceProvider`，通过 `payment.gateways` tag 注册支付 driver。
6. 新增 `config/integrations.php`，集中声明第三方能力默认 provider 和保留 provider key。
7. `PaymentService`、`InvoiceController`、支付宝回调验签中间件已改为通过 `PaymentGatewayManager` 获取支付宝 driver。
8. `VerificationDriverManager` 改为接收容器 tag 注册的实名 driver，当前 `Stay33Driver` 通过 `identity.verification_drivers` 注册。
9. `SmsDriverManager` 改为接收容器 tag 注册的短信 driver，当前 `AliyunSmsDriver` 通过 `sms.drivers` 注册。
10. `AppServiceProvider` 不再直接绑定实名/短信 Manager，第三方能力统一由 `IntegrationServiceProvider` 注册。
11. 实名认证新增初始化、扫码链接、查询结果 DTO，业务层不再直接消费 Stay33 原始数组。
12. 短信新增发送请求/结果 DTO，阿里云英文或技术类错误统一映射为简体中文业务提示。
13. 上游 `UpstreamDriver` 新增 `capabilities()` 能力声明，`ResolvedProvider` 可输出当前 provider 能力列表。
14. `HostingPanelApiDriver` 与 `MofangFinanceDriver` 均声明各自能力，`mofang_finance_api` 仍解析到魔方 adapter，不折叠到共享 transport。
15. 新增 `PaymentGatewayCode`，集中区分 `payments.gateway = alipay` 业务值与 `alipay_f2f` 支付插件 key。
16. 核心支付服务、客户端充值/支付查询、财务查询和支付宝底层日志写入已改用支付网关常量。
17. 新增 `UpstreamProviderDescriptor`，统一输出上游 provider 的 key、中文 label 和能力声明。
18. `ProviderRegistry::descriptors()` 与 `ResolvedProvider::descriptor()` 已提供结构化元数据；旧 `options()` 保留 `value/label` 兼容选择器。

## 保持不变

- `payments.gateway` 仍保留业务历史值 `alipay`，避免破坏既有财务数据和查询。
- `alipay_f2f` 仅作为插件 key 使用，业务表、筛选、退款判断继续使用 `PaymentGatewayCode::ALIPAY`。
- 支付宝底层 SDK/HTTP 细节暂时保留在 `AlipayFaceToFaceService`，由 driver 包装。
- Stay33 实名认证和阿里云短信的底层 HTTP 细节暂时保留在各自 driver 内，driver 输出已先通过 DTO 与业务层隔离。
- 支付业务流程、账单状态、余额扣减、回调幂等、退款事务逻辑不在本阶段重写。
- `mofang_finance_api` 继续作为独立 provider key，不能归一化为 `hosting_panel_api`。
- `ProviderRegistry::options()` 仍只作为旧选择器兼容输出；新审查工具或接口扩展应优先消费 `UpstreamProviderDescriptor`。
