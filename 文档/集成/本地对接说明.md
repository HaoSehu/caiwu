## 一、上游供应商

当前实库 `suppliers` 表中已启用的上游：

| 供应商 | `code` | `interface_type` | 对接协议 |
| --- | --- | --- | --- |
| 极点云 | `supplier_1` | `hosting_panel_api` | 主机面板 OpenAPI |
| 美得云 | `supplier_2` | `hosting_panel_api` | 主机面板 OpenAPI |

说明：

- 两家上游底层是同一套主机面板 API 协议，本地走 provider 驱动体系适配；`hosting_panel_api` 使用 `HostingPanelApiDriver`，`mofang_finance_api` 使用独立 `MofangFinanceDriver` + `MofangFinanceAdapter`，并暂时委托同一传输层
- `mofang_finance_api` 是独立 provider key，禁止在解析、开通、同步或服务绑定时归一化为 `hosting_panel_api`
- 新增同类上游只需在后台添加 `suppliers` 记录并维护 API 地址、账号、密钥

## 1.1 中间层边界

| 层 | 职责 | 魔方落点 |
| --- | --- | --- |
| Provider 解析 | 按服务绑定、商品绑定、供应商配置解析真实 provider key | `ProviderResolver`、`ProviderRegistry` |
| Driver | 暴露供应商 key、能力清单和能力对象 | `Drivers/Mofang/MofangFinanceDriver.php` |
| Adapter | 屏蔽魔方财务/魔方云协议差异，供业务 Service 调用 | `Integrations/Mofang/Adapters/MofangFinanceAdapter.php` |
| Support | 魔方模板、兼容校验、字段映射等可替换细节 | `Integrations/Mofang/Support/` |
| Shared Transport | 仅承载仍通用的主机面板 HTTP/JWT 协议 | `HostingPanelApiTransport.php` |

扩展规则：

- 业务 Service 不直接拼魔方请求，也不直接读取官方字段差异，新增差异先落到 adapter/support。
- 能复用主机面板协议时可以委托 shared transport，但 provider key 和能力对象必须保持魔方独立身份。
- 魔方云商品配置项模板优先在 `MofangCloudConfigTemplate` 扩展，通用 fallback 才放到 `Services/Upstream/Support/CloudConfigTemplate`。
- 旧魔方密码兼容走 `LegacyPasswordVerifier` 聚合器，具体格式判断放在 `MofangLegacyPasswordVerifier`。
- 新增 provider 或能力时同时补最小测试：provider 解析、adapter 能力、关键字段映射、失败降级。

## 三、对接的主机面板 OpenAPI 清单

只列项目真实调用的，不代表官方全量：

| 能力 | 方法 | 路径 | 本地调用入口 |
| --- | --- | --- | --- |
| 登录并换 JWT | `POST` | `/v1/login_api` | `HostingPanelApiTransport::login()` |
| 获取用户资料 | `GET` | `/v1/user` | `HostingPanelApiTransport::getUserProfile()` |
| 获取账户余额 | `GET` | `/v1/user`（复用） | `HostingPanelApiTransport::getBalance()` |
| 获取主机续费信息 | `GET` | `/v1/hosts/{hostId}/renew` | `HostingPanelApiTransport::getHostRenewInfo()` |
| 发起主机续费 | `POST` | `/v1/hosts/{hostId}/renew` | `HostingPanelApiTransport::renewHost()` |
| 设置自动续费 | `POST` | `/v1/hosts/{hostId}`（autoRenew 字段） | `HostingPanelApiTransport::setHostAutoRenew()` |

其余通用方法（商品同步、订单状态同步、开通操作、状态查询等）由 `get / post / put / parallelGet` 通用方法按场景调用。所有调用都会自动带 JWT，有缓存复用，过期自动重登录。

## 四、签名与认证约束

- 上游 JWT 按 `supplier_id` 独立缓存，默认 TTL 见 `config/idc.php.hosting_panel_api`
- 所有调用前会自动 `login`，失败或 401 会触发 `refreshJwt`
- 上游请求失败的异常统一由 `HostingPanelApiTransport::request` 处理并记录到 `storage/logs/laravel.log`
- 上游回调（供应商主动推我们）当前**未**暴露标准 webhook；业务主要靠轮询

## 五、支付对接：支付宝 F2F

### 5.1 能力

| 能力 | 阿里方法名 | 本地入口 |
| --- | --- | --- |
| 预下单生成付款二维码 | `alipay.trade.precreate` | `AlipayFaceToFaceService::precreate()` |
| 主动查询订单状态 | `alipay.trade.query` | `AlipayFaceToFaceService::query()` |
| 交易退款 | `alipay.trade.refund` | `AlipayFaceToFaceService::refund()` |
| 验证异步通知签名 | - | `AlipayFaceToFaceService::verifyNotify()` |

### 5.2 配置入口

通过管理端"通知配置/支付配置"设置以下 `settings` 项：

- `alipay_app_id`
- `alipay_private_key`
- 其余支付宝相关 `alipay_*` 项

### 5.3 回调路径

- 支付宝异步通知：`POST /api/client/payment/alipay/notify`
- 本地回调 URL 约定：`{APP_URL}/api/client/payment/alipay/notify`
- 回调里 `AlipayFaceToFaceService::verifyNotify` 做签名校验，`PaymentService` 做幂等 + 状态落库 + 后续开通/续费派发

## 六、实名认证对接：支付宝实名

### 6.1 客户端接口（面向用户端 SPA）

- `GET /api/client/verification/fee-config` - 获取实名费用配置
- `POST /api/client/verification/init` - 初始化实名（拿 `certify_id`）
- `POST /api/client/verification/qrcode` - 获取扫码二维码
- `GET /api/client/verification/status` - 查询当前状态
- `GET /api/client/verification/scan` - 扫码跳转中转

### 6.2 实名异步回调

- 路径：`GET|POST /api/client/verification/callback`
- 中间件：`verify.callback`（对应 `VerifyCallbackSignature`）
- 控制器：`Client\VerificationController::callback`
- 成功后会更新 `users.verification_*`、`user_accounts` 对应字段，并落 `verification_histories`

### 6.3 管理端可见性

- `GET /api/admin/verifications` - 实名列表
- `GET /api/admin/verifications/{user}/history` - 历史
- `POST /api/admin/verifications/{user}/unbind` - 后台解绑（按权限）

## 八、新增对接时的基线清单

新增上游或支付渠道时，至少满足：

- 在 `suppliers` 表建立记录（或接入相应配置表）
- 新增或复用 `Service` 客户端（不要直接在 Controller 里 `Http::post`）
- 入参、出参、异常落日志（`trace_id` + `supplier_id` + 调用上下文）
- JWT / Token 做缓存 + 过期回退机制
- 调用失败有可观测性（管理端日志页能查）
- 回调必须过 `verify.callback` 或等价签名中间件
- 回调处理必须幂等
- 回调路径、公钥/密钥、商户号等敏感配置走 `settings` 或 `.env`，**不要硬编码**

## 九、尚未接入的官方能力
