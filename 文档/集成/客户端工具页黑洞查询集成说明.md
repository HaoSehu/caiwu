# 客户端工具页黑洞查询集成说明

- 文档性质：现行方向 / 仓库内已落地集成说明
- 对齐时间：`2026-04-24`
- 读者画像：后端对接开发、前端集成开发、联调排障人员
- 适用范围：`/client/tools` 工具页与 `/api/client/blackhole/query`

## 1. 集成目标

本次集成不是新增独立页面，而是把上游黑洞查询能力直接折叠进现有客户端工具页 `127.0.0.1:5173/client/tools`。

当前工具页已统一接入以下能力：

1. 十堰直连接口：`http://160.202.238.2:90`
   - 十堰黑洞记录
   - 十堰 7 层策略
   - 十堰 4 层策略
   - 十堰攻击流量图表
2. 宁波直连接口：`http://160.202.238.2:81`
   - 宁波黑洞查询
   - 宁波域名过白
3. `blackhole.jdidc.cn`
   - 香港 `1,2,3,5` / 美国 `2,3` 共享黑洞查询入口
4. `do.yazzi.net`
   - 美国 `1` 流量图片地址

## 2. 代码落点

### 2.1 前端

- 页面：`frontend-client/src/views/client/Tools.vue`
- API 封装：`frontend-client/src/api/client.js`

前端仍然只调用一个接口：

```http
POST /api/client/blackhole/query
Content-Type: application/json

{
  "ip": "160.202.238.52"
}
```

### 2.2 后端

- 路由：`backend/routes/client.php`
- 控制器：`backend/app/Http/Controllers/Client/BlackholeController.php`
- 聚合服务：`backend/app/Services/BlackholeService.php`

后端负责：

1. 直连十堰 `:90` 与宁波 `:81` 已识别接口
2. 拉取并解析 `blackhole.jdidc.cn/US23.php` HTML
3. 生成美国 `1` 流量图 URL
4. 统一归一查询结果
5. 预留宁波过白、十堰 7 层策略切换、十堰 4 层策略增删写接口

## 3. 环境变量

新增配置落在：

- `backend/config/idc.php`
- `backend/.env.example`

### 3.1 可配置项

| 变量 | 说明 |
| --- | --- |
| `BLACKHOLE_TIMEOUT` | 上游请求超时秒数 |
| `BLACKHOLE_CACHE_TTL_SECONDS` | 聚合结果缓存秒数 |
| `BLACKHOLE_USER_AGENT` | 上游请求 User-Agent |
| `BLACKHOLE_NINGBO_BASE_URL` | 宁波上游基础地址，默认 `http://160.202.238.2:81` |
| `BLACKHOLE_SHIYAN_BASE_URL` | 十堰上游基础地址，默认 `http://160.202.238.2:90` |
| `BLACKHOLE_PUBLIC_BASE_URL` | `blackhole.jdidc.cn` 根地址 |
| `BLACKHOLE_US1_TRAFFIC_BASE_URL` | 美国 `1` 流量图基础地址 |
| `BLACKHOLE_SSL_VERIFY` | 是否启用 SSL 校验 |
| `BLACKHOLE_CA_BUNDLE` | CA 证书路径 |

### 3.2 最关键配置

当前实现不再依赖浏览器登录态 Cookie，而是直接请求已确认的上游地址：

```env
BLACKHOLE_SHIYAN_BASE_URL=http://160.202.238.2:90
BLACKHOLE_NINGBO_BASE_URL=http://160.202.238.2:81
```

如果后端环境无法访问这两个地址：

- 十堰黑洞 / 7 层 / 4 层 / 流量图
- 宁波黑洞

都会在返回里标记为 `unavailable`，但：

- 香港/美国共享入口
- 美国 1 流量图

仍可继续工作。

## 4. 请求与响应契约

## 4.1 请求

```http
POST /api/client/blackhole/query
Authorization: Bearer {client_token}
Content-Type: application/json

{
  "ip": "160.202.238.52"
}
```

后端校验规则：

- `ip`: `required|ip`

因此接口同时支持 IPv4 / IPv6。

### 4.2 响应骨架

成功响应仍然遵循项目统一格式：

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "ip": "160.202.238.52",
    "ip_version": 4,
    "blackholed": true,
    "overall_status": "blackholed",
    "overall_message": "在 1 个来源发现黑洞记录",
    "query_at": "2026-04-24 18:30:00",
    "available_source_count": 7,
    "total_source_count": 7,
    "warnings": [],
    "details": [],
    "meta": {
      "ningbo_base_url": "http://160.202.238.2:81",
      "shiyan_base_url": "http://160.202.238.2:90",
      "public_base_url": "https://blackhole.jdidc.cn"
    },
    "sources": {}
  }
}
```

### 4.3 `overall_status` 语义

| 值 | 含义 |
| --- | --- |
| `blackholed` | 至少一个黑洞来源命中记录 |
| `normal` | 已完成查询，未发现黑洞记录 |
| `partial` | 部分来源成功，部分来源不可用 |
| `unavailable` | 黑洞来源整体不可用 |

## 5. `sources` 字段说明

`data.sources` 是真正的明细载体。当前固定包含以下 key：

### 5.1 `shiyan_blackhole`

十堰黑洞记录。

示例字段：

```json
{
  "key": "shiyan_blackhole",
  "label": "十堰黑洞记录",
  "kind": "blackhole",
  "available": true,
  "blackholed": true,
  "status": "blackholed",
  "summary": "1 条黑洞记录",
  "message": "查询成功",
  "count": 1,
  "records": [
    {
      "host_ip": "160.202.238.52",
      "start_time": "2024-04-24 00:00:00",
      "end_time": "2024-04-24 01:00:00",
      "product_name": "十堰高防"
    }
  ]
}
```

### 5.2 `shiyan_layer7`

十堰 7 层策略。

关键字段：

- `count`
- `enabled_count`
- `enabled_list`
- `app_enabled_count`
- `app_max`
- `apply_rule_id`
- `pass_through`

当前后端还额外提供写接口：

```http
POST /api/client/blackhole/shiyan/layer7/toggle

{
  "ip": "160.202.238.52",
  "rule_id": 61,
  "enabled": true
}
```

### 5.3 `shiyan_layer4`

十堰 4 层策略。

关键字段：

- `columns`
- `count`
- `list`

当前 `list` 是按 HTML 表格解析出来的数组，字段名可能直接保留上游中文列名。

当前后端还额外提供两个写接口：

```http
POST /api/client/blackhole/shiyan/layer4/add

{
  "ip": "160.202.238.52",
  "mode": 1
}
```

```http
POST /api/client/blackhole/shiyan/layer4/delete

{
  "ip": "160.202.238.52",
  "rule_id": "1001"
}
```

### 5.4 `shiyan_flow`

十堰攻击流量图表。

关键字段：

- `info`
- `samples`
- `metrics`

其中 `metrics` 为后端归一后的展示指标：

```json
{
  "sample_count": 1,
  "avg_before_mbps": 200,
  "avg_after_mbps": 160,
  "peak_before_mbps": 200,
  "peak_after_mbps": 160
}
```

换算规则：

- 过滤前 Mbps = `in_size * 8 / 1000000`
- 过滤后 Mbps = `(in_size - in_drop_size) * 8 / 1000000`

### 5.5 `ningbo_blackhole`

宁波黑洞查询。

关键点：

- 当前实现直接请求 `:81/api/blackhole.php`
- 以 `code` 作为业务成功判定
- 不再依赖 `cloud.jdidc.cn` 页面外层 `status`

当前返回已归一为：

- `status=normal`：查询成功且无记录
- `status=blackholed`：查询成功且有记录
- `status=warning`：例如 `非法请求`
- `status=unavailable`：登录态缺失、上游非 JSON、HTTP 失败等

### 5.6 `shared_us23`

香港 `1,2,3,5` 与美国 `2,3` 的共享 HTML 查询入口。

关键字段：

- `total`
- `matched`
- `displayed`
- `columns`
- `records`
- `query_url`
- `shared_entry_note`

注意：

- 这里不是 JSON API，而是 HTML 页面解析结果
- 当前业务上不能区分“香港 1,2,3,5”与“美国 2,3”的真实后端来源，它们共用一个入口

### 5.7 `us1_traffic`

美国 `1` 当前只提供流量图片地址。

示例：

```json
{
  "key": "us1_traffic",
  "label": "美国1流量图",
  "kind": "image",
  "available": true,
  "status": "info",
  "summary": "已生成流量图地址",
  "message": "美国1 当前仅支持图片流量查询",
  "query_url": "https://blackhole.jdidc.cn/US1.php",
  "image_url": "https://do.yazzi.net/index/history?logo=0&ip=8.8.8.8"
}
```

## 6. 前端展示策略

`Tools.vue` 当前按以下结构展示：

1. 查询输入区
2. 总体状态条
3. 来源摘要卡片
4. 折叠面板
   - 十堰操作台
   - 宁波黑洞
   - 香港 `1,2,3,5` / 美国 `2,3`
   - 美国 `1` 流量图

这意味着以后如果你继续加来源，优先沿用：

- `data.details` 做摘要
- `data.sources.xxx` 做展开面板

不要再新增平行页面。

## 7. 上游限制

### 7.1 十堰 / 宁波直连接口

- 不是公开标准 OpenAPI
- 目前依赖固定上游入口 `:90` / `:81`
- 十堰 4 层策略查询和增删是 HTML 页面解析，不是 JSON 契约
- 一旦上游页面表头改动，`columns/list` 的字段名可能跟着变

### 7.2 `blackhole.jdidc.cn`

- `US23.php` 是 HTML 查询页，不是 JSON
- `US1.php` 只是图片地址拼接页，不是结构化流量接口

## 8. 后续扩展建议

如果你后面还要继续扩展这个工具页，建议按下面顺序：

1. 保持 `/api/client/blackhole/query` 这个统一入口不变
2. 在 `BlackholeService` 里新增新的 `sources.xxx`
3. 在 `Tools.vue` 里把新来源挂到摘要卡片和折叠面板
4. 写操作继续拆成独立接口，不要混进查询接口
