# 魔方财务上游插件化规划

- 文档性质：后端架构规划
- 日期：2026-07-02
- 范围：`servers` 领域的魔方财务上游对接插件
- 状态：规划稿

## 1. 目标

规划 `servers` 领域的“魔方财务上游对接插件”，要求所有上游能力插件化，系统内核不再直接承载魔方财务协议细节。

硬性目标：

- 插件目录固定为 `backend/plugins/servers/mofang_finance/`。
- 插件 domain 为 `upstream`。
- 插件 slug 为 `mofang_finance`。
- 插件 key 必须保持 `mofang_finance_api`。
- 禁止把 `mofang_finance_api` 归一化或别名为 `hosting_panel_api`。
- 禁止 Controller 直接调用上游 `Http::*`。
- 禁止业务 Service 直接拼魔方财务请求。
- 禁止插件直接修改订单、账单、支付、余额、服务实例核心状态。
- 禁止插件自行注册任意路由、菜单、权限、迁移。

## 2. 当前现状梳理

### 2.1 已经插件化的部分

- 上游插件域已存在：`upstream` 对应 `backend/plugins/servers`。
- 插件扫描、安装、启停、配置、运行入口已经存在，核心入口为：
  - `backend/app/Services/Integrations/Plugins/PluginRuntimeRegistry.php`
  - `backend/app/Services/Integrations/Plugins/PluginScanner.php`
  - `backend/app/Services/Integrations/Plugins/PluginInstaller.php`
- `ProviderRegistry` 当前从启用插件解析上游驱动。
- 魔方财务插件已声明：
  - domain：`upstream`
  - slug：`mofang_finance`
  - key：`mofang_finance_api`
  - capabilities：商品、开通、续费、状态同步、控制台等能力
- `ProviderResolver` 当前按供应商 `interface_type`、商品 `provision_module`、服务 `provision_data.provider` 解析 provider，未把 `mofang_finance_api` 归一化为 `hosting_panel_api`。

### 2.2 仍残留在系统内核或共享传输层的部分

- `backend/plugins/servers/mofang_finance/logic/MofangFinance.php` 主要只处理：
  - `server.metadata`
  - `server.supports`
  - `server.resolve_capability`
- `backend/plugins/servers/mofang_finance/lib/MofangFinanceAdapter.php` 当前明确实现的魔方差异较少，大量方法通过 `__call()` 转发到 `HostingPanelApiTransport`。
- 实际登录、JWT 缓存、刷新、HTTP 请求、续费、开通、状态、控制台能力仍主要由 `backend/app/Services/Upstream/Drivers/HostingPanelApi/HostingPanelApiTransport.php` 承载。
- 商品目录与配置项解析仍复用主机面板通用 trait：
  - `HandlesCatalogNormalization`
  - `HandlesApiConfigOptions`
- 开通流程仍由 `ProvisionService` 直接编排购物车、结算、上游支付、host 回查。
- 续费流程仍由 `ServiceRenewService` 调用上游能力。
- 控制台能力仍分散在 `ClientServiceConsole` 内核服务中。
- 状态同步仍由 `ServiceStatusSyncService` 直接拉取上游数据并写本地快照。

### 2.3 文档与代码差异

- `文档/开发文档/集成/插件开发/demo-mofang-finance.md` 仍偏 demo 描述。
- 当前实际代码已经把魔方 `MofangFinanceDriver`、`MofangFinanceAdapter`、`MofangCloudConfigTemplate`、`MofangProductTypeMapper` 放在插件目录下。
- `文档/开发文档/集成/本地对接说明.md` 仍提到部分旧 `app/Integrations/Mofang/Drivers`、`Adapters` 落点；当前 `app/Integrations/Mofang` 主要保留凭证解析、旧密码兼容和账单恢复相关能力。

## 3. 目标插件架构

### 3.1 总体原则

不建议把所有高频业务动作都退化成字符串 `execute()` 数据面调用。建议保留当前“插件注册 + capability 对象”的结构：

- 控制面走 `PluginRuntimeRegistry::execute()`：
  - `server.metadata`
  - `server.supports`
  - `server.resolve_capability`
  - `server.health_check`
- 数据面由 `ProviderRegistry` 解析插件能力对象后调用。
- 能力对象必须完全来自插件内部。
- 魔方财务插件内部不再通过 `__call()` 透传 `HostingPanelApiTransport`。
- 如后续必须所有数据面都走 `execute()`，也只能暴露高层业务 action，禁止暴露原始 HTTP action。

### 3.2 目标目录结构

```text
backend/plugins/servers/mofang_finance/
├── MofangFinancePlugin.php
├── config.php
├── logic/
│   └── MofangFinance.php
└── lib/
    ├── MofangFinanceDriver.php
    ├── MofangFinanceAdapter.php
    ├── MofangFinanceTransport.php
    ├── MofangAuthManager.php
    ├── MofangCatalogService.php
    ├── MofangProvisionService.php
    ├── MofangRenewService.php
    ├── MofangStatusService.php
    ├── MofangConsoleService.php
    ├── MofangNetworkService.php
    ├── MofangSecurityService.php
    ├── MofangProductTypeMapper.php
    ├── MofangCloudConfigTemplate.php
    └── MofangErrorMapper.php
```

### 3.3 类职责

| 类 | 职责 |
| --- | --- |
| `MofangFinancePlugin` | 插件入口，不写业务，只继承或组合逻辑类。 |
| `MofangFinance` | 处理 `server.*` 控制面 action，返回元信息、健康检查、能力对象。 |
| `MofangFinanceDriver` | 暴露 `key()`、`label()`、`capabilities()`、`resolve()`。 |
| `MofangFinanceAdapter` | 聚合各领域 service，实现 `Provides*` capability；逐步移除 `__call()`。 |
| `MofangFinanceTransport` | 插件内 HTTP 客户端，负责 URL 校验、TLS、超时、重试、日志脱敏、响应解析。 |
| `MofangAuthManager` | 供应商维度登录、JWT 缓存、刷新、401 自动重登。 |
| `MofangCatalogService` | 商品、价格、库存、配置项、配置项价格归一化。 |
| `MofangProvisionService` | 上游开通、购物车、结算、余额支付、host 回查协议封装。 |
| `MofangRenewService` | 续费信息、发起续费、自动续费开关。 |
| `MofangStatusService` | host 状态、到期时间、运行状态、IP、流量快照归一化。 |
| `MofangConsoleService` | VNC、电源、重装、重置密码、host detail。 |
| `MofangNetworkService` | NAT、网络、流量包等网络能力。 |
| `MofangSecurityService` | 安全组、防火墙规则能力。 |
| `MofangErrorMapper` | 上游错误码、错误文案、业务失败类型归一化。 |

| VNC | `server.console.vnc.get` |
| 电源操作 | `server.console.power.action` |
| 重装系统 | `server.console.os.reinstall` |

- `server.request`
- `server.get`
- `server.post`
- `server.put`
- `server.raw_http`

## 5. 系统与插件边界

### 5.1 平台负责

- API 路由、Controller、FormRequest、Resource、统一 `ApiResponse`。
- 用户认证、管理员权限、用户服务归属校验。
- 商品绑定、本地商品生命周期、本地价格策略最终落库。
- 订单、账单、余额、支付、服务实例状态机。
- 开通幂等、续费幂等、失败重试、队列调度。
- 操作审计、操作日志、财务日志。
- 控制台操作限流、用户权限、服务状态前置判断。
- `payments` 规则：只记录真实第三方资金流入，禁止物理删除。
- 插件扫描、安装、启停、配置加密、manifest 校验。

### 5.2 插件负责

- 魔方财务 API 地址、账号、密钥使用和协议封装。
- 登录、JWT / Token 缓存、刷新、401 重登。
- 所有魔方财务上游 HTTP 请求。
- 魔方财务字段、错误码、状态码、配置项、价格、周期、规格映射。
- 商品、价格、配置项的上游读取与归一化。
- 开通、续费、状态同步、VNC、电源、重装、重置密码、网络、安全组等上游动作。
- 返回稳定、受控、脱敏后的结构给平台。

### 5.3 插件禁止

- 直接修改订单、账单、支付、余额、服务实例核心状态。
- 直接写本地业务表状态。
- 自行注册任意路由、菜单、权限、迁移。
- 暴露原始 HTTP 动作给平台调用。
- 把 `mofang_finance_api` 别名为 `hosting_panel_api`。
- 在日志中输出密钥、JWT、密码、VNC token。

## 9. 最终验收目标

### 9.1 架构验收

- [ ] 魔方财务上游能力以 `backend/plugins/servers/mofang_finance/` 为唯一协议实现入口。
- [ ] `mofang_finance_api` 全链路保持独立 provider key，不被归一化、别名或回退为 `hosting_panel_api`。
- [ ] 平台业务 Service 不再直接拼接魔方财务 API 请求路径、请求参数或响应字段。
- [ ] Controller 不直接调用上游 `Http::*`，只调用平台 Service。
- [ ] 插件不直接修改订单、账单、支付、余额、服务实例核心状态。
- [ ] 新增能力优先通过插件内部 service 扩展，不再扩大 `MofangFinanceAdapter::__call()` 动态转发面。

### 9.2 能力验收

- [ ] 插件可完成魔方财务登录、凭证缓存、凭证刷新、401 自动重登。
- [ ] 插件可获取商品列表、商品详情、价格、库存、配置项和配置项价格。
- [ ] 插件可支撑订单履约开通，并返回平台可落库的 host、连接信息、到期时间、运行状态等归一化数据。
- [ ] 插件可支撑服务续费、自动续费设置、续费后 host 回查。
- [ ] 插件可支撑状态同步，包括服务状态、运行状态、IP、流量、到期时间等字段。
- [ ] 插件可支撑用户控制台能力：VNC、开机、关机、重启、强制关机、重装系统、重置密码、NAT、安全组、监控、流量包和升降级。

### 9.3 安全验收

- [ ] API 地址、账号、密钥、JWT、VNC token、密码等敏感信息不硬编码、不明文入日志。
- [ ] 上游请求保留 URL scheme 校验、私网地址拦截、DNS 解析安全校验、TLS 校验、超时控制和重试边界。
- [ ] 插件配置中的敏感字段加密保存，管理端不回显真实值。
- [ ] 所有控制台动作先通过平台用户身份、服务归属、权限、限流和服务状态校验，再调用插件。
- [ ] 插件返回的第三方响应按不可信数据处理，只输出平台允许消费的字段。

### 9.4 业务一致性验收

- [ ] 支付、订单、账单、余额、服务实例状态机仍由平台统一维护。
- [ ] 开通、续费、状态同步具备幂等保护，重复任务或重复回调不造成重复开通、重复续费或重复扣款。
- [ ] 上游开通成功但本地落库失败时，有可重试、可排查、可审计的恢复路径。
- [ ] 上游失败时向用户返回统一、可理解的中文错误，不暴露上游敏感细节或堆栈。
- [ ] 供应商、商品、服务三个层级的 provider 解析结果与历史数据兼容。

### 9.5 可观测性验收

- [ ] 登录、商品同步、开通、续费、状态同步、控制台动作均有脱敏日志。
- [ ] 日志至少包含 `supplier_id`、`provider_key`、动作名称、耗时、成功/失败结果和可追踪上下文。
- [ ] 上游错误码、HTTP 状态、业务错误原因可在日志中定位，但不泄露 secret。
- [ ] 管理端或运维日志能区分 `mofang_finance_api` 与 `hosting_panel_api` 的调用失败。

### 9.6 文档与测试验收

- [ ] `文档/开发文档/集成/插件开发/demo-mofang-finance.md` 与当前插件结构一致。

- [ ] 覆盖插件解析、provider key 防回归、商品配置项、登录缓存、开通、续费、状态同步、VNC 和控制台动作测试。
