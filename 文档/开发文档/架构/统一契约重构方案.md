## 2. 最终契约

### 2.1 订单类型

订单 `orders.type` 只允许：

| 值 | 含义 |
| --- | --- |
| `new` | 新购 |
| `renew` | 续费 |
| `upgrade` | 附加配置、升降级、流量包等服务变更订单 |

删除：

- `addon`：不再作为请求值、响应值、前端枚举值、测试数据值或页面筛选值。
- `normal`：订单不再使用；仅允许作为历史账单 `invoices.type` 兼容值存在。

统一显示：

- `upgrade` 显示为“附加配置”。
- 前端类型文案只从 `shared/statusConfig.js` 获取。

### 2.2 日期筛选

财务列表查询参数统一为：

```text
start_date=YYYY-MM-DD
end_date=YYYY-MM-DD
```

后端规则：

- 只传 `start_date`：`created_at >= start_date 00:00:00`
- 只传 `end_date`：`created_at <= end_date 23:59:59`
- 两者都传：`whereBetween(created_at, [start_date 00:00:00, end_date 23:59:59])`
- `start_date > end_date`：返回项目统一 422 响应，业务码 `42200`

删除：

- `date_range`
- 数组式日期查询
- 同一接口混用 `per_page`、`pageSize`、`page_size`

### 2.3 供应商配置

`suppliers.provider_config` 是正式字段：

- `api_url`、`api_username`、`api_key` 只作为通用基础字段保留。
- 其他插件/上游字段进入 `provider_config`。
- `provider_config` 使用 Laravel `encrypted:array` cast。
- 列表和详情接口只返回非 secret provider 字段；secret 字段空值表示“已有但不明文返回”。
- secret 字段查看必须走 reveal 接口。

供应商保存请求必须提交：

```json
{
  "interface_type": "provider_key",
  "name": "供应商名称",
  "status": 1,
  "api_url": "https://example.com",
  "api_username": "user",
  "api_key": "secret-or-empty-keep-existing",
  "provider_config": {}
}
```

### 2.4 API 边界

- 管理端、用户端复杂查询和写操作必须使用 FormRequest。
- Controller 只做：接收已校验数据、鉴权上下文、调用 Service、返回响应。
- 不在 Controller 内 `$request->validate()`。
- 不在 Controller 内手写复杂参数归一化。

### 2.5 分页响应

继续保持项目外层：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

列表分页只返回：

```json
{
  "list": [],
  "total": 0,
  "page": 1,
  "page_size": 20
}
```
