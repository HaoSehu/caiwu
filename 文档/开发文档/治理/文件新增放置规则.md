# 文件新增放置规则

- 文档性质：现行规则
- 执行日期：2026-05-23
- 最后更新：`2026-06-19`（适配 开发文档/开发记录 两级结构）
- 读者画像：所有开发人员、运维人员

## 1. 目的

防止治理后的目录结构再次失控。新增文件前先查本表，确认放置位置。

## 2. 目录两级划分

| 目录 | 判断标准 |
|------|----------|
| `开发文档/` | 修改后需要长期维护的固定规范、指南、规则 |
| `开发记录/` | 一次性产物：报告、快照、交接、审计、日志 |

## 3. 放置规则

### 3.1 开发文档（永久规则、长期维护）

| 文件类型 | 放置位置 | 说明 |
|----------|----------|------|
| 产品文档 | `开发文档/产品/` | 产品全局视角 |
| 架构文档 | `开发文档/架构/` | 技术架构现状、方案设计 |
| 后端规范 | `开发文档/后端/` | 后端规则、接口、目录规范 |
| 前端规范 | `开发文档/前端/` | 前端规则、结构、实现规范 |
| 数据库流程 | `开发文档/数据库/` | 数据库结构说明、迁移流程 |
| 上游文档 | `开发文档/集成/` | 第三方 API 文档、对接说明 |
| 治理规则 | `开发文档/治理/` | 目录治理、文件放置规则 |
| 部署运维 | `开发文档/` | 根目录，除非形成稳定子目录 |

### 3.2 开发记录（一次性产物、不定常维护）

| 文件类型 | 放置位置 | 说明 |
|----------|----------|------|
| 审查/审计报告 | `开发记录/审查报告/` | 工程深度审查、审计报告 |
| 任务交接 | `开发记录/` | AI 任务交接、分批任务说明 |
| 测试执行报告 | `开发记录/架构/` | 自动化测试归档 |
| 数据库审查/审计 | `开发记录/数据库/` | 数据库审查、迁移审计 |
| 数据库快照 | `开发记录/数据库/快照归档/` | SQL dump、数据库结构快照 |
| 迁移日志 | `开发记录/数据库/迁移记录/` | 迁移执行日志 |
| 测试输出 | `开发记录/测试/原始输出/` | 测试运行日志和输出 |
| 治理记录 | `开发记录/治理/` | 治理执行结果、清单、映射表 |
| 演示页/原型 | `开发文档/前端/原型与素材/` | HTML 原型、UI 演示 |
| 构建日志 | `开发文档/归档/历史资料/` | 历史构建记录 |
| 开发日志 | `开发文档/归档/历史资料/dev-logs/` | dev server 日志 |
| 后端维护脚本 | `backend/scripts/` | 不放长期业务代码 |

## 4. 禁止事项

- 禁止在仓库根目录新建文档或演示文件
- 禁止在 `backend/` 或前端目录根部新建日志、报告、快照文件
- 可再生产物（`dist/`、`.phpunit.cache/`、`node_modules/`）不纳入版本管理

## 5. 命名规则

- 规则型文档（开发文档）：`主题 + 类型.md`（如 `产品总览.md`）
- 带日期文档（开发记录）：快照、分析、报告、验收类文件名含日期（如 `数据库结构说明-idc-2026-04-17.md`）
- 现行规范直接原位更新，不新增 `v2`、`最新版`、`最终版` 后缀
