# 全栈代码规范化工程化治理计划

- 文档性质：现行治理计划
- 首次执行日期：`2026-06-30`
- 适用范围：`backend`、`frontend-admin-v3`、`frontend-user-v3-www`、`frontend-user-v4-console`、`shared`

## 1. 文档定位

本文档作为 Caiwu 全栈代码规范化、工程化、目录治理、API 契约治理和后续维护升级的执行依据。

执行口径：审计全覆盖，修改有价值文件。每个源码文件需要有检查结论，但不得为了“覆盖”机械加注释、机械格式化或制造无意义改动。

## 2. 核心原则

- 不回滚当前脏工作区中已有用户改动。
- 不全仓格式化，不做一次性大重写。
- 不新增重复请求层、重复 UI 库、重复状态库。
- API 请求和响应以现有 `ApiResponseBuilder`、`ApiResponse`、FormRequest、Resource 为准。
- 前端请求走各端现有 `src/api/*` 和 request/runtime 工具。
- 状态、运行时、状态标签、控制台基础组件优先复用 `shared` / `@caiwu/shared`。
- 注释只解释复杂业务原因、兼容边界、第三方协议差异、幂等/事务/安全约束。
- 自动生成的 `文档/开发文档/后端/后端API清单.md` 不手工编辑。

## 4. Task List

### Task 1：冻结基线与保护脏工作区

验收标准：

- 记录 `git status --short`。
- 标出用户已有改动、生成物、临时文件、可治理源码。
- 不删除、不回滚、不覆盖现有改动。

验证：

- 输出覆盖前基线摘要。
- 明确本次不会触碰的用户改动列表。

### Task 2：建立全仓源码覆盖矩阵

验收标准：

- 覆盖 `backend/app`、`backend/routes`、`backend/tests`、三个前端的 `src` / `tests` / `scripts`、`shared`。
- 每个文件至少标注：所属项目、层级、风险等级、是否建议修改、建议批次。
- 指定根内的图片等资产文件也必须逐行给出检查结论；Git 已删除但仍属于指定根的源码路径必须记录保护结论，不得只放在说明段落。
- 生成覆盖矩阵到 `文档/开发记录/治理/`。

验证：

- 覆盖矩阵文件存在。
- 文件总数与 `rg --files` 扫描结果、指定根内 Git 删除项可对齐，漏项必须为 0。

### Task 3：后端 API 契约审计

验收标准：

- 检查裸 `response()->json`、裸数组响应、非统一分页、错误码不规范、敏感字段输出。
- 检查 `page` / `page_size` 与历史 `per_page` 兼容边界。
- 不手工编辑自动生成的 `后端API清单.md`。

验证：

- 输出 API 契约问题清单。
- 必要时运行目标后端测试。

### Task 4：后端请求入口治理

验收标准：

- 写操作、复杂查询、财务/支付/上游/批量接口优先迁移或登记为 FormRequest。
- Controller 不继续堆 `$request->input/query/validate`。
- 兼容逻辑保留原因必须短注释说明。

验证：

- 受影响测试通过。
- `php vendor\bin\pint --test` 不因本次改动失败。

### Task 5：后端响应与敏感字段治理

验收标准：

- 面向前端输出优先走 Resource/DTO/统一响应。
- 不把第三方原始错误、secret、token、api_key、完整证件号透出。
- Service 不直接返回 HTTP Response。

验证：

- 补充或更新 Feature 测试覆盖敏感字段不泄露。
- `cd backend && php artisan test` 至少在阶段收口执行。

### Task 6：后端服务层结构治理

验收标准：

- Service 按领域进入现有目录，不新增 `_v2`、`new`、临时命名文件。
- Controller 中第三方调用、事务、复杂状态流转下沉到服务层。
- 不整体迁移稳定低风险命名空间。

验证：

- 依赖路径清晰，自动加载正常。
- 后端 targeted test 通过。

### Task 7：三端请求层统一审计

验收标准：

- 不新增 axios 实例。
- 统一处理 `code === 0`、`message`、`data.errors`、登录过期、分页结构。
- 梳理 admin、www、console 与 shared runtime 的复用边界。

验证：

- 三端受影响 build 通过。
- 错误提示仍为简体中文。

### Task 8：前端 API 类型与 normalizer 收敛

验收标准：

- 重复分页 normalizer、错误处理、状态映射优先复用已有工具。
- TypeScript 项目减少无必要 `any` / `as any`。
- `frontend-user-v3-www` 的 JS 结构不强行迁移 TS，只做低风险收敛。

验证：

- `cd frontend-admin-v3 && npm run build`
- `cd frontend-user-v4-console && npm run build`
- `cd frontend-user-v3-www && npm run build`

### Task 9：shared 复用治理

验收标准：

- 状态标签、状态文案、runtime/session、内容渲染优先复用 `shared`。
- 只有跨端稳定重复逻辑才进入 `shared`。
- 不把单页面业务逻辑抽进 `shared`。

验证：

- `npm run typecheck:shared`
- `npm run test:shared`
- 受影响前端 build 通过。

### Task 10：页面与领域结构治理

验收标准：

- 页面模板减少大段请求拼装、状态映射、金额/日期/状态魔法值。
- 业务逻辑进入 `domains`、`composables`、`features`、`utils` 等现有目录。
- admin 保持 TDesign，www 保持 Element Plus，console 保持 TDesign。

验证：

- 对应前端 build 通过。
- 涉及结构改造时执行 `verify:refactor`。

### Task 11：必要注释与文档同步

验收标准：

- 只给复杂业务、历史兼容、第三方协议、安全/幂等/事务边界加注释。
- 更新长期规则文档与执行记录。
- 不写无意义逐行注释。

验证：

- 文档路径符合 `文档/开发文档/治理/` 与 `文档/开发记录/治理/` 规则。
- 文档与当前代码事实一致。

### Task 12：最终验收与剩余风险清单

验收标准：

- 输出执行记录、覆盖矩阵、已修复问题、未修复问题、后续建议。
- 每个未修复项包含原因、风险等级、建议批次。
- 所有执行过的验证命令有结果记录。

验证：

- 后端：`cd backend && php artisan test`
- 前端：`npm run build:frontends`
- shared：`npm run typecheck:shared && npm run test:shared`
- 必要时补充 `npm run verify:refactor`

## 5. 公共接口与兼容策略

- 不破坏现有 API 外层：`code` / `message` / `data` / `timestamp`。
- 成功固定 `code = 0`。
- 分页固定 `list` / `total` / `page` / `page_size`。
- 历史 `per_page` 只作为兼容输入或兼容输出，不作为新增接口默认。
- 字段必须变更时，先登记影响面，再同步后端、前端、测试和文档。
