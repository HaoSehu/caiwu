# 前端项目规范

- 文档性质：现行方向
- 对齐时间：2026-06-07
- 读者画像：维护 `frontend-admin`、`frontend-admin-v3`、`frontend-client`、`shared` 的前端开发者与代理
- 适用范围：本仓库全部前端页面、样式、路由、接口接入、构建与验证流程

## 1. 文档目标

本规范用于统一 `frontend-admin`、`frontend-admin-v3` 与 `frontend-client` 的实现方式，减少重复封装、平行目录和页面内堆逻辑的情况。它不是脱离仓库的通用前端规范，而是基于当前代码结构、构建配置和页面组织方式整理出的执行规则。

发生冲突时，优先级按以下顺序处理：

1. 仓库根目录 `AGENTS.md`
2. `页面风格.md`
3. `启动指南.md`
4. 当前稳定运行的代码实现
5. 本文档

## 2. 项目边界

### 2.0 工作区形态

- 仓库前端已升级为 npm workspace 形态。
- 根目录统一管理：
  - `frontend-admin`
  - `frontend-admin-v3`
  - `frontend-client`
  - `shared`
- 推荐从仓库根运行前端脚本：
  - `npm run dev:admin`
  - `npm run dev:admin-v3`
  - `npm run dev:client`
  - `npm run build:frontends`
  - `npm run typecheck:frontends`
  - `npm run test:frontends`
  - `npm run verify:frontends`
- 子项目内原有 `npm run dev` / `npm run build` 继续保留，主要用于单端调试。

### 2.1 `frontend-admin`

- 定位：管理端后台，默认是亮色企业控制台。
- 技术：Vue 3、Vite、Element Plus、Pinia、axios、Sass。
- 页面入口：
  - `src/main.js`
  - `src/router/index.js`
  - `src/layout/AdminLayout.vue`
  - `src/layout/AdminLayout/index.vue`

### 2.2 `frontend-admin-v3`

- 定位：新版管理端后台，基于 TDesign Starter for Vue Next，逐步替代 `frontend-admin`。
- 技术：Vue 3、Vite、TypeScript、TDesign Vue Next、TDesign Icons Vue Next、Pinia、axios、Less。
- 工程基底：`Tencent/tdesign-vue-next-starter`。
- 页面入口：
  - `src/main.ts`
  - `src/router/index.ts`
  - `src/layouts/index.vue`
  - `src/layouts/components/`
- 目录结构：
  - `src/pages/`：按业务域组织的页面（`dashboard/`、`finance/`、`tickets/`、`services/`、`products/`、`users/`、`settings/` 等）
  - `src/router/modules/`：按业务域拆分的路由模块
  - `src/store/modules/`：Pinia 状态模块
  - `src/api/`：接口请求模块
  - `src/style/`：Less 样式与主题变量
  - `src/layouts/`：Starter Admin Layout 布局组件
- 约束：
  - **禁止**混用 Element Plus 组件或图标。
  - 图标统一使用 `tdesign-icons-vue-next`。
  - 所有页面功能、路由、权限、API 必须与旧管理端一致。
  - 样式走 Starter 自带的 `tvision-color` 主题变量和 Less 变量体系。

- 定位：官网 + 用户中心，官网允许更强视觉表达，用户中心仍以业务效率优先。
- 技术：Vue 3、Vite、Element Plus、Pinia、axios、Sass。
- 页面入口：
  - `src/main.js`
  - `src/router/index.js`
  - `src/layout/WebsiteLayout.vue`
  - `src/layout/ClientLayout.vue`

### 2.4 `shared`

- 定位：双前端共享包，不再只是零散工具目录。
- 当前分层：
  - `shared/status`：状态展示、状态映射、`StatusTag`
  - `shared/runtime`：session、路由 loading、标题/favicon、网络 hints、HTTP 原语
  - `shared/content`：markdown/html 安全渲染相关工具
- 约束：状态文案、状态色、状态标签优先复用 `shared/statusConfig.js`、`shared/extraStatusMaps.js`、`shared/components/StatusTag.vue`，不要在页面里重复硬编码一套。

## 3. 通用实现规则

### 3.1 组件与页面

- 统一使用 Vue 3 `script setup` 与 Composition API。
- 新增或重构的前端内核层代码优先使用 TypeScript。
- 页面模板只负责结构表达，不堆大段请求、状态映射和业务判断。
- 单页复杂逻辑优先下沉到页面同级 `composables/`、`utils/`、`services/`。
- 领域页面使用领域目录聚合，不按“一次性需求”散落文件。
- 同一业务域优先保留一个正式入口 `index.vue`，页面私有组件放在该目录内部。

### 3.2 请求层

- 所有 HTTP 请求统一走各端自己的 `src/utils/request.js`。
- 页面层只消费 `src/api/*` 暴露的方法，不直接在页面中创建 axios 实例。
- 认证信息统一走 `src/utils/auth.js`，不要直接读写 `localStorage` 键。
- 新接口保持后端当前响应约定：成功 `code = 0`，分页结构优先 `list`、`total`、`page`、`page_size`。

### 3.3 路由与页面标题

- 路由由各端 `src/app/router/*` 承载，`src/router/index.js` 只作为兼容导出入口。
- 新页面必须设置 `meta.title`，页面标题统一通过 `useAppStore().applyPageTitle(...)` 驱动。
- 需要鉴权的页面通过路由守卫处理，不要把鉴权跳转分散到页面组件中。
- 路由异步加载要提供明确的加载反馈，避免白屏切换。

### 3.4 状态管理

- 全局站点信息、用户信息、布局状态放入 Pinia store。
- 页面私有的短生命周期状态优先保留在页面或同级 composable，不滥用全局 store。
- store 内存在并发请求去重时，完成后必须正确释放缓存 promise，避免后续无法刷新。

### 3.5 用户可见文案

- 前端页面上的所有用户可见文案必须使用简体中文，包括页面标题、按钮、表单标签、占位符、校验错误、接口错误提示、确认框、通知、空状态、加载态、操作结果提示。
- 不得直接展示英文异常、第三方原始错误、后端堆栈、供应商错误码或未翻译字段名。
- 接口失败提示优先读取后端返回的简体中文 `message`；字段校验错误优先读取 `data.errors`，展示前应保持简体中文。
- 前端自行补充的兜底错误必须使用简体中文，例如“操作失败，请稍后重试”，不要使用 `Error`、`Failed`、`Unknown error` 等英文。
- 代码标识符、组件名、变量名可以使用英文；呈现在页面上的文本必须使用简体中文。

## 4. 样式与视觉规则

### 4.1 样式入口

- 统一复用：
  - `src/assets/styles/variables.scss`
  - `src/assets/styles/global.scss`
  - `src/assets/styles/element/index.scss`
- 非必要不要在业务页散落 `:deep(.el-*)` 覆盖。
- 颜色、圆角、阴影、间距优先走现有 token，不额外发明第二套视觉变量。

### 4.2 图标与品牌资产

- `frontend-admin` / `frontend-client`：图标统一优先使用 `@element-plus/icons-vue`。
- `frontend-admin-v3`：图标统一使用 `tdesign-icons-vue-next`，**禁止**混用 `@element-plus/icons-vue`。
- 品牌资源统一放在 `public/branding/`，业务静态图按语义目录归类到 `public/img/`。
- 不在页面中硬编码跨项目路径，不复制一份相同品牌资源到多个业务目录。

### 4.3 管理端视觉（Element Plus）

- 使用浅灰背景、白卡片、蓝色主操作。
- 列表页默认结构：筛选区 -> 表格卡片 -> 分页，不再加独立页头卡片。
- 管理端页面禁止新增独立的"头部说明卡片"。不要在页面顶部放只包含模块名、标题、说明文案和少量按钮的 `admin-page-head`、`*-hero`、`*-head` 大块。
- 详情页需要返回、刷新、保存等操作时，使用紧凑工具栏，不做说明型页头卡片。
- 后台页面不套官网 Hero 风格，不做深色大屏化改造。

### 4.4 新版管理端视觉（TDesign v3）

- 沿用 TDesign Starter for Vue Next 自带的主题变量（`tvision-color`）和 Less 变量体系。
- 使用 Starter Admin Layout 布局：侧边菜单、顶部栏、面包屑、用户菜单。
- 页面模板复用 Starter 的列表页、表单页、详情页模式，参考 `src/pages/` 下已有页面。
- 状态标签基于 TDesign Tag 组件适配 `shared/statusConfig.js` 状态映射。
- 不做深色大屏化改造，保持 Starter 原有亮色风格。

### 4.5 用户端与官网视觉

- 官网首页、产品页、登录页可更有视觉表达，但必须沿用现有品牌色与可读性规则。
- 用户中心、账单、服务控制台仍以白卡片业务结构为主，不做装饰性优先的布局。

## 5. 目录落点规则

### 5.1 `frontend-admin`

- 内核入口优先放在 `src/app/`：
  - `bootstrap`
  - `router`
  - `runtime`
  - `stores`
- 页面按业务域聚合，例如 `Users/`、`Products/`、`Orders/`、`Notifications/`、`Logs/`、`Settings/`。
- 路由第一阶段优先保持 `path` 与 `name` 稳定，只调整组件落点和目录归属。
- 同域 Tab 页可继续使用域内 `defineAsyncComponent`，不要把子页拆成跨目录漂浮文件。

### 5.2 `frontend-admin-v3`

- 内核入口：
  - `src/main.ts`
  - `src/permission.ts`（路由守卫）
  - `src/router/index.ts` + `src/router/modules/`
  - `src/store/index.ts` + `src/store/modules/`
- 页面按业务域聚合在 `src/pages/`：`dashboard/`、`finance/`、`tickets/`、`services/`、`products/`、`users/`、`settings/`、`content/`、`login/` 等。
- 布局组件在 `src/layouts/`，基于 Starter Admin Layout。
- API 请求模块在 `src/api/`，复用 `frontend-admin` 的 API 接口。
- 样式入口在 `src/style/`，使用 Less + `tvision-color` 主题变量。

### 5.3 `frontend-client`

- 内核入口优先放在 `src/app/`：
  - `bootstrap`
  - `router`
  - `runtime`
  - `stores`
- 官网页放在 `src/views/website/`，用户中心放在 `src/views/client/`；后续重构可逐步迁到 `src/pages/website` 与 `src/pages/client`，但首轮兼容旧落点。
- 购买、优惠券、恢复下单等流程优先复用：
  - `src/utils/websiteCheckout.js`
  - `src/utils/websiteCoupon.js`
  - `src/views/website/products/*`
- 服务控制台相关逻辑继续收敛在 `src/views/client/ServiceConsole/` 内部，不把同一实例域拆散到多个根目录。

## 6. 异步加载与性能规则

### 6.1 路由加载

- 路由组件默认使用异步加载。
- 管理端与用户端都应提供路由级 loading 反馈，避免切页时出现无反馈白屏。
- 页面内大区块可以继续使用 `defineAsyncComponent` + skeleton/fallback 方式分段加载。

### 6.2 大依赖处理

- 构建分包必须显式考虑大依赖，不把所有基础库挤进一个超大 vendor chunk。
- 当前仓库重点关注的重量级依赖包括：
  - `element-plus`
  - `@element-plus/icons-vue`
  - `tdesign-vue-next`（v3）
  - `tdesign-icons-vue-next`（v3）
  - `echarts`
  - `three`
  - `@novnc/novnc`
  - `markdown-it`
  - `qrcode.vue`
  - `axios`
- 做性能优化前，先检查现有路由懒加载和 `vite.config.js` 的 `manualChunks`，不要重复做已经存在的优化。

### 6.3 首页与高频页面

- 官网首页允许分段延迟挂载非首屏模块，但首屏信息必须可直接访问。
- 列表页优先处理重复请求、滚动监听、定时器和大列表渲染成本。
- 同一个安全读请求如果会被短时间重复触发，优先做请求去重而不是靠页面层规避。

## 7. 站点信息

- 站点名称、浏览器标题、Logo、favicon、客服联系方式、协议链接等由 `useAppStore()` 管理，不要在页面里各自拼一套。
- 站点配置需要支持再次刷新，不能因为一次请求成功就永久缓存到本次页面生命周期结束。

## 8. 开发与联调约定

- 本地开发统一使用 `127.0.0.1`，不要与 `localhost` 混用。
- 默认启动方式：

```bash
cd frontend-client
npm run dev

cd frontend-admin
npm run dev

cd frontend-admin-v3
npm run dev
```

- 后端联调地址、资源预热、预连接等逻辑继续收敛在各端的 `main.js`、`utils/network.js`、`utils/runtimeNetwork.js` 中统一处理。

## 9. 提交前检查清单

### 9.1 改 `frontend-admin`

至少执行：

```bash
npm run build:admin
```

如果只在子项目内验证，也可继续：

```bash
cd frontend-admin
npm run build
```

### 9.2 改 `frontend-admin-v3`

至少执行：

```bash
cd frontend-admin-v3
npm run build
```

注意：v3 的 build 包含 `vue-tsc --noEmit`，类型错误会导致构建失败。

### 9.3 改 `frontend-client`

至少执行：

```bash
npm run build:client
```

如果只在子项目内验证，也可继续：

```bash
cd frontend-client
npm run build
```

以下场景追加验证：

- 涉及结构性前端重构：`npm run verify:refactor`
- 双前端联动或共享层改动：`npm run verify:frontends`

### 9.4 自检项

- 新页面是否复用了现有样式入口和组件模式。
- 页面是否仍然通过 `src/api/*` 访问后端。
- `meta.title`、空态、加载态、错误态是否完整。
- 是否引入了新的重复抽象或并行工具层。

## 10. 禁止项

- 禁止在页面里直接 new axios。
- 禁止直接操作 token 的本地存储键。
- 禁止把业务判断和请求拼装大段写进模板。
- 禁止后台页面默认走深色大屏风格。
- 禁止为了“统一”把已有可复用能力删掉后重写一遍。
- 禁止改动公共响应结构却不同时更新前后端调用。
- 禁止在未验证构建的情况下提交前端改动。
