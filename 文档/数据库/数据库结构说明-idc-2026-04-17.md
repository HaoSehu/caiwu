## 1. 数据库概况

### 1.1 总体特征

- 这是一个面向 IDC / 云服务业务的综合业务库，主链路清晰：
  `用户 -> 商品 -> 订单 -> 账单 -> 支付 -> 服务实例`
- 结构上大量使用 `json` 字段保存配置、价格快照、通知参数和扩展数据。
- 多数核心业务表带有 `remark`、`operator`、`trace_id` 字段，具备较强的审计和追踪意识。
- 库内不存在数据库级外键，删除、迁移、修复数据时需要依赖业务代码保证一致性。
- 用户资金相关信息同时存在于 `users` 与 `user_accounts`，从结构看属于历史兼容与账户子表并存模式。

## 3. 逐表介绍总览

### 3.1 用户与权限

- `users`：用户主表，除登录信息外，还承载实名信息、推荐关系、余额字段和审核状态。
- `user_accounts`：用户账户子表，按 `user_id` 一对一记录现金余额、返佣余额和账户版本号。
- `verification_histories`：实名认证历史表，保存每次认证提交、处理结果和外部认证流水号。
- `member_levels`：会员等级或分销等级配置表，用于按累计销售额映射等级和返佣比例。
- `admin_users`：后台管理员账号表，保存登录账号、角色、状态和最近登录信息。
- `roles`：后台角色定义表，权限点以 `json` 形式保存在 `permissions` 字段中。
- `admin_user_roles`：管理员与角色的关联表，支持多角色分配。
- `personal_access_tokens`：Laravel Sanctum 的访问令牌表，用于 API 身份认证。
- `password_reset_tokens`：密码重置令牌表，用于找回密码流程。
- `sessions`：会话持久化表，用于保存登录会话和最近活跃时间。

### 3.2 商品与服务

- `product_groups`：商品分组表，支持父子层级和不同商品类型的展示分组。
- `products`：商品定义表，保存商品价格、配置项、库存、供应商映射和开通模块。
- `suppliers`：上游供应商配置表，记录接口地址、密钥、联系人和状态。
- `servers`：资源节点或宿主机抽象表，用于承载模块配置、容量和节点状态。
- `services`：服务实例表，表示用户购买后实际生成的业务实例，包含到期时间和开通数据。

### 3.3 交易与财务

- `orders`：订单主表，保存下单时的商品名称、商品类型、配置和优惠快照。
- `invoices`：账单主表，表示用户应付的收费单据，可关联订单。
- `invoice_items`：账单明细表，按行记录账单中的具体收费项目。
- `payments`：支付单表，用于承接订单或账单的支付动作和支付状态。
- `payment_callbacks`：支付回调表，用于落库保存网关异步通知原文和校验结果。
- `balance_logs`：余额流水表，偏向旧版现金余额变动记录。
- `account_transactions`：通用账户流水表，支持按账户类型、事件类型和来源对象追踪变更。

### 3.4 优惠与分销

- `coupon_campaigns`：自动发券活动表，用于按时间和条件批量生成或下发优惠券。
- `coupons`：优惠券定义表，保存折扣规则、适用商品、账期和使用限制。
- `user_coupons`：用户领券 / 发券记录表，表示某张优惠券和某个用户的绑定关系。
- `referral_rewards`：返佣奖励表，以订单为粒度记录推荐奖励金额、状态和释放时间。
- `referral_account_logs`：返佣账户流水表，记录返佣余额在冻结、可用、提现中、已提现之间的变化。
- `referral_withdrawals`：返佣提现申请表，保存用户提现账号、金额和处理状态。

### 3.5 内容与工单

- `content_categories`：内容分类表，用于帮助中心、公告、资讯等内容频道的分类管理。
- `content_articles`：文章内容表，支持发布状态、置顶、推荐、发布时间和软删除。
- `tickets`：工单主表，保存用户提单、优先级、状态和关联服务实例。
- `ticket_replies`：工单回复表，保存用户或客服在工单中的对话内容和附件。

### 3.6 通知与系统

- `settings`：系统配置表，采用 `group_key + item_key` 的键值结构保存配置项。
- `notification_logs`：统一通知日志表，适合承接站内、短信、邮件等多通道通知发送记录。
- `email_logs`：邮件发送日志表，记录模板、收件人、主题、内容和发送结果。
- `sms_logs`：短信发送日志表，记录手机号、模板参数、供应商和发送结果。
- `automation_logs`：自动化规则执行日志表，用于记录某个规则对某个对象的执行情况。
- `operation_logs`：操作日志表，用于记录后台或用户对各业务模块的操作行为。
- `jobs`：Laravel 队列表，用于存放待执行的异步任务。
- `failed_jobs`：Laravel 失败队列表，用于保存执行失败的异步任务详情。
- `migrations`：Laravel 迁移记录表，用于标记数据库迁移执行历史。

## 4. 核心关系概览

- `users.id -> orders.user_id -> services.order_id`
- `users.id -> invoices.user_id -> payments.invoice_id`
- `products.id -> orders.product_id -> services.product_id`
- `orders.id -> invoices.order_id`
- `orders.id -> payments.order_id`
- `orders.id -> referral_rewards.order_id`
- `users.id -> user_accounts.user_id`
- `users.id -> tickets.user_id -> ticket_replies.ticket_id`
- `coupons.id -> user_coupons.coupon_id -> orders.coupon_id`

## 6. 结构观察与后续建议

### 5.1 已经具备的建模优点

- 订单、商品、服务、账单、支付已经形成完整主链，结构比较清晰。
- 下单和开通环节使用了 `config_snapshot`、`coupon_snapshot`、`locked_pricing` 等快照字段，利于保留历史口径。
- 返佣、通知、自动化、操作日志都已经有专门表，审计基础较好。

### 5.2 需要重点关注的点

- `users.balance` 与 `user_accounts.cash_balance` 并存，后续如做收敛，应先明确哪边是权威余额来源。
- 没有数据库外键，数据修复和删除操作必须格外谨慎。
- `suppliers.api_key`、用户实名和支付信息都直接存在业务表中，安全治理时需要重点关注脱敏、权限和备份范围。
- `coupon_campaigns`、`coupons`、`user_coupons`、`member_levels`、`referral_withdrawals` 等模块已建模但当前数据较少，说明这些功能可能还在逐步启用阶段。

## 7. 结论

当前 `idc` 库已经不是单纯的用户与订单库，而是一套覆盖用户、商品、服务实例、账单支付、优惠券、返佣、工单、内容、通知和后台权限的完整业务库。若后续需要继续推进数据库收敛，建议优先围绕以下几条线处理：

1. 资金账户统一口径：`users` 与 `user_accounts`
2. 商品与服务链一致性：`products`、`orders`、`services`
3. 支付与账单闭环：`invoices`、`invoice_items`、`payments`、`payment_callbacks`
4. 营销与返佣启用边界：`coupons`、`user_coupons`、`referral_*`
5. 外部资源与供应商抽象：`suppliers`、`servers`、`services`
