# 服务状态五态化与实例电源状态

## 背景

1. caiwu 服务状态改为五态：**开通中 / 运行中 / 已暂停 / 已删除 / 异常**。
2. 实例状态改为电源状态，数据经魔方财务（zjmf_finance）插件从上游映射。

## 调研结论（实库与反编译库实锤）

- zjmf 上游 `host.domainstatus` 实际值域：`Pending/Active/Suspended/Deleted/Cancelled`（`Fraud/Completed` 仅存于注释；注释里的 `Terminated` 全库无写入点，实写为 `Deleted`，见 `app/common/logic/Host.php:563`）。官方中文映射真源 `app/config/public.php`：待开通/已激活/已暂停/被删除/被取消/有欺诈。
- caiwu 现值域 0-4，本地库（idc）分布 `{0:2, 1:72, 2:1, 4:119}`：**EXPIRED(3) 存量为零，且运行时无写入者**——到期流水线为「到期 → SUSPENDED(reason=expired) → 宽限期后 CANCELLED」（ServiceLifecycleAutomationService）。
- caiwu 现有上游映射 3 处同款（ServiceStatusSyncService / ProvisionService / ServiceTransformService）：`active→1、suspended→2、cancelled/deleted→4、default→0`。
- 电源状态：上游用户侧 `POST /dcim/refresh_power_status`（参数 id=host_id，home/DcimController::refreshServerPowerStatus → Dcim::refreshPowerStatus），返回 `data.status = on/off/suspend/waiting/process/paused/unknown` + `des` 中文（开机/关机/暂停/等待重启/{task}中/挂起/未知）。限制：仅支持上游产品 `type=dcim`。caiwu 传输白名单已含 `/dcim/` 前缀（`/dcim/buy_flow_packet` 已在用）。
- caiwu 已有电源标签死方法 `ServiceTransformService::resolvePowerLabel`（无调用方），本次收编进插件。
- 前端 SERVICE_STATUS_MAP 引用面：shared/statusConfig.js（真源）、v4-console useServiceCenter/useTickets、admin-v3 services/users 两页；www 端无引用。
- 详情页 `runtime.power_state/power_label` 链路已存在（transformDetail 组装、useServiceConsole 优先展示），缺的只是主动刷新端点。

## 风险与回滚

- 存量订正不可逆（已取消→已删除），迁移 down 仅恢复注释；部署前备份 services 表。
- 上游 `refresh_power_status` 仅支持 dcim 型产品，非 dcim 上游会返回 400，由前端静默降级到 module-status 快照。
- 上游侧若返回注释体系中的 Terminated，映射同样归已删除（三种删除拼写均收敛）。
