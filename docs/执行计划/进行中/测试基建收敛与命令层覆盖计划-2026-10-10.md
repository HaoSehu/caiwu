## V7-10 影响面评估（本批交付）

### 现状物证

| 事实 | 证据 |

### 环境约束（2026-10-10 实测）

- `idc` DB 用户授权：`ALL PRIVILEGES` 仅限 `idc` / `idc_test` 两库（**无全局 `CREATE DATABASE`**）→ 无法建临时 scratch 库验证「空库迁移链」；`migrate:fresh` 只能作用于 `idc_test`。
- 迁移链基线：`migrations` 表 219 条记录、`database/migrations` 44 个增量文件、`database/schema/mysql-schema.sql` schema dump 存在（Laravel 11+ `migrate` 会先载 dump 再跑增量）；`idc` 与 `idc_test` 均 67 表。

### 方案对比与推荐路径

| 方案 | 内容 | 收益 | 代价/风险 |
| --- | --- | --- | --- |
| **A（推荐，本迭代）** | 新增受护栏引导命令 `test:prepare`（目标库名必须以 `_test` 结尾否则拒绝 + `--force` 双闸），执行 `migrate:fresh` 重建 `idc_test`；配套 `.env.testing`（可选）与运维文档 | 干净检出跑一条命令即可自包含复现；隔离模型不变（事务回滚） | 小：一个命令 + 文档；首跑即验证迁移链 |
| C（渐进） | 新增测试逐步改用 `RefreshDatabase` 基线（先小范围试点） | 新测试天然隔离 | 中：需试点评估时长 |
| B（长期） | 全量切换 `RefreshDatabase` | 彻底自包含 + 可恢复 skip 用例 | 中-高：套件时长增加、迁移链需验证、76+ 文件改造 |

**推荐路径：A（本迭代）→ C（增量）→ B（长期，另行评估）。**

## test:prepare 与重建演练实录（2026-10-10）

**实现**：`app/Console/Commands/TestPrepareCommand.php`
- 双闸：目标库名必须以 `_test` 结尾 + 必须显式 `--force`；production 环境一律拒绝。
- 破坏性操作前**预检 `mysql` 客户端**（`migrate:fresh` 加载 schema dump 硬编码调用 `mysql`，走 PATH）；支持 `--mysql-bin="D:/BtSoft/mysql/MySQL8.0/bin"` 临时入 PATH（同步 putenv/$_SERVER/$_ENV，保证 Symfony Process 子进程继承）。
- 演练首个教训（已固化为预检）：首跑在「删表后、schema 加载时」因 mysql 客户端缺失失败，留下半程状态；预检前置后此类失败发生在删表之前。
- 配套 `TestPrepareCommandTest` 3 用例（拒绝路径静态验证，套件内绝不真实重建）。

**重建演练结果（2026-10-10 22:50~23:10）**：
1. `mysqldump idc_test` 备份（261MB → `backend/storage/app/backups/idc_test_20261010_225021.sql`，已 gitignore）。
2. `php artisan test:prepare --force --mysql-bin=...` → **67 张表重建成功**，schema dump 加载 4s，迁移链完整（无缺口）。
3. 全量回归发现 **5 个「共库残留依赖」失败**（重建即暴露，正是 V7-10 记录的问题）：
   - `StockGateTest` ×3：把一级分组 id 塞给 `products.product_group_id`（外键→三级分组），旧库恰有同 id 行才通过 → 改为逐级造可见 一/二/三级分组链；
   - `CouponDiscountDisplayEndToEndTest`：`jobs` 表存在行断言依赖残留行（测试环境队列实为 sync）→ 改 `Queue::fake()` + `assertPushedOn('coupon', …)` 断言真实派发目标；
   - `InvoiceCleanupAutomationTest`：订单随账单级联取消后不再计入 `orders_cancelled`，计数断言靠残留未付订单撑住 → 补「独立挂单（无账单）」验证订单侧清理路径自身。
4. 修复后全量回归绿（见修复批次第八轮/本计划验证记录）。**结论：干净库 `test:prepare → php artisan test` 链路成立。**

### 重建演练深挖（23:00~23:20）：共库残留的根因修复

重建后又定位并修复 3 处测试缺陷（残留数据的真正来源）：

1. **`AdminManualOrderEntryTest`、`RechargeIdempotencyTest` 类体未应用 `DatabaseTransactions`**（仅 import 未 `use`，全部写入直通提交）——单跑复现：3 个用例即向 idc_test 提交 3 个用户；全库扫描同类缺陷仅此 2 处。修复后单跑零残留。
2. **`ZjmfBillingRestoreServiceTest` dump 客户行 ID 硬编码 3**：恢复服务按「dump 客户 ID = users.id」回写余额，硬编码行在干净库被「用户不存在」过滤 → 余额断言失败（此前被 skip 分支长期掩蔽）。参数化为用例用户后 force 路径完整通过。
3. 附：`RechargeIdempotencyTest` 的 trait 缺口系此前编辑历史遗留，已修复并复核。

**修复后干净库全量回归：495 过 / 0 失败 / 1 跳过（skip 为 Z case 的脏库防御分支，干净库不再触发）**；再修复后验收全量（见最终记录）。
