# 三端手机端适配与自适应（逐页产品级）

## 背景

`frontend-admin-v3`、`frontend-user-v4-console`、`frontend-user-v3-www` 三端已具备响应式底盘：
断点令牌（管理端 `MOBILE_BREAKPOINT=768` / `TABLET_BREAKPOINT=992`，控制台 `@screen-mobile-max`
与 `useDeviceLayout`，官网 `$breakpoint-*` 与 `useMobileBreakpoint`）、移动侧栏抽屉、
共享 `theme.css` 的弹层与触控热区兜底、以及部分列表页的移动卡片形态。

但覆盖极不均匀。按目录口径核对（同目录 `.less`/`.scss` 中的 `@media` 是否生效），当前缺口：

- 管理端 `frontend-admin-v3`：36 个页面中，工单列表与详情、用户详情各 Tab、用户实名核验、
  设置、集成插件、数据库、日志三个抽屉、通知子面板、产品目录子组件、结果页仍无移动形态。
- 控制台 `frontend-user-v4-console`：56 个页面文件中，服务控制台全部 Tab 与 9 个对话框、
  帮助 / 帮助详情 / 公告 / 公告详情 / 商品目录、仪表盘无移动形态。
- 官网 `frontend-user-v3-www`：公告与帮助页共用 `ContentListPage`，落地页共用 `SeoLandingView`，
  已具备响应式；剩余缺口为首页容器与少量档位。

用户已裁决：三端均按**逐页产品级体验**推进，管理端与用户端**同等深度**，并**新增移动端 e2e**。

## 目标与非目标

目标：

- 三个 Vue 端在 375px（iPhone SE 基准）与 390px/414px 常见手机宽度下无横向溢出。
- 每个页面在手机端有明确信息层级：筛选区纵向排列、列表在手机端转为卡片或可横向滚动的完整表格、
  详情页字段纵向或两列、操作按钮全宽或成组可点。
- 所有可交互元素触控热区 ≥ 44×44（`docs/DESIGN.md` §7）。
- 对话框与抽屉在手机端不超宽、页脚按钮可点、内容可滚动。
- 每端新增移动端 e2e，断言核心页面在移动视口下的结构与非溢出。

非目标：

- 不移除既有后端能力、不改变接口语义。本计划附带的少量后端改动只做「补齐前端已依赖的契约」
  与「统一口径」，单独列在下方「附带后端改动」一节，不与前端样式混在同一回滚单元里。
- 不引入新的 UI 框架或新的状态管理/请求抽象。
- 不做深色模式（`docs/DESIGN.md` §2 明确只提供浅色）。
- 不重写页面整体信息架构；产品级体验指手机端形态的合理重排，不是重新设计产品。

## 统一判定口径

三端必须共用同一套响应对齐规则，避免各页各写一套：

1. **断点唯一**：手机形态一律 `@media (max-width: 767.98px)`（管理端 LESS 写字面量，控制台用
   `@screen-mobile-max`，官网用 `$breakpoint-mobile-max`）。JS 判定与 CSS 同源：
   管理端 `window.innerWidth < MOBILE_BREAKPOINT`，控制台 `useDeviceLayout().isMobile`，
   官网 `useMobileBreakpoint()`。禁止区间语法。
2. **平板档**：`991px` 仅用于布局层页边距归零与卡片内边距收窄，不用于形态切换。
3. **列表三选一**：a) 手机端专用卡片模板（`.xxx-mobile-card`，桌面表格 `display:none`）；
   b) 表格保持但外层横向滚动容器；c) 次要列隐藏。财务与工单类优先 a，配置类优先 b。
   同一页面只选一种，不混用。
4. **详情页字段网格**：复用既有 `record-detail-page` / 四层骨架，手机端由 4 列降为 1 列。
5. **筛选区**：手机端 `flex-direction: column` 或两列 grid，操作按钮整行等分；不做横向滚动筛选条。
6. **弹层**：宽度由 `theme.css` + `mobile-overlays.less` 兜底，页面只处理内容排版，不重复写宽度。
7. **触控热区**：仅图标按钮显式 `min-width/height: 44px`；文字按钮用 `theme.css` 的 `.t-button` 基线。
8. **禁止**：`display:none` 删掉唯一操作入口；`!important` 覆写热区以外的属性；新增非 TDesign 组件。
9. **移动形态标记（可测契约）**：列表类页面在手机端必须渲染一个带 `data-mobile-view` 的容器：
   - 卡片形态：`data-mobile-view="card"`
   - 横向滚动表格：`data-mobile-view="scroll"`
   该容器只在手机断点下存在或可见，桌面端不渲染/不可见。三端 e2e 用它判定「这一页是否真的做了
   手机端适配」，而不只是「恰好没有溢出」。非列表页面（详情、表单、设置）同样在手机端主容器打
   同名字段，值取 `detail` / `form`，以便逐页清点。

## 实施步骤

1. 建立移动端 e2e 基线（每端一份），先以当前状态跑出失败清单，作为改动前的证据。
   - 基线结果：管理端 17 页无形态标记；控制台 14 页；官网 5 页。
2. 按端 + 页面域拆分并行实施（六个子代理，页面目录严格隔离）：
   - 管理端 A：财务四页 + 订单/账单详情 + 用户详情 + 服务控制台；
   - 管理端 B：用户/实名/工单/内容/日志/通知；
   - 管理端 C：产品/营销/系统/设置/结果页；
   - 控制台 A：服务控制台（7 个 Tab + 9 个对话框）；
   - 控制台 B：服务/目录/仪表盘/公告/帮助/优惠券/推广；
   - 官网：首页/产品/落地页/公告/帮助/关于/法务 + 布局层。
3. 主进程独占公共层：`theme.css`、各端 `style/`、`layouts/`，并补齐管理端看板/登录/结果页、
   营销卡片、控制台财务三页与充值/工单/实名/资料的形态标记。
4. 全部合并后逐端串行跑构建、`verify:refactor`、e2e 与体积门禁。

## 风险与回滚

- 风险一：多代理并行改同一端样式文件。缓解：任务按页面目录严格隔离，公共层
  （`theme.css`、`style/layout.less`、`variables.less`）由主进程独占修改。
- 风险二：移动卡片与桌面表格双份模板造成维护负担。缓解：优先复用既有
  `mobile-record-card` / `record-mobile-card` 组件，不新造。
- 风险三：误删桌面端行为。缓解：所有移动规则限定在 `max-width: 767.98px` 内，
  桌面规则零改动；e2e 既有桌面用例必须保持通过。
- 回滚：前端改动均为样式与模板，按页面目录回退即可，无数据影响；
  附带的后端改动单独回退（见下节），不随前端回滚。

## 附带后端改动

手机端适配暴露了三处既有契约缺口，随本计划一并修复，回退时需单独处理：

| 文件 | 改动 | 原因 |
| ---- | ---- | ---- |
| `Http/Requests/Admin/V2/UserService/ListUserServicesRequest.php` | `status` 同时接受单值与数组，两个分支都校验值域 | 用户详情状态筛选改为多选，旧的 `in:0,1,2,3,4` 只覆盖单值 |
| `Services/ClientServiceConsole/ServiceOverviewService.php` | `status` 为数组时走 `whereIn` | 同上 |
| `Services/User/UserService.php` | 列表 `opened_product_count` 与详情 `service_active` 统一为「开通中 + 运行中 + 已暂停」 | 与删除校验口径一致，避免「详情显示 0 个服务却被拒绝删除」 |

## 代码审查整改（2026-11-06）

首轮实现后做了一轮代码审查，以下问题已修复：

| 问题 | 处理 |
| --- | --- |
| 删除 `.service-view-toggle` 的移动端隐藏规则，与 `useServiceCenter#restoreViewMode` 的「手机端强制卡片」逻辑冲突，产生可点但刷新即失效的按钮 | 恢复隐藏规则，并补注释说明原因 |
| `mobile-record-card` 逐行调用 `useMediaQuery`，一页 20–50 行各注册一份 matchMedia；父容器已有同一标记 | 移除组件内标记与 hook，保留父容器标记 |
| 工单详情的标记挂在 `v-if="detail"` 容器上，加载/失败态无标记 | 移到页面根节点 |
| 工单列表用 CSS 显隐而非 `v-if`，两套节点永久共存 DOM | 改为 `v-if="isMobile"` 二选一；因桌面分页夹在中间，`v-else` 不适用，改用独立 `v-if` |
| `data-mobile-view` 混用 `:null` / `:undefined` / `isDesktop` 三种写法 | 统一为 `条件 ? 'x' : undefined` |
| `767.98px` 字面量在 40 个文件重复硬编码 | 抽出 `MOBILE_MEDIA_QUERY` 常量，全部改引用 |
| 官网公告/帮助列表的 `card` 标记挂在含 hero 与侧栏的根节点，语义过宽 | 收回到 `.list-panel` 列表容器 |
| e2e 只验证手机端有标记，未验证「桌面端不渲染」 | 三端各补反向断言（1280px 下 `[data-mobile-view]` 数量为 0） |

另有两条未采纳：`useMediaQuery` 内部的 `MediaQueryList` 重复创建属既有实现（改为模块级共享
会让页面切换时的组件卸载互相干扰，实测导致标记误判，已回退）；e2e 在空数据下不断言标记可见性，
因为空列表时卡片容器高度为 0，可见性改由「列表切换为卡片形态」用例在有数据时覆盖。
