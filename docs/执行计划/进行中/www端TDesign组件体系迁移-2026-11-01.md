# www 端 UI 组件体系迁移（Element Plus → TDesign Vue Next）-2026-11-01

- 适用范围：`frontend-user-v3-www/`。管理端 `frontend-admin-v3`、控制台 `frontend-user-v4-console` 早已是 TDesign，本次不动。
- 关联规格：`docs/DESIGN.md`（设计令牌与组件映射）、`docs/FRONTEND.md`（前端规范）。
- 关联计划：`docs/执行计划/进行中/TDesign规范逐页对齐-2026-11-01.md`（只覆盖 admin/console 的规范对齐，本计划是 www 的体系迁移，两者不重叠）。

> 本文件记录迁移决策与现状依据。所有结论来自当前运行代码、官方组件文档（tdesign-mcp-server）与实测构建输出，不猜测。

## 1. 目标

把 `frontend-user-v3-www` 从 Vue 3 + Element Plus 迁移到 Vue 3 + TDesign Vue Next：

1. 该端**所有**使用 Element Plus 的页面与组件全部替换，完成后不残留 EP 的组件引用、样式引用与依赖。
2. 业务逻辑、接口调用、路由与交互行为保持不变，本次只替换 UI 层与组件体系。
3. 设计上向 `https://tdesign.tencent.com/` 的规范与组件用法对齐；TDesign 无法直接满足的现有视觉细节按贴近规范的方式处理，并逐条登记在第 5 节。
4. 同步更新与本端 UI、组件用法、依赖说明相关的文档。

## 2. 迁移前基线（Element Plus，已实测）

| 关注点 | 迁移前状态 |
| --- | --- |
| 依赖 | `element-plus ^2.9.0`、`@element-plus/icons-vue ^2.3.0` |

| 主题 | `src/assets/styles/element/index.scss` 用 `@forward element-plus/theme-chalk/src/common/var.scss with (...)` 把站点 Sass 令牌灌进 EP；`:root` 另写一批 `--el-*` |

## 3. 目标方案（TDesign Vue Next）

沿用 admin/console 已经验证过的按需子入口范式，**不重新发明**：

| 关注点 | 迁移后做法 | 依据 |
| --- | --- | --- |
| 依赖 | `tdesign-vue-next ^1.19.1`、`tdesign-icons-vue-next ^0.4.4`（workspace 提升安装） | 与 admin/console 同版本口径，锁文件 dedupe 到同一份实现 |
| 组件解析 | 新增 `scripts/tdesign-resolver.mjs` 的 `createTDesignResolver()`，把 `<t-xxx>` 解析到 `tdesign-vue-next/es/<dir>/index`，子入口自带 `import './style/css.mjs'` | 官方 `TDesignResolver` 的 `from` 恒为全量 barrel，会把全部组件样式拉进包；表数据取自 `es/index.mjs` 的导出语句（约四成导出名目录不是 kebab-case） |
| 函数式插件 | `MessagePlugin` ← `es/message/plugin`；`DialogPlugin` ← `es/dialog/plugin`。这两个 plugin 入口**不带样式**，由 `bootstrap.ts` 补 `es/message/style/css.mjs` 与 `es/dialog/style/css.mjs` | 组件入口带样式、plugin 入口不带，是包内 `sideEffects` 声明的直接结果 |
| 设计令牌 | 入口引入仓库根 `theme.css`（TDesign 令牌唯一真源） | 与 admin/console 同级联顺序 |
| 入口顺序 | `es/style/index.css` → `theme.css` → message/dialog 样式 → `global.scss` | `es/style/index.css` 自带 TDesign 默认品牌色（`--td-brand-color-6 #366ef4`），站点令牌块必须排在其后覆盖 |
| 全局配置 | 删除 `provideGlobalConfig` | `es/config-provider/utils/context.mjs` 的 `defaultGlobalConfig` 已 merge `zh_CN`；admin/console 也都没有该调用 |
| locale 瘦身 | 删除 `strip-element-plus-en-locale` 插件与 `src/shims/en-locale.mjs` | TDesign 不再有 `use-locale` 静态 import en 的问题，插件失去作用对象 |
| 主题入口 | 删除 `src/assets/styles/element/`，`global.scss` 去掉全部 `.el-*` 覆盖与 `--el-*` 变量 | 站点自定义的 `variables.scss` 保留（与 UI 框架无关） |
| 图标 | 一律显式 `import { XxxIcon } from 'tdesign-icons-vue-next'`，**禁止 `<t-icon name>`** | `<t-icon name>` 走 svg-sprite，要注入 `https://tdesign.gtimg.com/icon/*/fonts/index.js`；www 的 CSP `script-src 'self' 'unsafe-inline'` 不放行该域，且不该为首屏引入第三方脚本 |
| 暗色块剔除 | 新增 `scripts/light-theme-only-postcss.mjs`，在 postcss 阶段删掉 `:root.dark, :root[theme-mode='dark']` 整块 | 本站仅浅色；`es/style/index.css` 与 `es/skeleton/style/index.css` 各带一块永不生效的暗色变量（约 5.6 KB minified） |
| 体积门禁 | 维持 `FIRST_SCREEN_BUDGETS.www = 145,000`、`CHUNK_BUDGETS.www = 180,000`、`CSS_CHUNK_BUDGETS.www = 70,000`，只把注释里的「www 用 Element Plus」改为事实描述 | 门禁口径（manifest 静态闭包）不变 |

## 4. 组件映射

| Element Plus | TDesign Vue Next | 注意点 |
| --- | --- | --- |
| `el-button type="primary"` | `<t-button theme="primary" variant="base">` | `theme.css` 的 `#app .t-button` 有 `min-width: 72px` |
| `el-button link` | `<t-button variant="text">` | `theme.css` 已把 `--variant-text` 的 `min-width` 归 `auto`，否则行内链接按钮会被撑到 72px |
| `el-button plain` | `<t-button variant="outline">` | — |
| `el-input` | `<t-input>` | `@input` 语义改为 `@change` / `@enter` |
| `el-select` + `el-option` | `<t-select :options>` 或 `<t-select><t-option/></t-select>` | — |
| `el-input-number` | `<t-input-number>` | — |
| `el-tabs` + `el-tab-pane` | `<t-tabs>` + `<t-tab-panel value label>` | theme 用 `normal` |
| `el-empty` | `<t-empty :description>` | `role="status" aria-live="polite"` 需显式补（e2e 断言依赖） |
| `el-alert` | `<t-alert theme message>` | 默认不可关闭 |
| `el-divider` | `<t-divider>` | 垂直用 `layout="vertical"` |
| `el-tooltip` | `<t-tooltip content placement>` | 继承 Popup 属性 |
| `el-popover` | `<t-popup trigger placement>` | 默认 trigger 是 hover，点击型要显式 `trigger="click"` |
| `el-drawer`（仅 MobileSheet） | `<t-drawer placement="bottom" :header="false" :footer="false" :close-btn="false" attach="body">` | `footer` 默认渲染确认/取消两个按钮，必须显式关闭；不传 `attach` 不 Teleport，遮罩会失效 |
| `el-pagination` | `<t-pagination v-model:current v-model:page-size>` | `showPageSize`/`showJumper` 默认 true，单页隐藏必须显式传布尔 |
| `ElMessage.xxx` | `MessagePlugin.xxx` | 样式由入口补 |
| `ElMessageBox.confirm` | `DialogPlugin.confirm` | 样式由入口补 |
| `@element-plus/icons-vue` | `tdesign-icons-vue-next` 逐图标组件 | 命名规则：kebab → PascalCase + `Icon`（`arrow-right` → `ArrowRightIcon`） |

## 5. 无法直接对齐 TDesign 规范的视觉细节

### 5.1 全站性说明

- 图标一律显式 `import { XxxIcon } from 'tdesign-icons-vue-next'`，禁止 `<t-icon name>`：`t-icon` 走 svg-sprite，需从 `tdesign.gtimg.com` 拉雪碧图脚本，本站 CSP `script-src 'self' 'unsafe-inline'` 不放行，且首屏不应引第三方脚本。命名规则 kebab → PascalCase + `Icon`。
- `theme.css` 的 `#app .t-*` 覆盖（`.t-button { min-width: 72px }`、移动端 `min-height: 44px`、`.t-input` 背景、`.t-card__body` padding 等）来自管理端与控制台的规范，本站引入后同样生效；本次未改动这些跨端规则，页面侧通过 `variant="text"`（`min-width: auto`）承接行内链接按钮。
- `scripts/light-theme-only-postcss.mjs` 剔除 TDesign 样式里 `:root.dark` / `:root[theme-mode='dark']` 暗色块，与 `theme.css` 的「仅浅色模式」一致。

### 5.2 无障碍语义（ARIA）差异：组件库能力差异，不自行补齐

TDesign Vue Next 整体不向 DOM 输出 ARIA 角色属性。逐组件比对（EP 2.9.0 源码 `package/es/components/<组件>` 与 `tdesign-vue-next@1.20.7` 的 `es/<组件>`，统计 `aria-` 与 `"role"` 字面量命中数）：

| 组件 | EP aria / role | TDesign aria / role | 影响 |
| --- | --- | --- | --- |
| button | 0 / 0 | 2 / 0 | 无（TDesign 反而输出 `aria-disabled`） |
| empty | 0 / 0 | 0 / 0 | 无 |
| pagination | 39 / 0 | 0 / 0 | 无 role 差异；EP 的 `aria-current`/`aria-label` 文案丢失 |
| select | 29 / 12 | 0 / 0 | 下拉的 `role=listbox/option` 丢失 |
| input | 6 / 2 | 0 / 0 | 无 |
| input-number | 23 / 1 | 0 / 0 | 增减按钮的 `aria-label` 丢失 |
| drawer | 17 / 0 | 0 / 0 | 见下 |
| tabs | 10 / 2 | 0 / 0 | `role=tablist/tab`、`aria-selected`、`tabindex` 丢失 |
| tooltip | 9 / 2 | 0 / 0 | `role=tooltip` 丢失 |
| dialog | 0 / 0 | 0 / 0 | 无（两端都不输出） |
| popup / alert / divider | 0 / 0 | 0 / 0 | 无 |

两处需要单独说明：

1. **底部弹层（`MobileSheet.vue`）不丢语义**。`el-drawer` 的 17 处 ARIA 是它自带的焦点陷阱与 `role=dialog`，`t-drawer` 一个都不给（全仓无 focus-trap 实现）。站点已在 `src/components/MobileSheet.vue:21-24` 自行补 `role="dialog"` / `aria-modal="true"` / `aria-label` / `tabindex="-1"`，并自研焦点陷阱与焦点还原（见第 15b、15c 条），实测 Tab 不逃出弹层、关闭后焦点回到触发元素。
2. **二次确认弹框（`DialogPlugin.confirm`）丢了 `aria-modal` 与 `aria-describedby`**。EP 的 message-box 有 2 处 `aria-modal` + 6 处 `aria-label` + 3 处 `aria-describedby`，TDesign 的 dialog 全 0。该路径在 `src/domains/products/useWebsiteProductCheckout.js:495-532`（移除优惠券确认）。

**为什么不补**：补齐意味着给每个 TDesign 组件再套一层自研 ARIA 包装或改组件内部渲染，属于「用自定义实现替代 TDesign 已有能力」，与本次迁移的约束冲突；且 TDesign 的键盘可操作性并未退化（`t-tabs` 的 `nav-item` 不可聚焦，但 EP 的 `el-tabs` 同样只处理 Delete/Backspace、没有方向键漫游——已解包 EP 2.9.0 源码逐行核实，迁移前后一致）。记录为已知差异，若后续有无障碍达标要求，应在组件库层统一解决而不是在站点层逐页打补丁。
