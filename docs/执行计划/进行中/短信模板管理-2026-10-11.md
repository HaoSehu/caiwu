# 短信模板管理机制（运营商审核闭环）· 2026-10-11

## 背景

短信模板需经运营商审核，系统不内置短信模板。设计目标：插件从运营商 API **拉取/推送**模板形成审核闭环，系统对外保持统一调用方法不变（续费提醒、账单提醒等场景）。

**三层模型**：业务模板（`notification_templates` + `SmsTemplateCatalog` 业务码，唯一稳定契约）→ 映射层（新表 `sms_provider_templates`，桥接业务码与运营商模板 ID，含审核状态）→ 运营商模板（插件经 API 拉取/推送的供给侧数据）。

**设计已审核（2026-10-11），审核修订全部纳入本计划**：🔴 挂接操作补齐、🔴 deleted 状态与运营商侧删除探测、🟡 driver 解析上移、🟡 变量交集校验 fail-fast、🟡 旧列跨运营商风险标注、🟡 命名空间撞车文档化。

**用户裁决（2026-10-11 卡片）**：① push 一期与 pull 一并实现；② 旧列 `provider_template_id` 保留为末位兜底 + 切绑提示；③ 立计划并开工。

**调用方无感知依据（已读码核实）**：`SmsService::sendTemplateSms(phone, templateCode, params, options)` 是唯一正文入口，现仅两处调用（`NotificationTemplateTestSendService` 测试发送 + verify-code 非 aliyun 内部回落），业务场景（续费/账单提醒）当前实际只走邮件通道（`BillingAutomationService::sendTemplateEmail`），短信正文链路为预留——回归风险极低。`SmsMessageRequest` 已同时携带 templateCode + content。

**命名空间警示**：`SmsTemplateCatalog` 业务码 100001~100033 与阿里云号码认证模板码 100001~100005 **数值撞车但属不同命名空间**（业务码 vs 运营商模板 ID）；映射表靠列格式区分（`provider_template_id` 存运营商原生格式 SMS_xxx/数字码，`business_code` 存业务码）。

**非目标**：不做运营商签名管理（签名沿用插件现有配置）；不改造验证码链路（`sendVerifyCode` + `ProvidesVerifyCodeTemplate` 保持现状）；不在管理端做脱敏（审计红线）；不自动提交 git。

## 风险与回滚

- **数据**：新表只增不改存量；旧列兜底语义不变，回滚 = 停用挂接与同步入口即可，调用方零感知。
- **兼容**：映射优先于旧列是有意语义（映射更新鲜），已记决策日志；显式 option 优先级保持最高。
- **运营商接口**：真实通道（aliyun QuerySmsTemplateList/AddSmsTemplate）需真实凭据联调，一期以 demo 模拟 + aliyun 骨架交付，联调验证列为遗留项。
- **回滚条件**：解析链出现误命中（发送用错运营商模板）→ 回退 `SmsService` 单文件改动即可（resolver 独立新增无侵入）。

### 🟡 建议修（待裁决）

1. **rejected 模板「提审」与「编辑」语义重叠**：`submitForReview` 对 rejected 行调 `sms.templates.push`（Add）→ 运营商侧可能重复创建新模板 ID；而「编辑」走 `sms.templates.update`（Modify 旧 ID）。同一驳回模板两个入口行为不同。建议：rejected 行隐藏「提审」仅留「编辑」（Modify 重审），或 rejected 提审内部改走 update。
2. **同一业务码可被多个模板挂接**：`link` 不检查该业务码已有挂接，resolver 取 synced_at 最新（并列按 id）——行为可预期但旧挂接仍显示「已挂接」，易误判生效模板。建议：link 时自动解绑该业务码其他挂接（对齐 ZJMF SetSmsTemplatePost 先删后插的单挂接语义），或列表标注「生效中」。
3. **插件非业务异常冒泡为 500**：PluginRuntimeRegistry 捕获 Throwable 后 re-throw，非 BusinessException（如插件内参数校验异常）在管理端表现为 500。建议 service 层（submitForReview/updateTemplate/pull）catch 非 Business 异常转 BusinessException 保留原消息。
4. **绑定候选不校验插件启用状态**：PluginDriverManager 注册所有已安装插件（含 status=0 的 aliyun），绑定解析可命中未启用插件——本次「27 条全败」即绑定错指未启用插件、发送时才暴露。建议：绑定管理 UI 限制仅启用插件可绑（短期）；运行时 resolveDriver 过滤启用插件（改动面较大，可后置）。

### 🟢 确认无碍

- 权限/限流：写端点 SETTINGS_MANAGE + throttle:20,1，读端点 SETTINGS_VIEW。
- 密钥安全：插件配置经 configRepository 加密存取，模板管理不触碰密钥；日志不留敏感值。
