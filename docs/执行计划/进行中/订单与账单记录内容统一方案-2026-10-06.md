# 订单与账单记录内容统一方案

> **路线更新（2026-10-06）**：经用户确认采用**方案 2：职责重划**（账单=资金真源，订单=履约工单），本方案升级为方案 2 的实施载体。职责契约见下文「方案 2：职责重划」章节；记录契约（不变式 I1-I7 + 分组表）与工作项 W1-W10 继续有效，归入方案 2 的阶段一/阶段四实施。

## 背景

2026-10-06 对账单（invoices）/订单（orders）做了「逻辑 + 记录内容」审查：实库不变量探针（idc 库 2923 账单 / 406 订单）+ 全部创建路径字段对照（详见对话记录与记忆 `caiwu-invoice-order-audit-20261006`）。结论：

- **口径核心已稳**：所有现行路径 `amount` 均为应付价，`目录价 = amount + discount + member_discount_amount`（与 `Money::catalogAmountOf` 一致）；券记录完整；状态/金额无越界；引用无悬挂。
- **记录内容仍有缺口**（均为代码级、已验证）：明细投影漏算会员折扣且错值已持久化；新购账单 type 双值（`createFromOrder` 缺 `NEW` 分支）；补录订单缺商品快照；影子订单缺 `trace_id`；`createDirect` 丢弃会员折扣/`paid_amount`；升级/流量包跨 kind 静默取消未付账单；`config_snapshot` 跨类型异义、续费缺 `config_pricing_snapshot`；`adminDetail`/`clientDetail` 字段不对称。
- **存量异常**（本地库，疑似迁移/旧代码产物）：28 订单↔账单金额错位 + 9 孤儿订单（订单 id 9-52）；446 张 renew 账单无 `service_id`（173 已支付）。需生产核实，不自动修。

目标：定义订单/账单的**唯一记录契约**，写入侧全路径收敛并用契约测试锁死，投影可重放，存量有订正与核对方案。

**非目标**：不改金额口径（应付价已统一）；不动支付/履约链路结构；不新增表列（除非 D2 决策要求）；不自动修存量配对错位。

关联：[优惠券功能智囊团审查-2026-10-05.md](优惠券功能智囊团审查-2026-10-05.md)、[财务功能全链路与溯源审查方案-2026-10-03.md](财务功能全链路与溯源审查方案-2026-10-03.md)。

## 方案 2：职责重划（账单=资金真源，订单=履约工单）

用户在两条路线（①取消订单只保留账单；②重新分工）中选定方案 2。规划期完成两次全量触点清点（订单金额列约 40 触点、状态变更入口 10 处、`Money::catalogAmountOf` 9 处中 Invoice×5/Order×4、资金组成断言唯一订单依赖是回调事务内一处相等检查）与三轮计划自审。

### 职责契约（目标态）

- **账单 = 资金域唯一真源**：amount / discount / member_discount_amount、券四件套、paid_amount / paid_at / status、config_pricing_snapshot、member_discount_snapshot。
- **订单 = 履约工单**：service 关联、config_snapshot（开通载荷）、履约准入；其金额/券列**保留为「创建时资金快照 + 生命周期投影」**——不删列、不改 OrderStatus 枚举（order.status=PAID 是履约准入 `InvoicePaidOrchestrator:467`、推荐奖励 `ReferralService:197`、库存占用 `ProductSyncService:2226`、开通重试 `RetryFailedProvisionCommand:127`、退款资格 `InvoiceRefundService:92` 共同依赖的准入信号），唯一写者收敛为生命周期状态机。
- **两条读取准则**：资金决策（奖励基数、开通定价基数、退款额）读账单；订单域展示/统计（订单数、订单金额合计）读投影。
- **明确不做**：物理删列、改 OrderStatus 枚举、动履约主链、撤对账命令（降级为手工巡检）。

## 记录契约（目标态）

### 不变式（购买类路径必须全部满足）

| # | 不变式 | 说明 |
| --- | --- | --- |
| I1 | `amount + discount + member_discount_amount = 目录价` | `Money::catalogAmountOf` 唯一口径 |
| I2 | 折扣分列 | `discount`=优惠券减免；`member_discount_amount`=会员折扣；禁止合并成一个「优惠金额」 |
| I3 | 券四件套 | 用券时 `coupon_id`+`user_coupon_id`+`coupon_code`+`coupon_snapshot` 同时落库 |
| I4 | 快照组 | `product_spec_snapshot`+`product_type_snapshot`+`config_snapshot` 必填；`member_discount_snapshot`（member>0 时）；`config_pricing_snapshot`（upgrade 必填含 `meta.kind`，renew 补写） |
| I5 | 绑定 | `invoice.order_id` 单向绑定订单；充值/返利/扣款/退款无订单属设计；退款红字账单以 `origin_invoice_id` 追溯 |
| I6 | type 值域封闭 | `new/renew/upgrade/recharge/deduction/referral_credit/refund/manual`；`normal` 仅作读取兼容（`InvoiceType::normalize`），**禁止新写入** |
| I7 | trace 贯穿 | `invoice.trace_id` 与 `order.trace_id` 同源同值 |

### invoices 字段契约（按 type 分组）

| 字段组 | new / renew / upgrade | recharge / referral_credit / deduction | refund |
| --- | --- | --- | --- |
| 金额组 | I1/I2 必填；`paid_amount`/`paid_at` 按状态 | `amount`/`paid_amount`/`paid_at` 必填；折扣恒 0 | `amount`/`paid_amount` 为负数红字 |
| 绑定组 | `order_id` 必填 | 无订单（设计） | `origin_invoice_id` |
| 商品组 | `product_id` 必填；renew/upgrade 另有 `service_id` | 无 | 无 |
| 快照组 | I4 | `config_snapshot` 仅备注 | `config_snapshot` 仅备注 |

### orders 字段契约（new / renew / upgrade）

identity（order_no/user_id/type/status/projection_type）+ 金额组（I1/I2/paid_amount/paid_at）+ 引用组（coupon 三件套、service_id、product_id）+ 快照组（I4）+ `trace_id`/`billing_cycle`/`quantity`/`operator`。影子订单与补录订单同契约。

### invoice_items 投影契约（决策点 D1）

投影必须可重放（现状即全删全插）。目标行结构（**推荐 A**）：

- 商品行：`unit_price = 目录价/quantity`、`line_amount = 目录价`；
- 折扣行：`优惠券减免 -discount`（有则）、`会员折扣 -member`（有则）；
- 行合计 = `amount`；`meta_json` 记录折扣分列来源。

备选 B（改动最小）：保持单商品行结构，仅把 `unit_price` 基数补上 member（单价=会员折后价），不加折扣行——明细仍看不到会员折扣行，不推荐。

### config_snapshot 语义（决策点 D2）

**推荐：按 type 约定 + 补齐，不迁移列**。`config_snapshot` = 类型私有载荷（new：商品配置；renew：续费元数据 + 履约状态——`RENEW_FULFILLMENT_STATUS_KEY` 在此，不可迁走；upgrade：升级配置）；`config_pricing_snapshot` = 计价快照（含 `meta.kind`），续费路径补写。约定写入 DATABASE.md。

### 1. 订单↔账单状态/金额错位（预期：本地 28 单）

```sql
-- 已付订单但账单未入账（或反向）的配对
SELECT o.id AS order_id, o.order_no, o.status AS order_status, o.paid_amount AS order_paid,
       i.id AS invoice_id, i.invoice_no, i.status AS invoice_status, i.paid_amount AS invoice_paid
FROM orders o
LEFT JOIN invoices i ON i.order_id = o.id
WHERE o.status IN (1, 5)   -- PAID / REFUNDED，按实库 OrderStatus 值域调整
  AND (
        i.id IS NULL
        OR i.status <> o.status
        OR ABS(COALESCE(i.paid_amount, 0) - COALESCE(o.paid_amount, 0)) > 0.001
      );
```

### 2. 孤儿订单（预期：本地 9 单，订单 id 9-52）

```sql
SELECT o.id, o.order_no, o.user_id, o.status, o.created_at
FROM orders o
LEFT JOIN invoices i ON i.order_id = o.id
WHERE i.id IS NULL;
```

### 3. 无 service_id 的已支付续费账单（预期：本地 446 张，其中 173 已支付）

```sql
SELECT COUNT(*) AS total,
       SUM(CASE WHEN i.status = 1 THEN 1 ELSE 0 END) AS paid_count,
       SUM(CASE WHEN i.status = 1 THEN i.paid_amount ELSE 0 END) AS paid_amount_sum
FROM invoices i
WHERE i.type = 'renew'
  AND (i.service_id IS NULL OR i.service_id = 0);
```

> 三类核对 SQL 均只读。订正动作（如 renew 账单回填 service_id）须另行出迁移方案并双库演练，不在本方案范围内。

## 风险与回滚

- **明细重放**：全删全插幂等，可重复执行；先 idc_test 验证行数守恒（商品行+折扣行 = 原商品行数×(1+折扣行数)）再上 idc。
- **type 订正**：读取侧已有 `InvoiceType::normalize` 兼容，回滚安全；需确认无第三方/导出直读 `type='normal'`。
- **kind 过滤**：行为变化（不再互取消）；上线前确认无运营流程依赖「建新单自动撤旧单」。
- **写入收敛**：全部为新增/修正字段写入，不改既有读取契约；契约测试防回归。
