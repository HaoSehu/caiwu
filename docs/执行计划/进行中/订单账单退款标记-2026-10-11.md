# 订单/账单退款标记 · 2026-10-11

## 背景

管理端需要「标记已退款」能力（订单/账单联动，支持部分退款）。管理端**动资金**的退款已于 2026-10-03 主动下线（`1b000b23`）；本计划新增的是**纯标记**通道：只登记「线下已退款/对账修复」的退款事实，不动任何资金。

**用户裁决（2026-10-11）**：纯标记不动钱；复用 `refunds` 表 + `refund_amount` 累加；新增 `finance.refund` 单权限码；收入统计按净额（实收 − 累计已完成退款）计入。

**资金红线（本计划零触碰）**：不改余额、不写台账、不生成红字账单、不改 Payment、不回退推广奖励——`AccountService` / `FinanceLedgerWriter` / `FinanceDocumentService` 三唯一写口零调用。

**设计已审核，4 处易错点均已读码核实**：

1. `orders` 表无 `invoice_id` 列（关联为 `invoices.order_id → orders.id`），订单侧入口须走 `$order->invoice`。
2. `DashboardService` 收入口径共三处（`salesIncomeInvoices` 被 `buildOverviewStats`/`buildMonthlyRevenue` 复用），须同批改造。
3. `FinanceDocumentService::createBalanceRefundDocuments` 部分退款也生成红字账单——净额扣减必须同时排除 `type=refund`，否则重复扣减。
4. `TradeLifecycleService::markInvoiceRefunded` 被可重复执行的对账命令调用，**保持覆盖写不改**；累加语义走新方法 `markInvoiceRefundMarked`。

**关联**：[财务单据生成规则](../../参考资料/后端/财务单据生成规则.md)、[BACKEND.md](../../BACKEND.md)、[财务B2能力设计（本地材料）](../../_local/收敛决策材料-2026-10-10/财务B2能力设计-部分核销与红字冲抵.md)（§四第 1 条红字冲抵待裁决项由本计划 §统计口径给出结论）、[后端审查修复批次](后端审查修复批次-2026-10-10.md)（B0「refund_method 恒为 balance」将被本计划扩展为 `balance | manual_mark`）。

**非目标**：不复活在线真退款；不做原路退款；不动 B2 部分核销批次 3（退款 payment 级口径）；不自动提交 git。

| 日期 | 决策 | 依据 |
| --- | --- | --- |
| 2026-10-11 | 纯标记不动钱（非真退款/非双模式） | 用户卡片裁决；2026-10-03 已下线动资金退款 |
| 2026-10-11 | 复用 `refunds` 表逐笔累加，不改 `markInvoiceRefunded`（覆盖写） | 对账命令可重复执行，改累加会无限膨胀；新增 `markInvoiceRefundMarked` |
| 2026-10-11 | 状态值域不变，新增 `RefundStatus` 派生态 | `6=部分退款` 历史上已移除；`PARTIAL_PAID=2` 已占展示槽位；20+ 处 `where(status, PAID)` 零改动 |
| 2026-10-11 | 统计按净额且排除红字账单 | 红字在部分真退款时也生成，仅净额会 `X-2Y` 重复扣减；顺带修复全额真退款计 `-X` 的既有缺陷 |
| 2026-10-11 | 幂等不用短窗内容指纹 | 金额上限 + `invoice_id` 已是精确硬约束；指纹会误伤合法分次退款 |
| 2026-10-11 | 推广奖励不自动回退，仅留痕 | 回退即扣余额（资金写入，违反纯标记裁决）；返利处理属运营决策 |
| 2026-10-11 | 权限单码 `finance.refund`，默认不下发 | 资金域敏感操作对齐 `finance.manual_reversal` 先例 |
| 2026-10-11 | 移动端列表菜单**不加**逐行退款标记项 | 列表不下发 `can_mark_refund`（N+1 取舍），移动端统一走「详情 → 抽屉工具条」入口，判定源唯一 |
| 2026-10-11 | 退款明细列表挂在账单详情 `refund_records` 字段 | 写接口不随次数线性增长；订单侧经 HasOne 投影透出退款列 |
| 2026-10-11 | `DashboardService::salesIncomeInvoices` 不加 `select('invoices.*')` | join 后 `invoices.id` 与 GROUP BY 不函数依赖（ONLY_FULL_GROUP_BY 报 1055）；分组查询由调用方 selectRaw 自带列覆盖 |
| 2026-10-11 | 退款到余额复用 `finance.refund` 权限，不新增权限码 | 同一入口两种方式，一次授权即可；默认不下发任何内置角色，风险面不变 |
| 2026-10-11 | 两通道**一单只选一种、互斥**（用户裁决） | 混用会让两种资金语义叠加、对账无法解释；真退款的覆盖写投影与标记的累加投影会在混用时互相污染 |
| 2026-10-11 | 余额退款**允许部分提交**（与既有真退款语义一致） | 审查修正：初版曾设计为强制整笔，但既有 `refundInvoiceToBalance` 本就支持部分退款（仅全额时收口 Payment/账单/订单），强制整笔会造成「前端拒绝、接口允许」的不一致；部分退款后账单显示「部分退款」标签、状态保持已支付是正确表现 |
