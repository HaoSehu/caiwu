# 上游驱动插件化立项（hosting_panel_api）-2026-10-12

## 背景

2026-10-11 调度体系重构时，4 个上游类任务迁入 `app/Services/Upstream/Integration/` 模块级归属；用户裁决彻底插件化"单独立项"。本文档为立项设计。

## 调研结论（实库与代码锚点）

- **ProviderRegistry 驱动来源**：`UpstreamServiceProvider` 以 `PluginRuntimeRegistry::resolveEntries(UPSTREAM, UpstreamDriver::class)` 构建注册表——**驱动只来自启用的 UPSTREAM 插件**（经 `PluginUpstreamDriver` 适配器包装）。不存在"系统内置驱动直注"通道。
- **hosting_panel_api 现状**：`ProviderKey::HOSTING_PANEL_API` 已定义；`app/Services/Upstream/Drivers/HostingPanelApi/HostingPanelApiTransport.php`（1300+ 行，implements ProvidesConsoleAccess/Catalog/Network/Runtime/Security/Provisioning/Renewal/ScheduledAuthRefresh/StatusSync 全能力）存在，但**没有 UpstreamDriver 实现、没有对应插件**。主库 `integration_plugins` upstream 域仅 `kanghostx`、`zjmf_finance` 启用。
- **存量绑定**：主库 `supplier_plugin_bindings` 仅 2 条（zjmf_finance_api）；`product_upstream_bindings` distinct 仅 zjmf_finance_api。**hosting_panel_api 零绑定**——即 `refresh-hosting-panel-auth` 任务当前实际空转（resolveForSupplier 后 registry.find 无驱动，require 能力即失败/无匹配），迁移无存量数据风险。
- **依赖封闭性**：`UpstreamJwtSessionManager` 仅被 Transport 自用；`web_session_credential_parsers` tag 当前无任何插件注册者（实施时确认 parser 是否随迁）。
- **插件样板**：`plugins/servers/kanghostx/logic/KangHostx.php` extends `AbstractUpstreamServerPlugin`（app/Services/Upstream/Support/，抽象 key/label/capabilities/supplierFormSchema），config.php 声明 `provider_key`、`capabilities`、`scheduled_tasks`、`schedule_hooks`。

## 实施方案（按实施调研修正后的最终形态）

1. **新建插件** `plugins/servers/hosting_panel/`（与 kanghostx/zjmf_finance 同构）：
   - `config.php`：manifest（domain=upstream、slug=hosting_panel、key=hosting_panel_api、capabilities 9 个 Provides* 接口、extra.scheduled_tasks 声明认证刷新任务）+ config（provider_key readonly）
   - `HostingPanelPlugin.php`：入口类（extends Logic\HostingPanel，同 ZjmfFinancePlugin 模式）
   - `logic/HostingPanel.php`：extends `AbstractUpstreamServerPlugin` implements UpstreamDriver/ProvidesSupplierFormSchema，构造器注入系统侧 Transport，**override capabilityCarrier() 把能力解析委托给 Transport**（基类 supports/resolve 自动工作）
   - `lib/HostingPanelAuthRefreshTask.php`：认证刷新任务类（从上游集成模块迁入，key/频率/超时不变）
2. **共享传输层保留系统侧（实施调研修正）**：`HostingPanelApiTransport`、`UpstreamJwtSessionManager`、`WebSessionCookieParser` 均被 zjmf_finance 插件与系统服务共享（ZjmfAuthManager 继承 SessionManager 并注入 Transport），不随迁——插件只做驱动注册壳，传输实现留在 `app/Services/Upstream/`。
3. **系统侧清理**：`app/Services/Upstream/Integration/HostingPanelAuthRefreshTask.php` 删除、`UpstreamScheduledTaskProvider` 移除该项；`ProviderKey::HOSTING_PANEL_API` 与 Transport singleton 保留（key 字符串是绑定契约，singleton 服务 zjmf 共享）。
4. **安装**：迁移内调用 `PluginInstaller::install('upstream','hosting_panel')` + enable（manifest_hash/清单校验全自动）；down 仅禁用（回滚目标=驱动未注册的历史现状）。

## 决策日志

- 2026-10-12：立项依据"零绑定、纯增量、依赖封闭"——迁移无存量数据风险；transport 能力全覆盖，插件化后与 kanghostx/zjmf_finance 同构。
- 2026-10-12：任务归属裁决为 A（插件 scheduled_tasks 声明，与 ZJMF 认证刷新任务同构）。
- 2026-10-12：**实施中发现方案修正**——`HostingPanelApiTransport` 被 zjmf_finance 插件深度共享（ZjmfAuthManager extends UpstreamJwtSessionManager 且注入 Transport；ZjmfFinanceAdapter/ZjmfFinanceTransport 注入 Transport），Transport 属共享传输基础设施，**保留系统侧**（`app/Services/Upstream/Drivers/`），插件仅做驱动注册壳（logic 类 capabilityCarrier 委托 Transport）。同理 UpstreamJwtSessionManager、WebSessionCookieParser（被 ServiceDetailService/UpstreamBindingWriter/zjmf 共享）保留系统侧。
- 2026-10-12：安装走 `PluginInstaller::install`（迁移内调用，manifest_hash/校验全自动），down 仅禁用（回滚目标=驱动未注册的历史现状）。
- 2026-10-12：**调度重构文件曾在 11 模块大合并中被回滚**（CoreScheduledTaskProvider 恢复旧版含 7 个已删任务，导致安装时任务 key 冲突），已重新应用重构并完成安装，端到端验收通过（驱动注册 9 能力 / 任务来自插件 / 总任务 17 = Core 11 + 上游集成 3 + 插件 3）。

## 范围与验收

- 插件启用后 `ProviderRegistry` 可解析 hosting_panel_api 驱动；`refresh-hosting-panel-auth` 任务执行 matched/refreshed 统计真实（对启用了 ScheduledAuthRefresh 能力的 host panel 供应商生效）。
- 未启用插件时：全系统无 host panel 驱动解析路径，任务空转无报错；UPSTREAM 相关测试（SelfSyncedProviderKeysTest 等）保持通过。
- 验证链：PHPStan 0 错 / Pint / 相关 PHPUnit / 四前端构建不受影响（纯后端插件域）。

## 风险与回滚

- Transport 体量大（1300+ 行）保留系统侧不迁移，规避了命名空间迁移与 zjmf 依赖破坏的主风险。
- 回滚：禁用插件即回到"驱动未注册"现状（与立项前等价）；安装迁移 down 为禁用动作。
