### 1.2 URL 生成方式（远程外链能否透传的关键依据）

`backend/app/Support/UploadUrl.php:13-39` 的 `resolve(?string $path): ?string` 是唯一 URL 生成入口，逻辑是：

1. 空串返回 `null`；
2. 以 `http://` / `https://` 开头 → 取 `parse_url(PHP_URL_PATH)`；仅当 path 命中 `isManagedUploadPath()`（`:48-53`，只认 `/media/` 与 `/uploads/`）**且** `uploadedFileExists()` 命中本地文件时，才重建为 `PublicUrl::api(path)`；否则**原样返回入参**；
3. 非 http(s) 的相对路径：不命中托管前缀原样返回，命中则 `PublicUrl::api()`。

调用点有两处：`MediaFileService::toMediaArray()`（`:334`）与 `AdminMediaFileResource::toArray()`（`backend/app/Http/Resources/Admin/V2/AdminMediaFileResource.php:26`，写法是 `UploadUrl::resolve($path) ?: $this->field('url')`）。

由此得到两条硬结论：

- **远程外链可以零改动透传**：只要记录的 `path` 本身就是 `http(s)://<非 /media/、/uploads/ 前缀>` 的完整 URL，`resolve()` 就原样返回它，预览、复制 URL 全部可用。
- **`url` 列在正常行上不会被用到**：因为 `resolve()` 对任何非空相对路径都返回非 null，`?: $this->field('url')` 的右支永远走不到。要让远程行展示外链，只能让 `path` 承载 URL，或改 `AdminMediaFileResource`（后者属核心改动，见 2.6）。

### 1.4 直接影响方案的判断

1. **addons 域没有宿主 adapter，但这不阻碍本方案**：`PluginRuntimeRegistry::execute()` 是**独立于 adapter 的动作通道**，只按 `domain + slug/key` 找已启用插件并调用入口 `execute()`。因此媒体库宿主服务可以直接 `execute('addons', 'ftp', 'storage.put', ...)`，不需要新增平台 adapter、不需要 `resolveEntries()`。这一点是本方案能「零新增平台代码即可调用插件」的唯一依据。
2. **不能只靠 `driver_binding` 表达「当前生效的存储驱动」**：`syncDriverBinding()` 的 identity 不含 `plugin_id`，四个插件若声明同一个 `binding_key` 会互相覆盖；而 addons 允许多插件同时启用，无法用「唯一启用者」反推。故驱动选择必须显式落在 `settings` 表（见 2.1）。
3. **文件内容不能走 payload**：`execute()` 会把 payload 写进 `integration_plugin_runtime_logs`（16KB 截断，且日志不脱敏）。因此插件接口只传**本地绝对路径 + 对象键**，由插件在同一进程同一文件系统内自行读写文件。
4. **官方能力边界**：四个外部存储的接口形态见第 3 节引用的官方文档；七牛、COS、OSS 的签名算法、Host 形态、Delete 接口均已核对；FTP 的「外链访问」在协议层不存在，必须由自定义 HTTP 域名补足（见 3.1 与待确认 P-01）。

## 2. 本地 / 远程共存与双向迁移方案

### 2.1 存储选择机制

三层选择，优先级从高到低：

1. **单文件级**：上传时由请求可选传入 `driver`（白名单为当前已安装且已启用的存储插件 slug，外加 `local`）。命中即以该驱动落盘并写 `disk` 列。
2. **分组策略级**：`settings` 表新增 `group_key='media'` 的 `policy_json`（`Setting::setValue()`，与 `MediaLibraryOrganizer.php:313` 的做法一致），形如 `{"default":"local","groups":{"hero-videos":"qiniu"}}`。上传未指定 `driver` 时按分组策略解析。
3. **全局默认级**：`settings` 的 `group_key='media'`、`item_key='storage_driver'`，取值 `local` 或某个插件 slug。分组策略缺省时回落到它。

解析结果统一由新增的 `MediaStorageResolver`（`backend/app/Services/Content/Storage/`）给出，并且：

- 解析不到、值为空、或对应插件未启用 → **一律回落 `local`**，并记一条 warning 日志。这条兜底保证「远程链路不可用不影响媒体库可用」。
- 远程驱动必须同时满足「`integration_plugins` 中该 slug 已启用」+「`config.php` 声明的必填项已齐」，否则视为不可用。

### 2.2 文件归属记录

`media_files` 走**新迁移**新增两列（`Schema::hasColumn` 守卫、中文 `COMMENT`，符合 `docs/参考资料/数据库/数据库升级规范.md:83-90`）：

| 列 | 类型 | 默认 | 注释 |
| --- | --- | --- | --- |
| `disk` | `varchar(24)` | `'local'` | 存储驱动标识：`local` 或插件 slug（`ftp`/`qiniu`/`tencent_cos`/`aliyun_oss`） |
| `object_key` | `varchar(500)` nullable | `NULL` | 远程对象键，如 `media/img_20261028_...jpg`；本地行为 `NULL` |

并加索引 `media_files_disk_index`（是否可加作为实施时确认项，登记在 P-08）。

**字段语义保持**：

- 本地行：`disk='local'`、`path='/media/xxx.jpg'`、`object_key=NULL`、`url` 仍是 `UploadUrl::resolve(path)` 的快照。**与今天完全一致**。
- 远程行：`disk='ftp'`、`path` 与 `url` **同值存完整外链**（`https://cdn.example.com/media/xxx.jpg`）、`object_key='media/xxx.jpg'`。`path` 存 URL 是为了让 `UploadUrl::resolve()` 原样透传（1.2 的结论），代价与备选见 2.6。

`checkReferences()`（`MediaFileService.php:193-228`）用 `path` 或 `url` 做 LIKE，远程行两者同值仍可命中 `settings`/`content_articles` 里残留的旧本地路径——这正是迁移时要做引用替换的原因（2.4）。

### 2.3 读写路径的最小接线

**唯一触及媒体库核心的改动点**（其余全部是新增文件）：

| 位置 | 改动 | 为什么必要 |
| --- | --- | --- |
| `MediaFileService::upload()` 开头 | 调 `MediaStorageResolver::resolve($group, $requestedDriver)`；返回 `local` 时**原样执行现有全部逻辑**（含 `guardDiskSpace`、`getimagesize`、`MediaFile::create`），一行不改；返回远程时改走 `RemoteMediaStorage::put()` | 共存必须在上传入口有唯一分支点；把分支放在方法最前，本地路径的语句顺序与行为逐字不变 |
| `MediaFileService::delete()` 开头 | 读 `$mediaFile->disk`；`local` 时原样执行现有 `resolvePublicUploadPath`+`@unlink`+`delete()`；远程时先 `storage.delete` 再删行 | 删除必须做到「远程对象同步删除」（验收要求），且失败要可恢复而不是先删行 |

明确不做的事：

- 不改 `UploadUrl`（远程外链靠 1.2 的透传机制）。
- 不改 `AdminMediaFileResource`、`list()`、`reindexMediaDirectory()`、`listHeroVideos()`、`checkReferences()`。
- 不改 `frontend-admin-v3` 现有交互；新增入口（驱动选择、迁移面板）以增量方式加。
- 不引入 `league/flysystem-*`、`aws/aws-sdk-php`：四个插件全部用 `ext-ftp` + Laravel `Http`（guzzle 已是传递依赖）自己实现最小客户端。

### 2.4 双向迁移

迁移是**平台侧能力**（`backend/app/Services/Content/Storage/MediaMigrationService.php` + 一个队列 Job），不是插件能力；插件只提供 `storage.put/get/delete` 三个原子动作（另加 `storage.url` 供外链现算），保证迁移不依赖具体厂商。

**触发方式**：管理端媒体库页新增「迁移」入口，两个动作：

- `POST /v2/admin/media-migrations`（`direction=to_remote|to_local`，`driver`，`scope`，`delete_source`）
- `GET /v2/admin/media-migrations/{id}`（进度轮询）

权限沿用 `content.manage`；路由作为新增条目写进 `backend/routes/v2-admin.php`，与现有 `/media-files` 同组（不改既有行）。

**范围选择**（三选一，互斥）：

1. `all`：全部满足条件的行；
2. `ids`：勾选的文件（前端表格多选）；
3. `filter`：复用现有列表筛选语义（`group` / `keyword` / `type`），服务端用与 `list()` 同一套 `where` 条件取行，避免前端自拼条件与列表口径漂移。

**执行流程（本地 → 远程）**，逐文件、可断点续跑：

1. 取行 → 校验 `disk='local'` 且 `resolvePublicUploadPath()` 命中真实文件，否则计入 `skipped`；
2. `execute('addons', $driver, 'storage.put', ['local_path'=>绝对路径, 'object_key'=>$key, 'mime_type'=>...])`；
3. 从返回 `data.url` 取外链，更新行：`disk`、`object_key`、`path=$url`、`url=$url`；
4. **引用替换**：把 `oldPath → newUrl` 组成映射，按 `MediaLibraryOrganizer.php:291-318`（settings）与 `:323-352`（content_articles）已验证的两处 `str_replace` 做法替换；
5. `delete_source=true` 时删除本地文件（仍走 `resolvePublicUploadPath()` 的前缀校验，不直接 `unlink` 拼路径）；
6. 单个文件失败不回滚已完成项，记入 `failures[]`（含 `media_file_id`、`stage`、`message`），并由 Job 继续下一项。

**执行流程（远程 → 本地）**，方向对称：

1. 取行 → 校验 `disk != 'local'` 且 `object_key` 非空；
2. `execute('addons', $driver, 'storage.get', ['object_key'=>$key, 'target_dir'=>public_path('media')])`，插件把对象下载为临时文件并返回临时路径；
3. 平台侧接管落盘：重新生成文件名（沿用 `:91` 的 `sprintf` 规则）、`guardDiskSpace()`、`rename` 到 `public/media`；
4. 更新行：`disk='local'`、`object_key=NULL`、`path='/media/{filename}'`、`url=UploadUrl::resolve(path)`；
5. 引用替换为新的本地 URL；
6. `delete_source=true` 时调 `storage.delete` 删除远程对象。

**进度与失败处理**：复用「备份任务」已验证的形态——批次 Job（`tries=1`、`timeout` 显式声明）在 `default` 业务队列执行（`backend/config/queue.php` 的 `caiwu_business_queues` 含 `default`），进度写缓存键 `media:migration:{id}`（`total/done/failed/skipped/status/failures`，TTL 24h），前端轮询状态接口。**不新建业务日志表**（插件与平台都不应以自建表替代运行日志）。失败项支持「只重试失败项」（`ids` 范围即失败清单）。

### 2.5 迁移后 URL 与记录一致性

| 风险 | 处理 |
| --- | --- |
| 引用方仍指向本地 URL，本地文件已删 | 迁移步骤 4 的 `str_replace` 覆盖 `settings.item_value` 与 `content_articles.cover_image`；这两个表是 `checkReferences()` 认的全部引用来源（`:193-228`），口径一致 |
| 同一 URL 出现在其它未覆盖字段 | 迁移前对每行先跑 `checkReferences()` 的等价查询，把「非上述两表」的引用计入 `failures` 并要求人工裁决，不静默改库 |
| `path` 与 `url` 不一致 | 远程行由服务写入时**强制同值**；提供只读校验命令（`media:storage-audit`，仅读、只报告）对比 `disk='local'` 行的 `path/url` 与 `disk!='local'` 行的 `path===url` 不变式 |
| 迁移中途站点正在用旧 URL | 顺序固定为「先上传→再改库→再删本地」，任何时刻至少一处可用；`delete_source` 默认 `false`，需显式打开 |
| 缓存导致首页视频仍指旧路径 | 迁移批次结束时调 `Cache::forget('media:hero-videos:list')`（与 `bustHeroVideoCache()` 同键） |
| 远程对象被删除但库行仍在 | 删除时「先远程、后库行」；远程返回 404/612 类不存在按成功处理 |

### 2.6 备选方案与取舍

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 远程行 `path` 存完整外链（本方案） | 完全不动 `UploadUrl`/`AdminMediaFileResource`/前端；预览与复制 URL 天然可用 | `path` 列语义扩宽（注释需同步更新）；「复制路径」按钮会复制 URL | **采用** |
| 改 `AdminMediaFileResource` 让 `url` 优先取列值 | `path` 语义保持纯净 | 触及核心 Resource，且 `toMediaArray()` 是第二处同样写法，需同步改，回归面更大 | 记为后续可选重构，本次不做 |
| 引入 Flysystem + S3 适配器统一四家 | 代码量小、成熟 | 需要新增 3 个 composer 依赖（仓库当前零存储依赖），AWS SDK 体积大，FTP 适配器对被动模式/编码支持需另配 | 不采用：与「最小范围修改」冲突 |
| 远程文件先落地本地再异步上传（双写） | 上传接口行为与今天完全一致、失败不阻塞编辑 | 本地磁盘仍被占用，与「部分文件只存远程」的目标矛盾；需要第二套后台任务 | 不采用，仅作为 FTP 大文件超时的兜底提案（待确认 P-05） |

## 3. 四个插件的设计方案

四个插件结构、命名、动作名、配置字段顺序、错误返回形态**完全同构**，只有「连接参数」「签名方式」「外链拼接」三处不同。

### 3.0 共同契约（四插件一致，逐插件不再重复）

**目录与命名空间**

```text
backend/plugins/addons/{slug}/
├── {Name}Plugin.php        入口类，extends Logic\{Name}
├── config.php              清单 + 配置 schema
├── lib/
│   ├── {Name}Client.php    最小 HTTP/FTP 客户端（唯一做外部 IO 的类）
│   ├── {Name}Signer.php    签名/路径拼接纯函数（可单测，不发网络请求）
│   └── {Name}Support.php   对象键校验、外链拼接、错误归一
├── logic/
│   └── {Name}.php          实现 execute()，match 分发动作
└── tests/
    └── {Name}ClientTest.php
```

命名空间前缀 `Caiwu\Plugins\Addons\{Name}\*`，入口类位于根部——满足 `PluginFileLoader::assertNoClassConflicts()` 的前缀约束。

**动作清单（四插件同名同义）**

| action | payload | 返回 `data` | 用途 |
| --- | --- | --- | --- |
| `storage.test` | 无 | `{ok, endpoint, bucket/root, writable, latency_ms}` | 安装后配置校验与「测试连接」按钮；也是健康检查。语义注记（2026-11-01 更新）：FTP 与七牛均为真实写探针（FTP 建删临时目录；七牛上传 16B 探针对象后删除）；COS/OSS 为「凭证有效 + 桶可达」即 `writable=true`（收到 403 视为链路通但 `writable=false`），未实测写入；调用方不得把 `writable` 当作「上传必成功」的保证 |
| `storage.put` | `{local_path, object_key, mime_type, content_length}` | `{object_key, url, size, etag?}` | 上传，返回外链 |
| `storage.get` | `{object_key, target_dir}` | `{temp_path, size}` | 下载到临时文件（迁回本地用） |
| `storage.delete` | `{object_key}` | `{deleted: bool, missing: bool}` | 删除；对象不存在按成功（`missing=true`） |
| `storage.exists` | `{object_key}` | `{exists: bool}` | 迁移一致性核对（可选实现，缺失时平台按「未知」处理） |
| `storage.url` | `{object_key}` | `{object_key, url}` | 按对象键与当前配置现算外链（换域名/协议后订正存量行用），不重传文件、不发网络请求；同一键与配置下结果必须与 `storage.put` 的 `url` 全等 |

**统一约束（写进每个插件）**

- 入口类必须提供 `execute(array $request): array`，并额外提供 `healthCheck(): array`（被 `PluginRuntimeRegistry::healthCheck()` 调用，返回 `healthy/message/details`）。
- 所有失败返回 `['success'=>false,'message'=>'中文可读原因','data'=>['code'=>'...']]`，**不抛裸异常**；网络超时、鉴权失败、桶不存在、对象键非法四类必须有明确中文消息。
- `local_path` 必须由平台侧构造；插件侧再校验一次：`realpath` 必须位于 `public_path('media')` 或 `storage_path('app/tmp')` 之下，且 `is_file()`，否则直接拒绝（防越权读盘）。
- `object_key` 校验：非空、≤500、不以 `/` 开头、段内无 `..`、字符集限制在 `[A-Za-z0-9._/-]`。
- 不在 payload 或日志里出现任何密钥；密钥一律从 `$request['config']` 取（`PluginConfigRepository::resolvedConfig()` 已解密）。
- `info.capabilities` 统一声明 `['media.storage','media.storage.migrate']`（当前平台不消费该字段，只作清单自描述，与 README 说明一致）。
- 每个插件 `info.extra.requires = ['core' => '>=1.0.0']`；**不声明** `schedule_hooks`/`scheduled_tasks`/`admin_entry`/`client_entry`/`public_entry`（后者已是死扩展点）。
- 每个插件 `info.extra.driver_binding` **不声明**：addons 多插件同时启用，同一 `binding_key` 会互相覆盖（1.4 第 2 条），驱动选择改由 `settings` 承载。

**上传实现通则**：一律「读本地文件 → 计算签名 → 发一次 HTTP/FTP 请求 → 从响应解析 etag/status → 拼外链」。大文件不做分片（≤100MB，与 `StoreMediaFileRequest` 的 `max:102400` 对齐）；超过阈值的行为见待确认 P-05。

### 3.1 FTP 插件（`backend/plugins/addons/ftp/`）

**元信息与安装/启用**

与 3.0 共同契约完全一致，仅替换 slug/key/name/entry；下列 4 个插件同样只写差异项。

- `info`：`domain='addons'`、`slug='ftp'`、`key='ftp'`、`name='媒体库 FTP 存储'`、`version='1.0.0'`、`entry=FtpPlugin::class`、`capabilities=['media.storage','media.storage.migrate']`、`extra=['requires'=>['core'=>'>=1.0.0']]`。
- 安装：把目录放入 `backend/plugins/addons/` → 管理端插件页 `POST /integration-plugins`（`domain=addons`、`slug=ftp`）→ 填配置 → `PATCH /integration-plugins/{id}/status` 启用。启用后媒体库的驱动下拉才会出现「FTP」。

**连接参数（`config` schema，顺序固定）**

| key | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| `ftp_notice` | `notice`（theme=warning） | — | 提示「FTP 无 HTTP 外链能力，必须同时配置可访问的 HTTP 域名」 |
| `host` | `text` | 是 | 非空；不含协议前缀与路径；≤190 字符 |
| `port` | `number` | 是 | 1–65535，默认 21 |
| `username` | `text` | 是 | 非空，≤100 |
| `password` | `password` + `secret=true` | 是 | 非空；不回显，空提交保留旧值 |
| `root_dir` | `text` | 否 | 远端根目录，默认 `/media`；必须以 `/` 开头，不得含 `..` |
| `passive` | `switch` | 是 | 默认开（被动模式）；关闭仅在已确认网络拓扑时使用 |
| `use_ssl` | `switch` | 是 | 默认关；开启时走 `ftp_ssl_connect`，证书校验行为见 P-02 |
| `timeout` | `number` | 是 | 5–120 秒，默认 30 |
| `public_domain` | `url` | 是 | 必须 `http(s)://` 开头、无查询串、无结尾斜杠；用于拼外链（P-01） |
| `url_prefix` | `text` | 否 | 外链相对路径前缀，默认 `/media`；与 `root_dir` 不必相同（站点常做目录映射） |
| `object_prefix` | `text` | 否 | 对象键前缀，默认 `media`；不得以 `/` 结尾 |

校验分两层：字段级（`required`、类型、placeholder）由平台 `assertRequiredFields()` 与前端 schema 渲染承担；语义级（`public_domain` 是否可访问、`root_dir` 是否存在、能否 `STOR`）由 `storage.test` 动作完成，失败返回中文原因供管理员修正。

**上传（`storage.put`）**

1. 拼远端路径 `{root_dir}/{object_key}`，逐级 `ftp_mkdir`（已存在忽略）；
2. `ftp_put($conn, $remotePath, $localPath, FTP_BINARY)`；
3. 成功后 `ftp_size()` 与本地 `filesize()` 比对，不等则判失败并尝试删除半个文件；
4. 返回 `data.url`。

**读取/预览**：本插件**不代理读取**。预览完全依赖 `public_domain + url_prefix + object_key` 生成的 HTTP 外链。若该域名不可访问，预览与迁移校验都会失败——这是 P-01 的核心风险。

**删除（`storage.delete`）**：`ftp_delete()`；返回 `550`/文件不存在时按 `missing=true` 成功处理；连接级失败则整体失败，让平台保留库行（可重试）。

**外链生成**：`rtrim(public_domain,'/') . url_prefix . '/' . object_key`，再做一次分段 `rawurlencode`（只编码路径段，保留 `/`）。

**已验证依据**：本机 `php -m` 实测含 `ftp`/`curl`/`fileinfo`/`openssl`/`mbstring`（PHP 8.3.8 CLI），`ext-ftp` 可直接使用；协议细节为标准 FTP，无第三方文档强依赖。生产环境部署前仍须在生产 PHP 用 `php -m` 复核一次（见第 7 节「部署」行）。

### 3.2 七牛云插件（`backend/plugins/addons/qiniu/`）

**元信息与安装/启用**：同 3.0 通则，`slug='qiniu'`、`key='qiniu'`、`name='媒体库七牛云存储'`、`entry=QiniuPlugin::class`。

**连接参数**

| key | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| `qiniu_notice` | `notice` | — | 提示 AccessKey/SecretKey 需具备该空间的上传与删除权限 |
| `access_key` | `password` + `secret=true` | 是 | 非空，≤100 |
| `secret_key` | `password` + `secret=true` | 是 | 非空，≤100 |
| `bucket` | `text` | 是 | 非空，≤100；不接受含 `:` |
| `region` | `select` | 是 | 取值见下方区域表 |
| `upload_host` | `text` | 否 | 默认由 `region` 推导；允许覆盖为加速域名 |
| `api_host` | `text` | 否 | 默认 `https://rs.qiniuapi.com`（对象管理，删除用）。支持带路径前缀的反代形态（如 `https://rs.example.com/qiniu`）：签名路径自动拼接 `parse_url` 提取的 path 段，与请求 URL 保持同源（2026-11-01 修复并有签名重算测试防回归） |
| `public_domain` | `url` | 是 | 空间绑定的访问域名；无协议时自动补 `https://`（P-03） |
| `object_prefix` | `text` | 否 | 默认 `media` |
| `private_bucket` | `switch` | 是 | 默认关；开启后外链需下载凭证，**与「外链可打开」验收冲突**，见 P-03 |
| `timeout` | `number` | 是 | 5–120 秒，默认 30 |

区域选项取自官方「存储区域」文档：`z0`（华东-浙江）、`cn-east-2`（华东-浙江2）等；对应上传域名形如 `https://up-z0.qiniup.com`，对象管理 `https://rs-z0.qiniuapi.com`（[存储区域](https://developer.qiniu.com/kodo/1671/region-endpoint-fq)）。默认 `https://up.qiniup.com` 亦为官方入口（[直传文件](https://developer.qiniu.com/kodo/1312/upload)）。

**上传（`storage.put`）**

1. 生成上传凭证：构造上传策略 JSON `{"scope":"<bucket>:<objectKey>","deadline":<now+3600>,"insertOnly":0}` → `urlsafe_base64(putPolicy)` → `HMAC-SHA1(encodedPutPolicy, secret_key)` → 再 `urlsafe_base64` → `token = access_key + ':' + encodedSign + ':' + encodedPutPolicy`（[上传凭证](https://developer.qiniu.com/kodo/1208/upload-token)）；
2. `POST {upload_host}`，`multipart/form-data`，字段 `key`、`token`、`file`（[直传文件](https://developer.qiniu.com/kodo/1312/upload)）；
3. 成功返回 HTTP 200 + JSON，取 `key`/`hash`；非 200 时把响应 `error` 字段作为消息载体返回。

**读取/预览**：不代理读取；外链 = `public_domain + '/' + object_key`。私有空间见 P-03。

**删除（`storage.delete`）**

1. `EncodedEntryURI = urlsafe_base64(bucket + ':' + objectKey)`；
2. 生成管理凭证（`Authorization: Qiniu <token>`，对 Method/Path/query/Host/Content-Type 签名，[管理凭证](https://developer.qiniu.com/kodo/1201/access-token)）；
3. `POST {api_host}/delete/<EncodedEntryURI>`；HTTP 200 成功，`612` 视为「待删除文件不存在」按 `missing=true` 成功（[删除资源](https://developer.qiniu.com/kodo/1257/delete)），`401` 报「管理凭证无效」。

**外链生成**：`rtrim(public_domain,'/') . '/' . object_key`，路径段单独编码。

### 3.3 腾讯云 COS 插件（`backend/plugins/addons/tencent_cos/`）

**元信息与安装/启用**：同上，`slug='tencent_cos'`、`key='tencent_cos'`、`name='媒体库腾讯云 COS 存储'`、`entry=TencentCosPlugin::class`。

**连接参数**

| key | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| `cos_notice` | `notice` | — | 提示需要 `cos:PutObject`/`cos:GetObject`/`cos:DeleteObject` 权限 |
| `secret_id` | `password` + `secret=true` | 是 | 非空，≤100 |
| `secret_key` | `password` + `secret=true` | 是 | 非空，≤100 |
| `bucket` | `text` | 是 | 必须含 APPID 后缀（形如 `examplebucket-1250000000`），正则 `^[a-z0-9-]+-\d{6,}$` |
| `region` | `text` | 是 | 形如 `ap-beijing`，正则 `^[a-z]{2}-[a-z0-9-]+$` |
| `object_prefix` | `text` | 否 | 默认 `media` |
| `public_domain` | `url` | 否 | 自定义 CDN 域名；为空则用桶默认域名（P-04 决定是否可公开读） |
| `timeout` | `number` | 是 | 5–120 秒，默认 30 |

Host 形态由官方文档明确：`<BucketName-APPID>.cos.<Region>.myqcloud.com`（[PUT Object](https://cloud.tencent.com/document/product/436/7749)）。

**上传（`storage.put`）**：`PUT {scheme}://{bucket}.cos.{region}.myqcloud.com/{objectKey}`，签名为官方六步（[请求签名](https://cloud.tencent.com/document/product/436/7778)）：

1. `KeyTime = start;end`（默认 3600 秒有效）；
2. `SignKey = HMAC-SHA1(SecretKey, KeyTime)` → 小写十六进制；
3. `HttpString = method\nUriPathname\nHttpParameters\nHttpHeaders\n`，method 小写、空项保留空行；
4. `StringToSign = "sha1\n" + KeyTime + "\n" + SHA1(HttpString) + "\n"`（末尾带换行；2026-11-01 经官方 PHP SDK cos-php-sdk-v5 src/Signature.php 源码实证修订，此前简写漏了尾换行）；
5. `Signature = HMAC-SHA1(SignKey, StringToSign)`；
6. `Authorization: q-sign-algorithm=sha1&q-ak=...&q-sign-time=...&q-key-time=...&q-header-list=...&q-url-param-list=...&q-signature=...`。

请求头至少签入 `host`、`content-type`、`content-length`；`Content-Type` 取 `media_files.mime_type`。

**读取/预览**：不代理读取；外链 = `public_domain`（若配置）否则 `https://{bucket}.cos.{region}.myqcloud.com/{object_key}`。**对象默认私有**，默认域名直连会 403，必须二选一：桶/CDN 侧开放公有读，或上传时带 `x-cos-acl: public-read`（该头必须参与签名）。选哪条由 P-04 裁决，未裁决前不得声称「外链可打开」。

**删除（`storage.delete`）**：`DELETE /<ObjectKey>` + 同一套签名（[DELETE Object](https://cloud.tencent.com/document/product/436/7743)）；HTTP 204/200 成功，`404` 按 `missing=true` 成功。

**外链生成**：见上；自定义域名优先级高于桶域名。

### 3.4 阿里云 OSS 插件（`backend/plugins/addons/aliyun_oss/`）

**元信息与安装/启用**：同上，`slug='aliyun_oss'`、`key='aliyun_oss'`、`name='媒体库阿里云 OSS 存储'`、`entry=AliyunOssPlugin::class`。

**连接参数**

| key | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| `oss_notice` | `notice` | — | 提示需要 `oss:PutObject`/`oss:GetObject`/`oss:DeleteObject` |
| `access_key_id` | `password` + `secret=true` | 是 | 非空，≤100 |
| `access_key_secret` | `password` + `secret=true` | 是 | 非空，≤100 |
| `bucket` | `text` | 是 | `^[a-z0-9][a-z0-9-]{1,61}[a-z0-9]$` |
| `endpoint` | `text` | 是 | 形如 `oss-cn-hangzhou.aliyuncs.com`；不含协议与 bucket 前缀，正则 `^oss-[a-z0-9-]+\.aliyuncs\.com$` |
| `scheme` | `select`（`https`/`http`） | 是 | 默认 `https` |
| `object_prefix` | `text` | 否 | 默认 `media` |
| `public_domain` | `url` | 否 | 自定义域名/CDN；为空用 `https://{bucket}.{endpoint}` |
| `acl` | `select`（`none`/`public-read`） | 是 | 默认 `none`；选 `public-read` 时上传带 `x-oss-object-acl`，该头参与签名 |
| `timeout` | `number` | 是 | 5–120 秒，默认 30 |

**上传（`storage.put`）**：`PUT /{objectKey}`，Host `{bucket}.{endpoint}`（[PutObject](https://help.aliyun.com/zh/oss/developer-reference/putobject)）。签名用 V1（[在 Authorization 头中包含签名](https://help.aliyun.com/zh/oss/developer-reference/include-signatures-in-the-authorization-header)）：

```text
Authorization = "OSS " + AccessKeyId + ":" + base64(hmac-sha1(AccessKeySecret,
  VERB + "\n" + Content-MD5 + "\n" + Content-Type + "\n" + Date + "\n"
  + CanonicalizedOSSHeaders + CanonicalizedResource))
```

`Content-MD5` 空则以空串参与；`CanonicalizedOSSHeaders` 只收纳 `x-oss-` 前缀头（按字典序、名称小写）；`CanonicalizedResource = /{bucket}/{objectKey}`。上传成功后可从响应头 `ETag` 取 MD5。文档同时给出 V4（`OSS4-HMAC-SHA256`）示例；**默认实现 V1，V4 作为待确认的后续增量**（P-06）。

**读取/预览**：不代理读取；外链 = `public_domain` 或 `{scheme}://{bucket}.{endpoint}/{object_key}`。Bucket 默认私有，需 Bucket Policy/ACL 或上面的 `acl=public-read` 才能直连，同样受 P-04 约束。

**删除（`storage.delete`）**：`DELETE /ObjectName` + 同签名（[DeleteObject](https://help.aliyun.com/zh/oss/developer-reference/deleteobject)）；`204`/200 成功，`404` 按 `missing=true` 成功。

**外链生成**：见上；开启版本控制时不做特殊处理（P-06 记录为已知限制）。

## 5. 验证方案

### 5.1 单插件三环验证（FTP、七牛、COS、OSS 各跑一遍，共 4 轮）

每轮固定用同一份素材：一张 `test-media-01.jpg`（<1MB）、一段 `test-media-02.mp4`（<5MB）。域名/桶/目录全部指向**测试环境专用**资源，密钥只填在插件配置里（`secret_json` 加密），**不进仓库、不进本文件、不进日志**。

| 环节 | 步骤 | 通过判据 |
| --- | --- | --- |
| 上传 | 插件页安装→填配置→`PATCH status` 启用；媒体库页把驱动切到该插件（或分组策略指向它）；上传 jpg | 接口返回「上传成功」；`media_files` 新行满足 `disk` 为该 slug、`object_key` 非空、`path === url`、`size` 与本地一致；插件运行日志有一条 `storage.put` 成功记录 |
| 预览/访问（外链可打开） | 列表页预览缩略图能渲染；点「复制 URL」在浏览器新建标签打开 | 预览无裂图；外链返回 HTTP 200 且 `Content-Type` 与 `mime_type` 一致；未登录状态（无 Cookie）也能打开 |
| 删除（远程同步删除） | 列表页删除该行 | 库行消失；再用 `storage.exists` 对应接口或厂商控制台确认对象**已不存在**；插件日志有 `storage.delete`；重复删除同一对象不报错（`missing=true`） |
| 外链订正（换域名/协议后，第六动作 `storage.url`） | 改插件 `public_domain`（如 http→https 域名）后：先 `php artisan media:storage-rewrite-urls`（dry-run）看差异 → 再 `--execute` 写库 → 复核浏览器预览 | dry-run 输出 `pending_updated` 且库值一字未变；`--execute` 后 `path === url` 为新域名、`storage.url` 结果与 `storage.put` 的 `url` 全等、`settings`/`content_articles` 引用同步替换；再跑一次全 `unchanged`（幂等）；管理端预览可渲染、外链无登录态 200；`media:storage-audit` 仍 0 违规 |

补充项（每轮都做）：

- `POST /integration-plugins/{plugin}/tasks`（`type=health_check`）必须返回 `healthy=true`。
- 故意填错密钥后 `storage.test` 必须给出中文鉴权失败提示，且**不写明文密钥进日志**。
- 故意把 `public_domain` 填成不可达域名：上传仍应成功（远程写入与 HTTP 读取解耦），预览失败——用于确认故障边界清晰。
- 视频素材单独验证一次（走同一路径，确认 `Content-Type` 与大小校验）。

### 5.2 迁移验证（本地→远程、远程→本地各一轮）

前置：先准备 3 个本地文件（1 张图 + 1 段视频 + 1 个被 `content_articles.cover_image` 引用的封面）与 1 个被 `settings.item_value` 引用的图片。

| 轮次 | 步骤 | 通过判据 |

| 本地 → 远程（选 COS 作代表） | 在媒体库页勾选上述文件 → 迁移到 `tencent_cos` → 轮询进度 | `done=4`、`failed=0`；4 行 `disk='tencent_cos'`、`path===url`、外链可打开；`delete_source=false` 时本地文件仍在（可回退）；`content_articles.cover_image` 与 `settings.item_value` 已替换为新外链且前台首页/文章页显示正常；首页视频缓存已失效（新上传的视频立即出现在首屏列表） |

### 6.1 已查证结案（原 P-07）：`requires` 不支持声明 PHP 扩展

**结论（已确认，非待确认）**：`info.extra.requires` 只接受 `core` 与 `php` 两个键，**不能声明 `ext-ftp` 之类的 PHP 扩展**。

- 依据 `backend/app/Services/Integrations/Plugins/PluginCompatibility.php:26`：`SUPPORTED_KEYS = [KEY_CORE, KEY_PHP]`；`:53-55` 对任何非白名单键直接 `throw new BusinessException('插件清单 requires 只支持 core 与 php', 42200)`。因此写 `'ext-ftp' => '*'` 会让插件安装/升级直接失败，而不是被忽略。
- `requires` 的合法位置为清单 `info.extra.requires`，实证见 `backend/plugins/servers/kanghostx/config.php:28-32`（`'extra' => ['requires' => ['core' => '>=1.0.0']]`）。
- **对 FTP 插件的强制做法**：清单只声明 `core`（必要时加 `php`），扩展存在性改为运行时自检——在 `actions/storage.test` 与 `actions/storage.put` 入口执行 `function_exists('ftp_connect')`，缺失即返回结构化失败 `{"code":"dependency_missing","message":"PHP 扩展 ext-ftp 未启用"}`，不得抛未捕获异常。该检查是本机已验证能力（`php -m` 含 `ftp`），但生产端仍需按第 7 节复核。



### 6.2 已查证结案（审查遗留两条，2026-11-01 真修复）

**结论（已确认，代码已修复并有防回归测试）**：交叉审查中以「文档澄清」暂挂的两条七牛 🟡 项已转为真修复：
