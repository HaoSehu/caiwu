# API 通信结构治理重构方案-2026-08-16

## 背景

2026-08-16 完成 API 通信结构审查并落地第一批修复：`IntegrationException` 补统一信封 `render()`、健康检查改用 `ApiResponseBuilder` 并中文化、删除 4 个无引用的根目录遗留 Site 控制器、v3-www `__handled` 语义对齐 v4（含 422 服务端 message 回退）。相关回归测试已通过（13 passed）。

本计划管理审查确认的两项跨模块重构：

1. 后端两个过厚控制器：`Client/V2/AuthController.php`（663 行，login 等方法内联风控/极验/验证码/通知编排）；`Client/V2/ServiceConsoleController.php`（567 行、32 个 public 方法）。
2. 前端 API 通信层重复：v3-www 与 v4-console 的 axios 拦截器骨架近乎整份复制（约 200 行），`toUserMessage`、`contentNormalizer` 多端重复；admin-v3 未接入 `shared/runtime/http` 内核。

## 范围与验收

### 后端

- [ ] AuthController 拆薄：登录编排（软锁/极验/失败通知）下沉 `ClientLoginFlowService`；验证码「guest→用户」回退校验收敛进 `VerificationCodeService`；发码流程（purpose 校验、限流、发送、落码）下沉统一服务；`info()` 载荷改 Resource 输出。所有接口的 HTTP 状态、错误码、中文文案、响应信封保持不变。
- [ ] ServiceConsoleController 按域拆分为 3 个控制器（基础信息/计费下单/网络与安全组），共享助手（操作上下文、缓存锁）抽到 Support/Service；路由 URL、中间件、响应保持不变；`后端API清单.md` 重新生成且接口数不变。
- [ ] 全量 `php artisan test` 通过（预存失败需有隔离证据）。

### 前端

- [ ] `shared/runtime/http` 新增 `createHttpClient` 工厂：收敛拦截器骨架（信封校验、`__handled` 语义、silentError、422/429/401 处理、弱网重试、幂等去重、超时策略），UI 提示与 401 跳转通过回调注入。
- [ ] v3-www 与 v4-console 接入工厂并删除各自拦截器副本；两端行为差异（v4 的公共站点 GET 免 token、40100 跳登录）通过选项表达。
- [ ] `toUserMessage` 下沉 shared，v3/v4 引用 shared 版本并删除本地副本；admin 扩展版独立保留（决策见日志）。
- [ ] `contentNormalizer` 收敛到 shared（v3 的资源 URL 解析以可注入 resolver 表达），v3/v4 删除本地副本。
- [ ] shared 新增 HTTP 工厂行为测试；`npm run typecheck:shared && npm run test:shared`、v3/v4 `npm run build` + `npm run verify:refactor` 通过。

### 非目标

- admin-v3 的 VAxios 体系替换为 shared 内核：涉及全局错误提示产品策略（是否引入拦截器级 toast），单独立项决策，本计划不实施。
- session.ts 进一步合并：两端已是 `shared/runtime/session` driver 的薄壳，残余差异为 v4 的登录清理函数，属合理分叉。
- 不修改任何 API 的 URL、参数与响应结构。

## 实施步骤

1. 阶段一（后端 Auth）：`BusinessException` 增加可选 `data` 载荷；新建 `App\Services\Auth\ClientLoginFlowService`；`VerificationCodeService` 增加账号维度回退校验；新建发码统一服务；新建 `ClientUserInfoResource`；控制器瘦身为「校验→调服务→返回」。
2. 阶段二（后端 ServiceConsole）：新建 `ServiceBillingController`、`ServiceNetworkController`，原控制器保留基础信息/监控/VNC；抽 `RequestContext`（操作上下文）与 `ServiceActionLock`（缓存锁）；更新 `routes/v2-client.php` 引用；重新生成 API 清单。
3. 阶段三（前端 shared HTTP 工厂）：shared 新增 `createHttpClient` 与 `toUserMessage`，补行为测试；v3-www、v4-console 依次接入，构建 + `verify:refactor` 验证。
4. 阶段四（normalizer 收敛）：shared 增加可配置 `contentNormalizer`；两端迁移引用并删除副本；跑两端测试与构建。
5. 全量验证：后端全量测试；`build:frontends`；shared 测试；docs:check。

## 风险与回滚

- 认证链路属高风险域：每阶段独立提交，失败即回滚该阶段；行为等价以现有 `AuthLoginRegressionTest`、`LoginSoftLockTest`、`ClientAuthEnumerationTest`、`ClientAuthBindingSecurityTest`、`MessageRateLimitServiceTest` 等测试兜底。
- `BusinessException` 增加 `data` 为向后兼容的可选参数，不改既有 throw 点语义。
- 控制器拆分只移动代码不改路由；前端 v3/v4 接入工厂属于行为保持重构，`__handled`/`silentError` 语义以 v4 现行实现为基准（2026-08-16 已回修 v3）。
- 测试库依赖：`idc_test` 已由 root 授权创建（2026-08-16），若测试库被清空需先重建再跑测试。
- 回滚条件：任一阶段测试失败且无法在 30 分钟内定位；或前端构建/verify:refactor 出现与工厂接入相关的失败。
