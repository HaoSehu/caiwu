# 外部进程与被禁用函数依赖收敛 · 2026-10-22

## 背景

宝塔默认的 `disable_functions` 里包含 `proc_open`、`popen`、`exec`、`shell_exec`、`system`、`passthru`、`pcntl_exec`、`putenv` 等。对照 `zjmf-manger-decoded-main` 的只读分析结论：它能在默认清单下运行，是因为定时任务由 crontab 直接同进程执行、数据库备份自己拼 SQL、没有 Composer，三件事都不需要 fork。本项目的运行时不同（Laravel 调度器对命令型事件一律走 `Symfony\Component\Process`），但仍有几处「为了不必要的能力而放开禁用函数」的地方可以收敛。

本次优化的判定标准是：**只在确实能减少对外部进程与被禁用函数依赖时才改**，不为「对齐对照项目」而改运行时架构。

## 范围与验收

- [x] Web 请求侧不再有任何 `proc_open` 调用点
- [x] `backend/app` 里不再有 `popen` / `pclose` / `exec` 调用点
- [x] `proc_open` 只剩 CLI 的 `schedule:run` 派发与 `queue:drain` 拉起 worker
- [x] `putenv` 只剩 Composer 与 `test:prepare` 需要，运维文档口径与代码一致
- [x] 上游 DNS 解析能力不下降（仍能解析 A/AAAA 与 hosts 记录）

## 三项结论

| 项 | 对照 zjmf | 本项目处理 |
| --- | --- | --- |
| 定时任务同进程执行 | zjmf 用 crontab + `think cron` 同进程 | **不采纳**。`backend/routes/console.php:41-56` 里 `queue:drain` 与 `coupon:dispatch-due-campaigns` 都调 `runInBackground()`，Laravel 对命令型事件一律走 `Symfony\Component\Process`；要同进程只能改成闭包事件，而闭包事件禁止后台执行。`proc_open` 是 CLI 侧硬依赖，保留放开。 |
| 数据库备份纯 PHP 自拼 SQL | zjmf `app/admin/lib/Backup.php` 用 `show tables` + `file_put_contents` + `ZipArchive` | **不采纳**。纯 PHP dump 对财务库的大表会整表进内存，且 NULL/二进制/转义处理难以对齐 `mysqldump`。既有方案是「投队列 + CLI worker 跑 `mysqldump`」，已经把长事务从 FPM 移走，效果等价。 |
| 消除 Web 侧子进程 | zjmf 全程无子进程 | **采纳**。`HostingPanelApiTransport` 的异步 DNS 解析用 `new Process([$phpBinary, '-r', $script, $host])` 起子进程，是 FPM 请求内唯一的 `proc_open` 调用点；而 `proc_open` 被禁用时该子进程必然失败并降级，等于白付一次进程创建成本。 |

## 风险与回滚

1. **DNS 解析失去超时保护**：`dns_get_record` / `gethostbynamel` 是同步阻塞调用，解析器挂起时最长受 PHP `default_socket_timeout` 约束，不再有原来的 3 秒子进程超时。缓解：解析结果有 900 秒正缓存与 60 秒负缓存，失败会被缓存住不再重复付费；`allowed_hosts` 白名单与 SSRF 私网校验不变。
2. **VNC 拉起依赖 proc_open**：`vnc:ensure-relay` 改用 `Symfony\Component\Process` 后，若 `proc_open` 被禁用会直接失败并返回 `FAILURE`。该命令本就是手工排障用，正式部署的 Relay 由宝塔进程守护托管，不受影响。
3. **回滚**：本次改动只涉及解析实现与命令实现，无 schema、无路由、无接口契约变化，可整体回退；回退后 `dns_resolver_timeout` 配置需要一并恢复。
