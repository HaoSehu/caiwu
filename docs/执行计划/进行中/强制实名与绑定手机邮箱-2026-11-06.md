# 强制实名与强制绑定手机号/邮箱

## 背景

用户端对实名、手机号、邮箱三类账户要素没有统一的产品级开关：

- 实名校验散落在下单（`CheckoutService::assertPurchaseRequires`）、充值（`RechargePaymentService::assertVerifiedUser`）、提现（`ReferralService::createWithdrawal`），全部是无条件硬编码，管理端无法按运营策略开关；
- 手机号、邮箱没有全局拦截，只有商品级 `purchase_requires.require_phone`（仅下单生效、无邮箱维度）；
- 控制台只在首页展示「已实名 / 已绑手机 / 已绑邮箱」标签，没有统一强制引导；
- `EnsureEmailIsVerified`（别名 `verified`）是零挂载死中间件，`API格式规范.md` 的 `40301` 说明与之绑定。

目标：管理端三个开关 + 用户端「关键业务拦截 + 全局不可关闭弹窗引导」，把硬编码实名校验收敛为受开关控制。

## 范围与验收

- [x] 管理端「系统设置 → 系统维护 → 账户策略」提供三个开关：是否强制实名、是否强制绑定手机号、是否强制绑定邮箱，默认全部关闭。
- [x] 开关关闭时存量行为不变：未完成项不拦截下单、支付、充值、提现。
- [x] 开关开启时，下单（`checkout`）、支付（`payment`）、充值（`recharge`）、提现（`withdrawal`）按缺失项分别返回 `40301`/`40302`/`40303`，响应 `data` 带 `action` 与完整 `missing` 清单。
- [x] 判定口径统一：实名走 `User::hasCompletedVerification()`；手机/邮箱按字段非空判定（不要求验证标记）。
- [x] 商品级 `purchase_requires.require_phone` 独立于全局开关继续生效。
- [x] `GET /api/v2/client/auth/info` 下发 `account_policy`（三个布尔 + `missing_items`）。
- [x] 控制台在开关开启且存在未完成项时显示不可关闭弹窗（Esc、遮罩、关闭按钮均无效），「去完成」直达实名页或个人资料页对应绑定弹窗。
- [x] 只读页面不被重定向或阻断；实名页与个人资料页豁免弹窗（否则会挡住自己的落地表单）。
- [x] 后端 Feature 12 例、控制台 e2e 5 例、管理端 e2e 2 例通过；两端全量 e2e 通过。

## 实施步骤

1. `settings` 新增 `account_policy` 组（`require_verification` / `require_phone` / `require_email`，默认 `'0'`）：`SettingsSeeder` 种子 + `SettingService::getAccountPolicyConfig()` 与组默认回显。
2. 新增 `App\Services\User\AccountPolicyService`：`policy()` / `missingItems()` / `assertSatisfied($user, $action)`。
3. 四个关键写操作接入：`CheckoutService`、`ClientRechargeWorkflowService`、`ClientInvoicePaymentWorkflowService`（余额/混合/网关三入口）、`ReferralService`；删除 `OrderService::assertPurchaseRequires()` 死方法与基线条目。
4. `AuthController::info()` 合并 `account_policy`。
5. 管理端设置页五处联动 + 路由 + 菜单 + `UpdateSettingsRequest` 键白名单。
6. 控制台：`account-policy` store（由 user store 归一）、`AccountPolicyDialog` 挂到布局、`useProfile` 支持 `?tab=security&bind=phone|email` 意图、守卫在缺策略/实名字段时补拉 `auth/info`。
7. 测试与文档。

## 风险与回滚

- 开关默认关闭，存量行为零变化；唯一向后兼容的新增是 `auth/info` 多一个 `account_policy` 字段。
- **行为变化点**：开关开启后，未实名用户将无法下单/充值/提现（原先是无条件强制，现改为可关）。
- **边界（刻意不覆盖）**：自动续费（直连 `BalanceInvoicePaymentService`）与管理端代付不受策略约束；续费/流量包/升降级的建单放行、支付时统一拦。
- 回滚：移除四个调用点即可；数据库仅多出 `account_policy` 组三行配置，无害。
- 本地模拟命令 `LocalProductSimulateCommand` 走 `CheckoutService::create`，开关开启时其模拟用户会被拦截，属预期行为。
