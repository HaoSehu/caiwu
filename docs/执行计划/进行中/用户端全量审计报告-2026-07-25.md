## 四、各维度详细报告

### 4.1 性能审计（Frontend Developer）

**亮点**：
- ✅ 两项目路由懒加载覆盖率 100%
- ✅ v3-www 首页 `defineAsyncComponent` + `requestAnimationFrame` 延迟挂载首屏以下区块
- ✅ v4-console 广泛使用 `shallowRef` 减少响应式开销
- ✅ Dashboard 用纯 CSS 柱状图替代 ECharts，零图表库开销
- ✅ shared/runtime/http 请求去重 + 自动重试 + 弱网超时补偿
- ✅ 构建时 Gzip(level 9) + Brotli(quality 11) 预压缩

**短板**：
- ❌ `echarts@^6.1.0` 死依赖
- ❌ v3-www 未复用 shared HTTP 核心
- ❌ 无请求取消机制
- ⚠️ v4-console 重型组件（service-console 子 Tab）未做组件级懒加载
- ⚠️ 两个项目均未使用图片 `loading="lazy"`

### 4.2 布局架构审计（UX Architect）

**v4-console 亮点**：
- ✅ TDesign Token + Less 变量双体系干净
- ✅ 全局 `#app` padding 通过 CSS 变量统一
- ✅ 移动端 padding `12px !important` 强制覆盖
- ✅ z-index 层级差合理（Header 1001 > SideNav 200 > Content）
- ✅ service-console 布局稳定（flex + sticky sidebar）

**v3-www 短板**：
- ❌ 无断点变量体系（13 种裸 px 值）
- ❌ `!important` 泛滥（89 处）
- ❌ `.container` 在 5 个组件中重复定义
- ❌ 非 8px 倍数间距 7 处

**Shared 组件问题**：
- ❌ 70% 组件未被使用（PageScaffold/DetailScaffold/SideNavShell/AppDrawer/AppDialog/MotionWrapper/ResponsiveActionBar）
- 建议：删除 SideNavShell、ResponsiveActionBar、MotionWrapper；推广或删除 PageScaffold/DetailScaffold

### 4.3 视觉审计（UI Designer）

**最严重问题：两套颜色体系并行**

| Token | DESIGN.md | v3-www | v4-console |
|-------|-----------|--------|------------|
| 品牌色 | `#165DFF` | ✅ `#165DFF` | ❌ `#006eff` |
| 成功 | `#12B76A` | ✅ | ❌ `#0abf5b` |
| 警告 | `#F59E0B` | ✅ | ❌ `#ff7200` |
| 危险 | `#F04438` | ✅ | ❌ `#e54545` |
| 主文本 | `#1F2937` | ✅ | ❌ `rgba(0,0,0,0.9)` |
| 次文本 | `#5B6B82` | ✅ | ❌ `rgba(0,0,0,0.6)` |

**结论**：必须在 `theme.css` 中覆盖 TDesign 的品牌色系和语义色系为 DESIGN.md 值。

**暗色模式就绪度**：v4-console `theme.css` 已内置完整暗色变量（`[theme-mode='dark']`），但从未启用。v3-www 零暗色支持。

### 4.4 交互体验审计（UX Researcher）

**关键发现**：
- ⚠️ 25 个 v4-console 页面中仅 4 个有完整面包屑
- ⚠️ 购买链路跨应用断裂（v4-console catalog/order-create 为占位页，重定向到 v3-www）
- ✅ checkout-resume 三态容错设计优秀（loading/empty/error + 幂等键）
- ✅ 移动端列表全部卡片化适配
- ❌ 所有搜索框无防抖
- ❌ 所有列表页筛选条件不持久化 URL

**表单体验**：v4-console profile 表单无校验规则、无离开未保存确认；recharge 桌面端缺协议确认。登录/注册表单体验相对完善。

### 4.5 代码质量审计（Code Reviewer）

**大型文件需拆分 Top 3**：
1. `dashboard/index.vue`（740+ 行） → 拆 6 个子组件
2. `recharge/index.vue`（420+ 行） → 桌面/移动双模板重复
3. `services/index.vue`（520+ 行） → 卡片/表格双视图

**重复代码**：
- `getErrorMessage` 6 处重复 → 提取到 `@/utils/error.ts`
- 5 个财务列表页共享结构 → 提取 `FinanceListPage` 组件
- `formatMoney` 4 处重导出 → 页面直接从 utils 导入
- `client.ts` 单文件 50+ API 函数 → 按资源域拆分

**类型安全**：v4-console TypeScript 使用良好，但 `Record<string, unknown>` 泛滥。v3-www 为纯 JS 项目，无类型标注。

### 4.6 无障碍审计（Section 508）

**评分：2.4/10 — 严重不合规**

20 项 WCAG 2.1 AA 违规，覆盖：
- 1.1.1 非文本内容（图标无 label）
- 1.3.1 信息与关系（label 无 for、表格无 caption）
- 1.4.1 颜色使用（必填仅红色星号）
- 1.4.3 对比度（4 个颜色组合不达标）
- 2.1.1 键盘（侧边栏无键盘展开）
- 2.4.1 跳过块（无 skip-to-content）
- 4.1.2 名称/角色/值（支付方式用错 ARIA 模式）
- 4.1.3 状态消息（Toast 无 role="alert"）

**关键修复 Top 3**：
1. 添加 skip-to-content 链接
2. 为 Toast 通知添加 `role="alert"` + 全局 `aria-live` 容器
3. `<label>` 添加 `for` 属性关联 `<input>`

## 五、跨维度交叉分析

### 5.1 高频共性问题

1. **跨项目 Token 体系割裂** — 品牌色、语义色、文字色、圆角、阴影全部不一致（UI + UXA + A11y 三个智能体同时发现）

3. **Error/空态处理不统一** — 仅 checkout-resume 做到三态完整（UX + UI 同时发现）
4. **URL 状态持久化缺失** — 筛选条件、Tab 位置刷新即丢失（UX + CR 同时发现）
