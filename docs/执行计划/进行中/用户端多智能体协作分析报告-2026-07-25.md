## P0 — 必须立即修复（3 项）

### 1. 品牌主色跨项目不统一

`v3-www` 品牌色 `#165DFF`（符合 DESIGN.md 规范），`v4-console` 的 `theme.css` 品牌色为 `#006eff`（TDesign 出厂默认值）。两个用户端看到的是两个不同的蓝色。

- **文件**：`frontend-user-v4-console/theme.css`
- **修复方向**：将 `--td-brand-color-6` 及 `--td-brand-color-1` 至 `--td-brand-color-10` 完整色阶替换为以 `#165dff` 为基准的色阶

### 2. 购买链路跨应用断裂

v4-console 的 `/client/catalog` 和 `/client/order-create` 是空壳占位页，直接重定向到 v3-www 的 `/products`。用户在控制台侧边栏点击「产品目录」或「下单」后，从 TDesign 界面被踢到 Element Plus 官网。

- **文件**：`frontend-user-v4-console/src/pages/client/catalog/index.vue`、`frontend-user-v4-console/src/pages/client/order-create/index.vue`
- **影响**：视觉和交互完全割裂，登录态衔接依赖 URL 参数和 localStorage

### 3. v4-console 零使用 PageScaffold / DetailScaffold

FRONTEND.md 明确要求「优先复用 shared/user-v3 的 PageScaffold」，但搜索全部 46 个 client 页面，无任何页面引用 PageScaffold 或 DetailScaffold。每个页面自行实现布局代码。

- **文件**：`shared/user-v3/components/PageScaffold.vue`、`shared/user-v3/components/DetailScaffold.vue`
- **影响**：大量重复的 `display: flex; flex-direction: column; gap: ...;` 布局代码

## 亮点总结

- **错误处理体系设计精良** — `toUserMessage` + `extractValidationErrors` + `silentError` 三件套，两个项目共享同一套 request 工具
- **无 UI 框架混用** — v3-www 纯 Element Plus，v4-console 纯 TDesign，图标库各自隔离
- **状态组件复用** — `DataState`、`LoadingState`、`StatusTag` 在 v4-console 中广泛且一致地使用
- **v4-console CSS 变量化** — 13 个页面零硬编码十六进制颜色，100% 使用 `var(--td-*)`
- **checkout-resume 容错设计** — loading/empty/error 三态完整 + 幂等键 + localStorage 兜底
- **HTTP 层防御性编程** — 安全请求去重、弱网超时补偿、429 Retry-After 倒计时、网络断开中文提示
