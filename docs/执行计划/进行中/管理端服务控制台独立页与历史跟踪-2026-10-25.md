# 管理端服务控制台独立页与历史跟踪

## 背景

管理端「服务控制台」原先是用户详情页里的 `t-drawer`（`frontend-admin-v3/src/pages/users/detail/index.vue`），一个实例的摘要、实例操作、连接信息、规格参数、订单与上游全部堆在一个 680px 抽屉里；相关的订单、账单、操作日志只能跳回用户维度查看，无法按实例收敛；运维对某个实例的跟进记录（联系上游、变更说明）在系统里没有落点。

本次把服务控制台重构为独立路由页 `/admin/users/:id/services/:serviceId`，用五个页签承载：概览（默认）、相关订单、相关账单、操作日志、历史跟踪。其中历史跟踪是新增能力——列表型备注板块，每条含时间、图片（多图）、留言、操作人，操作人由后端取当前登录管理员，不允许前端传入。

## 实施步骤

1. 只读定位：抽屉模板与脚本、详情页服务 tab、订单/账单/日志/媒体上传的既有接口与组件、路由与权限、e2e 约定。
2. 后端先行：建表与模型 → 请求类/资源 → `AdminServiceTrackingService` → 控制器与路由 → 订单/账单 `service_id` 过滤 → 操作日志管理员开关。
3. 前端：新增 `pages/users/service-console/`（index.vue + index.less + 四个 tab 子组件），注册路由，详情页「管理」改跳转。
4. 清理：删除抽屉模板、弹窗、相关脚本与样式，避免同一能力存在两套实现。
5. 重生成自动生成物，补 e2e，跑后端静态检查 + 管理端 build + 全量 e2e。

## 风险与回滚

- 新增表 `service_tracking_records` 只增不改，回滚只需下线路由与删除表，不影响既有实例数据。
- 订单/账单新增的 `service_id` 过滤是可选参数，未传时行为与原来完全一致（用户维度列表不受影响）。
- 操作日志的服务维度接口是新增路由，客户端控制台的既有接口与过滤语义不变。
- 详情页抽屉已删除：旧链接若直接指向用户详情页无影响（抽屉从来不是路由），「管理」按钮改为页面跳转。
- 回滚方式：按 Git 历史恢复抽屉模板/脚本与详情页样式，删除新增路由与五个后端接口即可；表可保留。
