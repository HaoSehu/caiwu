# 后端目录治理

## 背景

目录审查确认三类问题：插件 Provider 会把任意扫描到的插件迁移加入 Laravel；用户端部分控制器直接查询模型并手工投影响应；`PaymentService` 同时承担充值、支付、回调、退款和支付后处理。另有空目录和无调用测试实现。

目标是在不改动 API 路由、响应契约或数据库结构的前提下，恢复插件边界、控制器薄层和支付领域的协作边界。此次不执行数据库迁移，也不调整现有业务数据。

## 范围与验收

- [x] 插件扫描和启动不再注册插件目录的数据库迁移，并有回归测试。
- [x] 用户端账单支付、充值、支付记录和订单读取不在 Controller 中直接查询 `Invoice`、`Payment`、`Order`，响应投影由服务或 Resource 完成。
- [x] 支付网关协议协作从 `PaymentService` 抽出，保留现有支付、回调和退款契约。
- [x] 删除经全仓检索确认无调用的空目录和测试实现。
- [x] 纯结构 PHPUnit 测试、PHP lint、Pint 和文档校验通过。
- [ ] 支付/订单 API 回归与 PHPStan 待具备 `idc_testing` 库访问权限后执行。

## 实施步骤

1. 删除 `PluginServiceProvider` 的插件迁移自动注册，并覆盖“扫描插件不注册迁移”的边界。
2. 增加客户端金融读取/工作流服务，将 Controller 中的模型查询、汇总和投影迁出。
3. 提取支付网关协议协调服务，迁移 `PaymentService` 的网关解析、预创建、查询和退款调用。
4. 清理确认无调用的遗留目录和 `app/Testing` 实现。
5. 运行受影响测试、PHPStan、Pint 检查和 `npm run docs:check`，更新本计划的结果。

## 风险与回滚

- 支付调用链涉及回调和财务状态；每一步保持原路由、请求字段、响应字段和事务边界。出现定向测试或静态分析失败时，回退该步骤的代码改动，不触碰本工作区已有数据库整理。
- 删除插件迁移加载只影响未来迁移发现；当前插件包不存在此类目录，不执行或回滚任何数据库迁移。
- 删除遗留文件前以全仓检索和 Composer 自动加载规则确认；发现动态装配点则停止删除。
