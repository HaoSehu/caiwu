# 无响应错误重试治理

## 背景

CORS/断网/超时类"无响应"错误在浏览器中无法与瞬时网络抖动区分，但均属确定性失败。当前三端请求层仍将其当作可重试错误：

- `frontend-admin-v3` 自研 VAxios 对 `status === undefined`（无响应）也重试 3 次、固定 1s 间隔、单发 10s 超时，最坏约 43 秒才报错。
- `shared` 的 `retrySafeRequest` 将 `ERR_NETWORK`/`ETIMEDOUT` 等无响应错误列入可重试白名单，弱网下最坏约 51 秒。
- `frontend-user-v4-console` 三个业务轮询（实名认证 3s、充值状态 2s、支付状态）请求失败后永不停止，形成"一直在重试"的体感。

目标：无响应错误一律不重试、立即报错；业务轮询连续失败后自动熔断。非目标：不处理后端 CORS/CDN 配置（属网络层根因，另行处理），不调整超时参数。

GitHub 调研佐证（2026-08-30）：vben v5 与 vue-element-plus-admin 无自动重试（网络错误提示后直接抛出）；soybean-admin 引入 axios-retry 但默认 `retries: 0`；axios-retry 维护者在 issue #96 明确 CORS 错误不该重试；保留重试的库（ofetch、TanStack Query）限额极紧（1~3 次 + 退避 + 封顶）。

## 风险与回滚

- 行为风险：CDN 瞬时抖动时少一次自动自愈机会，用户需手动重试（已确认接受）。轮询熔断后用户需重新操作触发（重新生成二维码/重新进入页面）。
- 兼容风险：无接口与数据变更；纯前端行为收敛。
- 回滚：改动均为独立小步提交，逐文件回滚即可恢复原重试行为。
