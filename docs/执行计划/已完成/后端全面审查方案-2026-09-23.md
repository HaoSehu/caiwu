# 后端全面审查方案（只读）

## 背景

后端已累计 1001 个 PHP 文件、13.9 万行应用代码，其中 `Services/` 占 6.4 万行；`app/Http/Requests` 303 个、`Resources` 121 个、`Console/Commands` 80 个可执行命令；后端 API 已到 368 条。此前两次审查留下了明确空档：

- 2026-08-23《六领域专家审查报告》只读审查完成，**报告文件已被外部删除**（`docs/设计文档/` 与断链可证），其 P0/P1 结论距今约一个月，现状未知。
- 2026-08-26《API接口安全与性能修复方案》修复了 v2 接口越权/信息暴露/N+1 的 M1–M5、L1–L6，但其自述未覆盖项（剩余 Service/Resource 补查、`LIKE '%kw%'` 前置通配符全表扫描、索引与慢查询、插件运行时）**明确划为另行立项**。

问题是：**没有任何一次审查回答过「后端整体有没有冗余、能不能复用、有没有无用过期文件」**。功能域正确性、API 冗余与数据传输量、文件卫生三件事，目前只有零散结论。

**目标**：用多智能体并行编队对 `backend/` 做一次全范围只读审查，产出可逐条跟踪的分级清单，并给出可直接排期的修复批次建议。

**非目标**：

- 不修改任何生产代码、不跑迁移、不动 git。工作区现有 20+ 未提交改动（用户详情页三 tab 与手动补录）仅作为审查基线，不触碰。
- 三端前端只作影响面提示，**不作为「端点是死端点」的裁决依据**（本次范围不含三端调用面，该限制写入报告未覆盖项）。
- 不复做 2026-08-26 已修完的 M1–M5/L1–L6；但承接其未覆盖项。
- 不纳入视觉/前端 UI、部署环境本身。

**关联**：`docs/执行计划/已完成/API接口安全与性能修复方案-2026-08-26.md`（承接未覆盖项）、`docs/执行计划/进行中/日志分层与容量治理整改方案-2026-08-23.md`（log-archive v1/v2 双轨裁决）、`docs/参考资料/后端/后端目录分类规范.md`（needs-review，仅作参考，分层裁决以运行代码为准）。

## 范围与验收

**范围**：`backend/` 全量，含 `app/`、`routes/`、`config/`、`database/`、`plugins/`（7 域 113 文件，排除各插件内嵌 `vendor/`）、`scripts/`、`tests/`。基线为当前工作区状态（HEAD `9a65652e` + 未提交改动）。

**通用检查清单（每个功能域都要过这 7 条）**：

1. 链路完整性：路由→控制器→请求校验→Service→模型/表→插件/上游 是否闭环，有无孤儿端点、不可达分支。
2. 业务正确性：状态机、金额/数量计算、幂等（唯一键/幂等键）、并发、事务边界、异常分类与「吞掉异常」。
3. 权限与归属：用户归属断言、权限码覆盖、越权路径（项目口径：管理端**不做**脱敏，管理端完整信息输出不算缺陷）。
4. 数据一致性：投影/缓存/台账与真源一致、迁移后遗留字段、双写残留。
5. 代码健康：重复实现与可复用点、超大文件与职责过载（32 个 >800 行）、分层违规（Controller 直连 `Http::`/DB）、死代码。
6. 性能与数据量：N+1、宽投影、无分页全量、循环内查询、缓存键与失效遗漏。
7. 可测试性：该域既有测试覆盖与关键未覆盖点（现状 30 个测试文件，`System`/`ClientServiceConsole`/`Ticket`/`Auth` 零覆盖）。

**验收**：

- [ ] 覆盖面：`app/` 全部 PHP 文件落在某个域审查范围内；368 条路由逐条过 Wave 2；`plugins/` 7 域、`config/` 23 文件、`migrations/` 35 + 归档 120、`scripts/` 34 文件逐项过 Wave 3。
- [ ] 证据质量：每条发现含 `文件:行号`；量化结论（引用 0 次、无分页、命中 N 次）可复算，抽样复验由主进程执行。
- [ ] 不新增 docs 失败项：`npm run docs:check` 失败数不高于当前既有 8 条断链。
- [ ] 零代码改动：审查结束 `git status` 与 Wave 0 基线逐项比对，除新增文档外无差异。
- [ ] 历史复验闭环：Wave 4 每条结论落到「仍存在 / 已修复 / 无法判定」三态之一。
- [ ] 关键结论已同步到会话（因 `docs/` 除 `参考资料/` 外不进 git，见风险）。

## 实施步骤

### Wave 0 · 基线快照与真源导出

录 `git status --porcelain` 与 HEAD SHA；跑 `composer analyse`、`composer format:check`、`php artisan test` 记录既有基线；导出 `artisan route:list --json` 与后端 PHP 文件行数清单到 `docs/_local/后端全面审查-2026-09-23/wave0/`。**不刷新** `docs/自动生成/` 与 `database/schema/mysql-schema.sql`，基线漂移作为发现记录。

### Wave 1 · 功能域审查（6 域 × 2 视角 = 12 个智能体，每轮并行 4 个）

域内两视角：**A 功能正确性**（清单 1–4、7）、**B 结构与质量**（清单 5–6）。

### Wave 2 · API 横切审查（3 个智能体，并行）

- **E1 冗余与复用**：368 条路由逐条过。已知待裁决重叠：资金流水三套入口（`/balance-logs`、`/ledger`、`/finance/ledger`）、管理端用户子资源与顶层资源双入口 4 组（订单/发票/服务/日志）、summary+list 成对 15 组、公告与内容概览跨前缀多实现、商品分组 `index/tree/children`、服务详情拆 5 端点、`ProductCatalogService` 别名方法组。产出「可收敛方案 + 收益 + 影响面」。
- **E2 数据传输量**：无分页全量端点（site 分组 catalog、instance-spec/cpu-model-catalog、供应商商品目录、商品收入报表、日志 `limit(1000)`、媒体重索引）；未走 Resource 的控制器与 Resource 白名单缺口；宽投影与列表页夹带明细（`config_snapshot` 系列、`provision_data`、每页全量 `categories`）；N+1；导出类整库下载。
- **E3 承接 2026-08-26 未覆盖项**：`LIKE '%kw%'` 全表扫描（重点 `AdminServiceListService.php:300-333` 三张 JSON 长文本表）、索引与慢查询静态评审、插件运行时链路。

### Wave 3 · 文件与资产审查（2 个智能体，并行）

- **F1 死代码与过期**：无引用类、未引用 Resource、Factory 与 `HasFactory`、`Requests/Site` V1 残留、孤立 Storage/Mail 契约、前台重复详情实现、`SiteProductReadService` 未用方法、log-archive v1/v2 双轨、一次性 `migrate:*`/`backfill:*` 命令。
- **F2 配置·迁移·脚本·文档漂移**：零调用配置、三套并行迁移机制、同日连删迁移、表删建反复、schema 基线与 `docs/DATABASE.md` 落后迁移、`docs/自动生成/` 与 `.gitignore` 的提交要求冲突、`API清单导航.md` 状态失真、`database/_archive` 体积、`scripts/` 大件与已提交 `.pyc`。

**硬性要求**：F1/F2 每条结论必须独立引用计数复验。已实证假阳性一例（`AdminServiceListService.php:74` 的 `paginate($pageSize, ['*'])` 实际被上游 `select()` 覆盖，**不是**宽投影）。

### Wave 4 · 历史结论复验（1–2 个智能体）

把 2026-08-23 六领域审查 P0/P1 逐条复验为「仍存在 / 已修复 / 无法判定」：开通异常吞掉与可见性超时（`retry_after=90` vs Job `timeout=1200`）、未知状态重复开通、退款无独立 `refunds` 记录、财务 float 金额、CSRF 豁免 + Sanctum stateful、代登录 Token `[*]` 2 小时、服务密码直出与 VNC token 校验、服务总览缓存缺版本化、安全组缓存键缺 provider/绑定版本且缓存 JWT、批量取消订单无上限 `get()`、测试直连 `idc` 的隔离风险、调度 stdout/stderr 丢弃与发布无健康门禁、VNC Relay 无 SIGTERM。

### Wave 5 · 汇总定级与登记（主进程 + 1 个交叉验证智能体）

去重合并与交叉验证（同问题被多域报出时合并）；按项目口径定级（P0=资金/权限/数据损坏/线上可用性，P1=正确性缺陷与明显性能安全风险，P2=可维护性/冗余/卫生）；标注与既有在跑方案的归并关系；产出修复批次建议（每批 = 可独立验证与提交的单元）。

**产物**：中间报告 `docs/_local/后端全面审查-2026-09-23/<wave>/`；最终报告 `docs/设计文档/后端/后端全面审查报告-2026-09-23.md`；本计划三处登记（`docs/catalog.json`、`docs/执行计划/README.md`、`docs/执行计划/进行中/README.md`）。

**回滚**：本计划只新增文档、不改代码；回滚 = 删除新增文档并撤销三处登记。
