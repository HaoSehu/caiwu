# API 接口安全与性能修复方案

依据 [API 接口安全与性能审查报告-2026-08-26](../../设计文档/API接口安全与性能审查报告-2026-08-26.md) 制定。本方案不是照抄报告：所有结论已逐项对照当前代码复验，行号级证据、修复策略以本计划的「复验修正」为准。

## 背景

审查报告对 `/api/v2/admin/*`、`/api/v2/client/*`、`/api/v2/site/*` 做静态审查，输出中危 5 项（M1-M5）、低危 6 项（L1-L6）。本方案落地前已完成逐项代码复验（2026-08-26），结果：

| 编号 | 报告结论 | 复验结果 | 修复策略要点 |
| --- | --- | --- | --- |
| M1 | NAT 删除缺归属校验 | 成立 | 复用 `resolveNatAclContext($fresh=true)` 返回的列表做 id 归属断言 |
| M2 | 工单回复引用查询 N+1 + 附件 stat 放大 | 成立，且有更优修法 | 引用回复与主回复同工单，发送者名可直接复用 `$staffMap`/`$clientName`；附件元数据落库时已固化在 `attachments` JSON，读取端优先信任固化值 |
| M3 | 管理端内容列表 N+1 | **失效** | `adminList()` 当前已含 `with(['contentCategory', 'creator', 'updater'])`（`ContentArticleService.php:38-43`），无需改动；报告该项作废 |
| M4 | 登录验证码接口用户枚举 | 成立 | 删除 `SendAccountCodeService` 两处 login 存在性分支即可，校验链路注释已声明「先验码再解析用户」的一致性设计（`AuthController.php:75`、`:377`） |
| M5 | `/ready` 暴露健康明细 | 成立 | 公开端只回状态码与 status；明细迁入管理端带权限码的新路由 |
| L1 | 用户列表三字段恒空 | 成立 | `company/qq/member_level_id` 均为 `users` 主表列，模型无 `profile()` 关联（`:275` 是 referralProfile），补 select 即可，同时删除 Resource 中恒不生效的 profile 死分支 |
| L2 | 公开内容接口 Markdown 渲染放大 | 成立 | 落库固化 excerpt 新列 + 列表 select 白名单排除 content + 列表接口补限流 |
| L3 | 权限码边界错位 | 成立 | 推荐 Hero 路由迁入 `SITE_*` 分组；`ORDER_MANAGE` 标注预留保留（待产品确认） |
| L4 | CSRF 例外路径失效 | 成立 | 直接删除（api 组本身无 CSRF 校验） |
| L5 | 推荐接口直出完整邮箱 | 成立 | 客户端侧邮箱掩码，格式与管理端脱敏器一致（`a***@domain`） |
| L6 | 报价限流维度不足 | 部分修正 | 现状 `throttle:60,1` 未命名时默认即按 IP 限流，问题是阈值过松而非维度缺失；降阈为命名限流器 |

非目标：报告「未覆盖项」（索引与慢查询专项、插件运行时、剩余 Service/Resource 补查）不在本计划内，另行立项。

## 范围与验收

- [ ] P1-M1：NAT 删除具备归属校验，跨服务枚举 forwardingId 返回业务错误且不打上游。
- [ ] P1-M2：一页全带引用的工单回复在 O(1) 次预取内完成渲染，读取端不再为附件重算 mime_type/size。
- [ ] P2-M4：发送验证码接口对注册/未注册账号返回一致响应与相同文案。
- [ ] P2-M5：未认证访问 `/ready` 不再返回 checks 明细；管理端新路由可查看明细。
- [ ] P3-L1：管理端用户列表 company、qq、member_level_id 三列恢复真实数据。
- [ ] P3-L2：公开内容列表 SQL 不再 SELECT content 长文本；摘要求高于实时渲染；两列表接口有限流。
- [ ] P4-L3：Hero 路由由 `SITE_*` 把关，前后端权限标识同步，文档同步。
- [ ] P4-L4：CSRF 死配置移除。
- [ ] P4-L5：客户端推荐接口邮箱部分掩码。
- [ ] P4-L6：报价接口使用命名限流器并降阈。

## 实施步骤

每步为独立可提交单元；全部完成后跑整体验证。

### 批次一（P1）

**1. M1 NAT 删除归属校验** — `backend/app/Services/ClientServiceConsole/ServiceNatService.php`
- `deleteNatForwardingForUser()` 在拼上游请求前断言 `$forwardingId` 属于 `$natContext['list']` 且对应项 `can_delete` 为 true，否则抛 `BusinessException('端口转发规则不存在或不属于当前服务', 42200)`。
- 不改 create 路径。删除仍以 `fresh=true` 解析最新列表，缓存陈旧风险不复存在。

**2. M2 工单回复引用批量预取与附件元数据去重复 stat** — `backend/app/Services/Ticket/TicketService.php`
- `v2Replies()` / `resolveTicketReplies()`：收集本批回复的 `quote_reply_id`（补上被引用回复中的 staff user_id 后并入现有 `AdminUser::whereIn` 一次查齐），`TicketReply::where('ticket_id')->whereIn('id', ...)` 一次取回被引用回复构建映射传入 `formatReply()`。
- `formatReply()` 签名改为接收映射上下文；被引用回复的发送者名直接用 `$staffMap` / `$clientName`（同工单，不再 `loadMissing('ticket.user')`）。确认 `formatReply` 全部调用点后收签名，不留旧分支。
- 附件：`attachments` JSON 已固化 `size/mime_type` 时直接组装（`SecureAsset::temporaryUrl` 只生成签名路由、不触碰文件系统）；JSON 缺失历史字段才回退 stat；`File::exists` 容错保留，失败仍剔除该附件。

### 批次二（P2）

**3. M4 移除发送端登录场景存在性判定** — `backend/app/Services/Auth/SendAccountCodeService.php`
- 删除 `sendPhoneCode()` / `sendEmailCode()` 中两个 `if ($purpose === 'login')` 块（存在性与禁用判定）。
- 与 `resetPassword` 发送链路行为完全一致：任意目标号照常限流（captcha + `MessageRateLimitService` 双闸）、照常发码落码；账号判定后移至 `loginByCode` / `resetPassword` 的统一文案分支。

**4. M5 收敛 `/ready` 明细**
- `backend/app/Http/Controllers/System/HealthController::ready()`：就绪返回 `{"status":"ready"}`（HTTP 200），未就绪仅 `status=not_ready` + HTTP 503，均不带 `checks`。
- 新增 `GET /api/v2/admin/system/readiness`（挂 `AdminPermissions::DATABASE_VIEW`，与 `/database/status` 聚合定位一致），返回完整 checks。
- 路由变更后运行 API 清单生成脚本；核对部署文档中探针是否解析 checks 字段（预期仅依赖 HTTP 状态码）。

### 批次三（P3）

**5. L1 用户列表恒空字段修复** — `UserService::list()` 补 select `company`、`qq`、`member_level_id`；`AdminUserListItemResource` 删除恒不生效的 `$profile` 分支（nickname/company/qq 直接取列值）。

**6. L2 公开内容摘要固化**
- 迁移（只新增）：`content_articles` 加可空 `excerpt` 列；新增共享的 excerpt 渲染 helper（模型或 Support 层），迁移回填历史行。
- `preparePayload()` 落库时生成；`PublishedContentSummaryResource::excerpt()` 改读 `summary ?: excerpt`，不再实时渲染 Markdown。
- 公开列表查询加 select 白名单排除 `content`（keyword 对 content 的 `LIKE` 过滤不受影响）；`routes/api.php` 给 `/v2/site/notices`、`/v2/site/help-articles` 列表接口补 `throttle:30,1`。
- 本地双库（idc、idc_test）各跑一次迁移。

### 批次四（P4，其中 L3 待产品确认后实施）

**7. L3 Hero 权限迁组**（推荐方案）：`v2-admin.php` 从 CONTENT_MANAGE/CONTENT_LIST 组移出两条 `/site/home-hero` 路由，新建 SITE_MANAGE（POST）、SITE_VIEW（GET）分组；`frontend-admin-v3` 同步权限标识；同步 `docs/参考资料/接口/API清单导航.md`。内置角色默认权限已含 `SITE_*`，超管与只读角色不受影响；自定义角色边界变化在发布说明标注。`ORDER_MANAGE` 加注释标记预留。备选方案：删除 `SITE_VIEW/SITE_MANAGE` 并保持现状——仅当产品确认不分权时采用。

**8. L4** — `bootstrap/app.php` 删除 `api/v2/callback/*` CSRF 例外，`validateCsrfTokens` 改无参调用并附一行注释说明 api 组不走 CSRF。

**9. L5** — 新增 `App\Support\EmailMasker`（格式 `首字符***@域名`），`ReferralController::rewards/directReferrals` 两处 email 输出套用；`NotificationService::maskEmail` 本轮不动。

**10. L6** — `AppServiceProvider` 注册 `RateLimiter::for('product-quote')`（IP 维度 10 次/分钟），路由改 `throttle:product-quote`。

## 风险与回滚

- **M1**：若上游主机存在本仓库解析列表之外的合法规则（如上游内置默认规则），新增校验会拒绝删除；通过观察业务异常日志确认，必要时放宽到仅 id 断言。
- **M2**：被引用回复可能不在当前分页内，映射必须全局 `whereIn` 取回；历史 `attachments` 缺字段走 stat 兜底，无破坏面。
- **M4**：输错手机号的用户等待短信不会到达；该体验取舍与重置密码链路现状一致。禁用账号会收到验证码但提交时报「账号已被禁用」，与密码通道信息暴露面相同。
- **M5**：仅当外部监控脚本依赖 `checks` 字段才会受影响，实施前核对部署与调度指南；回滚即还原 Controller 与路由两处。
- **L1/L2/L4/L5/L6**：均为低风险小改动；L2 迁移只增列不改列，回滚即停止读新列。
- **L3**：自定义角色授权边界变化不可自动回滚（存量 storedPermissions 数据），发布说明需明示。
