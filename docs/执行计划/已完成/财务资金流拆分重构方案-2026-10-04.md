# 财务资金流拆分重构方案（2026-10-04）

## 背景

`backend/app/Services/Finance/PaymentService.php` 已膨胀至 2797 行、79 个方法，充值、余额支付、在线支付、混合支付、冲正退款、网关款转余额、履约编排、管理员调整、状态机工具九类职责混居。三大危险耦合点：

1. **`handlePaidInvoice` 编排环**：PaymentService 构造器注入 InvoiceService（:56），InvoiceService 反向以 `app()` 现场解析调用 `handlePaidInvoice`（:1240）与 `syncProjection`（:1196）；ServiceRenewService 同样以 `app()` 延迟解析 `refundInvoiceToBalance`（:1626）。
2. **callback_raw 内嵌幂等标志是跨模块共享状态机**：`mix_payment`/`balance_amount`/`balance_restored`/`credited_to_balance` 等键写读方分散五处以上，口径漂移即资金重复退付。
3. **`handleGatewayNotify` 与 `completePaymentFromQuery` 为 130 行镜像双胞胎**，已各自独立演化。

同时发现三条资金主链路测试零覆盖：在线入账主链路（`handleGatewayNotify`/`completePaymentFromQuery`）、充值到账主链路（`completeRechargePayment`）、退款主流程（`refundInvoiceToBalance`，且无 HTTP 入口、仅续费冲正一处调用）。

## 与 zjmf-manger-decoded-main 对比结论

参照库为魔方财务 3.5.8 全解密版（`E:\caiwu\zjmf-manger-decoded-main`，ThinkPHP 5 + ThinkCMF，2925 个 PHP 文件）。同为 invoice 主体模式（订单仅是商品容器，`orders.invoiceid` 指向账单；充值即 `type=recharge` 账单）。

**同构确认**：

| zjmf 证据 | caiwu 对应 |
|---|---|
| 中央入账 `OrderController::orderPayHandle`（OrderController.php:29-136，账单回调+充值到账合一分派） | `handleGatewayNotify:968` 充值分派 |
| 按 invoice_item type 分派后处理的 `processPaidInvoiceFinal`（common/logic/Invoices.php:323-492） | `handlePaidInvoice`/`provisionPaidInvoice` 类型分派 |
| `credit_log` 带 `balance` 快照列 | `account_transactions.balance_after` 已具备 |
| `public/plugins/gateways` 网关插件化 + `shook` 分发 | `plugins/gateways` + `PaymentGatewayInterface` |

**新硬约束（源自 zjmf 病根）**：

1. **资金写入点不得增加**：zjmf 资金入账四件套（插流水+改账单+动余额+日志）在 6+ 处复制（OrderController.php:69-116、PayController.php:386-405、admin InvoiceController.php:258-275 等）且幂等边界各不一致，是其最大病根。拆出的每个新类：写余额仍唯一经 AccountService，写台账仍唯一经 FinanceLedgerWriter，禁止新类内直写。
2. **幂等与锁不得降级**：zjmf 回调防重靠 check-then-insert 且 `accounts.trans_id` 非唯一索引（并发双入账窗口）、插流水在事务外失败手工补偿、全库零锁。本重构 13 处命名锁 + 悲观行锁 + 幂等闸 + UNIQUE 约束原样保留。

**明确不抄**：单一 accounts 大流水表合并（表结构变更超范围）；amount_out 负流水替代 refunds 表（caiwu refunds+红字账单已结构化）；`description LIKE` 字符串对账。

## 目标架构（智囊团收敛方案 A）

新增 10 类 + 1 trait，全部平铺在 `backend/app/Services/Finance/`，PaymentService 最终删除、不留门面（门面即工作规则禁止的兼容层）：

| 新类 | 承接方法（79 方法全覆盖） |
|---|---|
| `RechargePaymentService` 充值流 | rechargeByGateway、queryRechargeStatus、cancelExpiredPendingRecharge(+ForUser)、completeRechargePayment、ensureRechargeInvoiceProjection、rechargeGatewayContext/ContextKey/MatchesGatewayContext/CallbackRaw、assertVerifiedUser、adjustBalance；recharge() 死入口删除 |
| `BalanceInvoicePaymentService` 余额流 | payByBalance、payOrderByBalance、resolveOrderPayableAmount、isAutoRenewBalancePayment、closeOtherPendingPaymentsForOrder |
| `GatewayInvoicePaymentService` 在线流 | payByGateway、handleGatewayNotify（保留验签/商户号/金额闸/recordPaymentCallback/充值分派）、queryGatewayPaymentStatus（保留 3 秒微缓存）；completePaymentFromQuery 拆入引擎 |
| `MixPaymentService` 混合流 | payByBalanceAndGateway、restoreReservedMixBalance、restoreConflictingMixBalancesForCapturedPayment、creditCapturedPaymentToBalance、resolveMixBalanceAmount；invoicePayableAmount 复制私有副本（避免 Mix↔引擎互依成环） |
| `InvoiceRefundService` 冲正退款流 | refundInvoiceToBalance、resolvePrimaryRefundablePayment、resolveBalanceRefundableAmount、invoiceCreditedToBalanceAmount、invoiceHasBalancePayment、remainingRefundableAmount、completedRefundAmount、markInvoiceRefunded、resolvePaymentGatewayLabel |
| `InvoiceSettlementService` 统一入账引擎 | 新方法 settleCapturedGatewayPayment（双胞胎合一四分支）+ closeOtherPendingPayments、cancelExpiredInvoiceAfterCapturedPayment、cancelLinkedPendingOrderForInvoice、recordSuccessfulInvoicePayment |
| `InvoicePaidOrchestrator` 履约编排 | handlePaidInvoice、3 个 Job 入口、provisionPaidInvoice/provisionPaidOrder 等 10 个私有履约/通知方法 |
| `FinanceLedgerWriter` 台账唯一写口 | createBalanceLog、resolveAccountTransactionSourceType |
| `PaymentCallbackProjector` 回调投影 | syncProjection、recordPaymentCallback、resolveCallbackVerified、nullableString、encodeJson |
| `PaymentCallbackRaw` 幂等闸收口（final 静态工具） | 八键常量化+读写收口；closed_reason 等纯审计键不收口 |
| `PaymentGatewayFlow` trait 共享网关工具 | withLock、resolveTraceId、gatewayOperations、resolveGateway、precreateGatewayPayment、queryGatewayPayment、timeout 三件套等 12 方法 |

依赖方向单向无环：外部调用方→五流服务；Gateway→引擎/Mix/Recharge/Orchestrator；Balance→引擎；引擎→Mix；ServiceRenewService→InvoiceRefundService（构造器注入替换 app()）；InvoiceService→Orchestrator+Projector（替换两处 app()）。两条新边若容器冒烟出环则该边回退 app()+中文注释论证。

## 关键红线

- 资金写入点不得增加（zjmf 教训）：余额写唯一经 AccountService、台账写唯一经 FinanceLedgerWriter、单据写唯一经 FinanceDocumentService。
- 幂等与锁不得降级（zjmf 教训）：锁键原样、幂等闸原样、UNIQUE 约束不动。
- 引擎合一五差异参数化而非抹平：notify 用原始 gateway 锁键、query 用消毒后 safeGateway，合并成"都消毒"=改并发行为=违规。
- 充值到账 completeRechargePayment 不进引擎（无账单 PAID 投影、独立幂等补账单分支）。
- 测试只改目标类名不改断言；删死代码前 git grep 确认零调用。
