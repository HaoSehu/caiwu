# 宝塔部署项目指南

面向全新服务器的完整部署流程。已有生产环境运维请直接看 [部署与调度指南.md](部署与调度指南.md)。

---

## 一、前置环境

### 1.1 宝塔面板安装

宝塔面板需已安装。未安装参考官方文档，推荐 Linux 系统（CentOS 7+ / Ubuntu 20.04+ / Debian 10+）。

登录宝塔面板后，进入**软件商店**安装以下运行环境：

| 软件               | 版本要求   | 说明               |
| ------------------ | ---------- | ------------------ |
| Nginx              | 1.20+      | Web 服务器         |
| PHP                | 8.2 或 8.3 | 项目要求 PHP 8.2+  |
| MySQL              | 8.0        | 数据库             |
| Redis              | 7.0+       | 缓存               |
| phpMyAdmin         | —          | 数据库管理（可选） |
| Node.js 版本管理器 | —          | 管理 Node.js 版本  |

### 1.2 PHP 关键配置

**安装 PHP 扩展**（宝塔 → 软件商店 → PHP → 设置 → 安装扩展）：

| 扩展        | 是否必需 | 用途                                                           |
| ----------- | -------- | -------------------------------------------------------------- |
| `fileinfo`  | 必需     | 上传文件的 MIME 类型识别（`league/mime-type-detection`）       |
| `redis`     | 必需     | 缓存与队列（`config/database.php` 默认使用 `phpredis` 客户端） |
| `pdo_mysql` | 必需     | 数据库连接                                                     |
| `opcache`   | 建议     | 生产环境性能；不装不影响功能                                   |

Laravel 框架硬依赖的 `ctype`、`filter`、`hash`、`mbstring`、`openssl`、`session`、`tokenizer` 在宝塔各 PHP 版本中默认已编译进核心，无需额外安装。项目不使用 `bcmath`、`intl`、`zip`、`curl`、`gd`、`imagick`，不需要装。

**禁用函数：在面板里删掉 `proc_open` 和 `putenv` 两项，其余全部保留。**

宝塔 → 软件商店 → PHP → 设置 → 禁用函数，列表每行右侧有「删除」按钮：

| 函数        | 处理             | 原因                                                                                                                                                                                                                                                                                    |
| ----------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `proc_open` | **删除（放开）** | `php artisan schedule:run` 派发每个调度事件、`queue:drain` 拉起 4 个 worker 都走 `Symfony\Component\Process`；被禁用时直接抛 `LogicException: The Process class relies on proc_open`                                                                                                    |
| `putenv`    | **删除（放开）** | 只有 `composer install` 需要：Composer 启动时其 xdebug-handler 无条件调用 `putenv()` 且没有 `function_exists` 保护，被禁用会直接 `Fatal error: Call to undefined function ...putenv()`；`php artisan` 与队列不受影响（Symfony Console 里的 `putenv()` 都包在 `function_exists` 判断中） |

其余函数一律保留禁用，**不要清空整个列表**：

- `symlink`：项目与 Composer 都不需要（`vendor/bin` 下是普通 PHP 脚本，不是符号链接）。
- `exec`、`shell_exec`、`system`、`passthru`、`popen`、`pcntl_exec`：项目代码里没有任何调用点，全部保留禁用即可（`vnc:ensure-relay` 也已改用 `Symfony\Component\Process` 拉起 Relay，不再依赖 `popen`/`exec`）。
- 不同宝塔版本、不同 PHP 版本的默认清单不一样（有的版本默认就没有 `proc_open`）。以面板实际列表为准：有就删，没有就跳过，不要为了「对齐清单」手工往 `disable_functions` 里塞函数。

> 面板改的就是 `php.ini`，FPM 与 CLI 共用同一份配置，所以这两项放开后在两边同时生效。这正是本项目需要的：调度与队列都在 CLI 跑，`proc_open` 用于 `schedule:run` 派发调度事件、`queue:drain` 拉起 worker；`composer install` 则依赖 `putenv`。管理端「导出数据库备份」已改为队列任务，`mysqldump` 同样由 CLI worker 执行，不在 FPM 请求内跑，因此放开并不是为了 Web 侧的长进程。

保存后必须重启 PHP（宝塔 → PHP → 重启），否则正在运行的 FPM 进程仍用旧配置。

**验证**（把 `php` 换成面板实际版本的绝对路径，如 `/www/server/php/83/bin/php`）：

```bash
php --ini   # 确认 Loaded Configuration File 指向面板里那个 php.ini

php -r "var_dump(function_exists('proc_open'), function_exists('putenv'), extension_loaded('fileinfo'), extension_loaded('redis'), extension_loaded('pdo_mysql'));"
```

五项都应为 `true`。命令行用的 PHP 必须与站点同一个安装目录（宝塔 → 网站 → PHP 命令行版本）；解析到别的版本就会读到另一份 `php.ini`，禁用函数与扩展都对不上。

> 每次升级 PHP 小版本或重装 PHP 后，宝塔可能把 `disable_functions` 恢复成默认清单，需要重新检查这两项。

> **安全影响**：放开 `proc_open` 会削弱 PHP 的沙箱强度——一旦出现任意代码执行漏洞，攻击者可以派生系统进程。因此只放开这一项，而不是把清单清空。项目侧的补偿措施：上传目录由 Nginx 直接静态服务，`backend/app/Services/Content/MediaFileService.php` 的扩展名白名单不含 PHP；`proc_open` 的调用点都由 `Symfony\Component\Process` 以参数数组形式发起（如 `queue:drain` 用 `new Process([PHP_BINARY, base_path('artisan'), 'queue:work', ...])` 拉起 worker），不经过 shell，不存在命令拼接；唯一的字符串命令是 `vnc:ensure-relay` 的后台拉起，参数全部经 `escapeshellarg()` 转义。需要再收紧一层时，可在面板「配置修改」里设置 `open_basedir`，必须同时包含项目根目录与系统临时目录（`/tmp`），否则子进程写临时文件会失败。

### 1.3 Node.js 配置

在 Node.js 版本管理器中安装 **Node.js 20.19+**（项目 package.json 约束的最低版本）。

### 1.4 DNS、网络与账户

- 先为 `api`、`www`、`console`、`admin` 四个域名添加 DNS 记录，并确认都解析到同一台服务器。
- 防火墙只对公网开放 `80` 和 `443`；MySQL、Redis 和 VNC Relay 的 `8100` 仅监听内网或 `127.0.0.1`，不要对公网放行。
- HTTPS 部署前先在宝塔申请并绑定四个站点的证书。四个公开地址必须统一为 HTTP 或 HTTPS；生产环境应使用 HTTPS。
- 记录宝塔站点运行用户（通常为 `www`）。后续仅授予该用户 `backend/storage` 与 `backend/bootstrap/cache` 的写权限。

## 二、项目部署概览

生产拓扑如下：

```
宝塔 Nginx
  ├── 站点1: 官网/用户入口 -> frontend-user-v3-www/dist （静态）
  ├── 站点2: 用户控制台   -> frontend-user-v4-console/dist（静态）
  ├── 站点3: 管理端       -> frontend-admin-v3/dist      （静态）
  └── 站点4: 后端 API     -> backend/public              （PHP-FPM）
                              ├── MySQL 8
                              ├── Redis
                              └── 宝塔计划任务（每分钟 php artisan schedule:run）
```

**关键理解**：

- 后端只通过 PHP-FPM 运行，不使用 `php artisan serve`
- 没有常驻 Queue Worker，队列消费并入 `schedule:run`（每分钟）
- 四个站点独立部署，可分配不同的域名/端口

数据库发布有两条互斥路径：

| 场景                 | 执行入口                        | 说明                                                                                |
| -------------------- | ------------------------------- | ----------------------------------------------------------------------------------- |
| 空数据库首次部署     | `python3 scripts/install_db.py` | 导入 `database/schema/mysql-schema.sql`、执行增量迁移、写入默认配置并初始化管理员。 |
| 已有生产库发布新版本 | `php artisan db:upgrade --force` | 受控升级：自动全库备份、版本与迁移清单校验、执行迁移并写入升级账本；失败按恢复矩阵处理。 |

首次部署不要先手动执行 `php artisan migrate --force`，也不要对生产库使用 `install_db.py --reset`。`php artisan migrate` 仅用于隔离开发环境调试，产品升级统一走 `db:upgrade`。

## 四、宝塔站点与伪静态配置

四个站点均使用宝塔创建时生成的默认 Nginx 配置。不要在“配置文件”中替换或粘贴完整 `server {}`，以免覆盖宝塔生成的 SSL、PHP-FPM 和日志设置。

在宝塔面板完成以下设置后，只编辑每个站点的“设置 → 伪静态”：

| 站点       | 运行目录                        | 宝塔面板设置                    |
| ---------- | ------------------------------- | ------------------------------- |
| 官网       | `frontend-user-v3-www/dist`     | 静态站点，申请 SSL。            |
| 用户控制台 | `frontend-user-v4-console/dist` | 静态站点，申请 SSL。            |
| 管理端     | `frontend-admin-v3/dist`        | 静态站点，申请 SSL。            |
| API        | `backend/public`                | 选择 PHP 8.2 或 8.3，申请 SSL。 |

HTTPS 跳转和证书通过宝塔“SSL”页面配置；纯 HTTP 环境不启用强制 HTTPS，并将 `SESSION_SECURE_COOKIE=false`。四个公开地址必须使用相同协议。

### 4.1 后端 API 站点伪静态

在 API 站点的“伪静态”完整填入：

```nginx
# VNC WebSocket 仅由 API 站点转发到内部 Relay。
location ^~ /ws/vnc {
    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade           $http_upgrade;
    proxy_set_header Connection        "upgrade";
    proxy_buffering off;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
    proxy_pass http://127.0.0.1:8100;
}

location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

项目未启用 VNC 远程控制时，可以删除 `/ws/vnc` 的整个 `location` 块，保留 Laravel 回退规则。宝塔默认 PHP 处理块保持不变。

### 4.1.1 可信代理（必须配置，否则按 IP 的限流与审计全部失效）

反代之后 `REMOTE_ADDR` 恒为反代地址。若不在应用侧声明可信代理，`$request->ip()` 会永远返回反代 IP，导致：

- 全站 `throttle:*`（含支付回调 60 次/分钟）退化为共用一个桶，攻击者打满即让真实回调被 429；
- 支付轮询凭证的客户端 IP 绑定形同虚设；
- 审计日志 IP 全为反代地址，追溯不可用。

在 `.env` 中按实际反代地址配置（多个用英文逗号分隔，只写反代/负载均衡自己的 IP，**不要**写 `0.0.0.0/0` 或 `*`）：

```dotenv
# 单机宝塔：Nginx 与 PHP-FPM 同机，反代地址即 127.0.0.1
TRUSTED_PROXIES=127.0.0.1

# 独立负载均衡：填 LB 的内网地址
# TRUSTED_PROXIES=10.0.0.10,10.0.0.11
```

改完执行 `php artisan config:cache`。验证方式：带 `X-Forwarded-For: 203.0.113.9` 请求任一 API，日志 `ip_address` 应为 `203.0.113.9` 而不是 `127.0.0.1`。

### 4.2 三个前端站点伪静态

官网、用户控制台和管理端都是 Vue History 路由站点。在三个前端站点的“伪静态”中均填入同一段：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

不要在三个前端站点添加 `/api`、`/uploads`、`/media` 或 `/ws/vnc` 的代理。浏览器直接访问 API 域名；`/vnc/vnc.html` 是控制台的静态构建产物，会由该规则直接命中。

### 4.3 非伪静态项

- SSL 证书、强制 HTTPS 和站点根目录：宝塔“网站”页面设置。
- API 的 PHP 版本与 PHP-FPM：宝塔站点的 PHP 设置。
- 上传大小：在宝塔 PHP 设置中同时调整 `upload_max_filesize` 和 `post_max_size`；站点级 Nginx 上传限制仅在实际遇到 413 时通过面板提供的对应设置调整。
- 保存伪静态后使用宝塔的 Nginx 配置检查与重载功能；无需手工编辑 Nginx 配置文件。

## 五、后端部署

### 5.1 上传代码

将项目代码上传至服务器，例如 `/www/wwwroot/caiwu`。

推荐方式：

- **Git 克隆**：宝塔 → 软件商店 → Git 插件，或手动 `git clone`
- **宝塔文件上传**：压缩包上传后解压

### 5.2 配置 .env

```bash
cd /www/wwwroot/你的项目/backend
cp .env.example .env
```

编辑 `.env`，修改以下必填项：

```ini
APP_NAME="创欧云"
APP_ENV=production
APP_DEBUG=false
APP_KEY=                            # 首次初始化脚本会在为空时生成
APP_URL=https://api.你的域名.com
FRONTEND_URL=https://www.你的域名.com
CLIENT_CONSOLE_URL=https://console.你的域名.com
ADMIN_URL=https://admin.你的域名.com
CLIENT_SESSION_COOKIE_DOMAIN=.你的域名.com   # 生产预检要求与 SESSION_DOMAIN 一致
SESSION_DOMAIN=.你的域名.com                 # 后端会话 Cookie 所属域
SESSION_SECURE_COOKIE=true
INSTALL_ADMIN_PASSWORD=请设置至少12位强密码

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=你的数据库名
DB_USERNAME=你的数据库用户
DB_PASSWORD=你的数据库密码

CACHE_STORE=redis
QUEUE_CONNECTION=database
SESSION_DRIVER=file

REDIS_HOST=127.0.0.1
REDIS_PASSWORD=你的Redis密码
```

`INSTALL_ADMIN_PASSWORD` 是首次初始化默认管理员所需的临时配置；生产环境不能为空、不能使用默认值且长度至少为 12 位。请通过受控渠道保存它，不要提交 `.env` 或把实际密码写入计划任务、Git 或本文档。

`.env.example` 未包含的键（`CLIENT_SESSION_COOKIE_DOMAIN`、`SESSION_DOMAIN`、`INSTALL_ADMIN_PASSWORD` 等）需手动追加。

`FRONTEND_URL`、`CLIENT_CONSOLE_URL`、`ADMIN_URL` 由后端读入 CORS 白名单（`config/cors.php`），跨子域共享登录态时后端会话 Cookie 的所属域由 `SESSION_DOMAIN` 决定；`CLIENT_SESSION_COOKIE_DOMAIN` 供生产预检脚本校验用，要求与 `SESSION_DOMAIN` 一致。这些地址只服务于后端 API，**不参与前端构建**——前端访问的 API 与站点地址来自各前端目录自己的构建 `.env`（见 6.1）。

### 5.3 安装后端依赖

```bash
cd /www/wwwroot/你的项目/backend

# 安装依赖（生产环境跳过 dev）
composer install --no-dev --optimize-autoloader
```

### 5.4 初始化空数据库

仅对尚未承载业务数据的空数据库执行。脚本会在缺少时生成 `APP_KEY`，然后导入 schema baseline、执行增量迁移、初始化默认配置和管理员：

```bash
cd /www/wwwroot/你的项目/backend
python3 scripts/install_db.py
```

不要额外执行 `php artisan key:generate` 或首次 `php artisan migrate --force`；上述脚本已按正确顺序完成这些步骤。脚本使用的数据库账户需要有创建目标库、导入表结构和执行迁移的权限。

### 5.5 发布到已有数据库

对已有生产数据库，先完成可恢复的备份，再执行：

```bash
cd /www/wwwroot/你的项目/backend

# 先看状态（退出码 2 = 有活要干，不是命令坏了）
php artisan db:upgrade-status

# 受控升级：自动备份 + 版本校验 + 执行迁移 + 写升级记录
php artisan db:upgrade --force

# 清缓存并生成生产缓存
php artisan optimize:clear
php artisan config:cache && php artisan route:cache
```

升级入口、失败恢复矩阵与迁移开发规则见 [数据库升级规范](../数据库/数据库升级规范.md)。

不要在生产库上使用 `migrate:fresh`、`migrate:reset` 或 `install_db.py --reset`。

### 5.6 设置文件权限

```bash
cd /www/wwwroot/你的项目/backend
sudo chown -R www:www storage bootstrap/cache
sudo chmod -R 775 storage bootstrap/cache
sudo chmod -R 775 public/uploads public/media
```

### 5.7 重启 PHP

宝塔面板 → 软件商店 → PHP → 重启，使生产缓存生效。

## 六、前端部署

### 6.1 配置前端构建地址

三个前端（官网、控制台、管理端）构建时读取各自目录下的 `.env`（均不入库），**不从 `backend/.env` 读取任何地址**。部署前为每个前端目录创建 `.env` 并填写生产值：

| 前端目录 | 关键变量（以实际代码读取为准） |
| --- | --- |
| `frontend-user-v3-www` | `VITE_API_BASE_URL`、`VITE_PUBLIC_SITE_URL`、`VITE_CONSOLE_SITE_URL` |
| `frontend-user-v4-console` | `VITE_API_BASE_URL`、`VITE_PUBLIC_SITE_URL` |
| `frontend-admin-v3` | `VITE_API_BASE_URL` |

- `VITE_API_BASE_URL` 需包含 `/api` 前缀，例如 `https://api.你的域名.com/api`
- `VITE_PUBLIC_SITE_URL` / `VITE_CONSOLE_SITE_URL` 为对应站点完整地址
- 跨子域共享登录态时，各端还须配置 `VITE_SESSION_COOKIE_DOMAIN=.你的域名.com`，与 `backend/.env` 的 `SESSION_DOMAIN` 一致
- 缺项或填错会让产物指向错误地址；本地开发各端读取 `.env.dev`，互不影响

### 6.2 构建前端

确保 Node.js 版本满足要求后，在项目根目录只安装一次 workspace 依赖并统一构建：

```bash
cd /www/wwwroot/你的项目

# 只预览构建目标，不实际构建、不校验任何地址。
npm run build:frontends -- --dry-run

npm ci
npm run build:frontends
# 产物仍分别位于三个前端目录的 dist/，不会写入 backend/public。
```

> 静态资源默认以根路径 `/` 发布。构建脚本会注入 `VITE_ADMIN_ASSET_BASE_URL` / `VITE_CONSOLE_ASSET_BASE_URL` / `VITE_WWW_ASSET_BASE_URL` 为 `/`，且该注入优先于各端 `.env` 的同名配置，因此当前不能通过这三个变量配置 CDN 域名；如需 CDN 发布，在各前端目录直接执行 `npm run build`（读取各自 `.env`），或调整 `backend/scripts/build_frontends.mjs` 的注入逻辑。

### 6.3 验证站点

构建完成后，在浏览器中分别访问四个站点域名，确认页面正常加载，API 请求正常。

## 七、计划任务配置

宝塔面板 → 计划任务 → 添加：

- **任务类型**：Shell 脚本
- **任务名称**：`Laravel 调度`
- **执行周期**：每分钟
- **脚本内容**：

```bash
cd /www/wwwroot/你的项目/backend
/www/server/php/83/bin/php artisan schedule:run >> /dev/null 2>&1
```

> 这条计划任务每分钟触发心跳，并行消费开通队列 `provision`、业务队列 `referral,notification,coupon,default` 与定时队列 `automation`。不要额外配置覆盖同一队列的 `queue:work`，避免重复消费。
>
> **这里必须写 PHP 绝对路径，不要写 `php`。** 宝塔计划任务的 Shell 环境 `PATH` 常指向系统自带的旧 PHP 或面板默认版本，一旦解析到别的安装目录，就会读到另一份 `php.ini`，`proc_open` 可能仍处于禁用状态。用 `php -v` 与 `/www/server/php/83/bin/php -v` 各跑一次确认是同一个版本。

同时在宝塔进程守护中常驻：

```bash
cd /www/wwwroot/你的项目/backend
/www/server/php/83/bin/php artisan vnc:relay
```

确认 `127.0.0.1:8100` 监听后再部署新代码；Relay 由守护进程自动重启，`vnc:ensure-relay` 仅用于手工健康检查。

进程守护与计划任务都必须使用同一份 PHP 绝对路径 `/www/server/php/83/bin/php`，保证与 API 站点的 PHP 版本、`php.ini` 完全一致。

## 九、常见问题

### 9.1 502 Bad Gateway

通常原因是 PHP-FPM 未运行或 API 站点未选中可用的 PHP 版本：

- 检查 PHP 是否启动（宝塔 → 软件商店 → PHP → 状态）
- 在 API 站点的“PHP 版本”中重新选择 PHP 8.2 或 8.3，然后重启对应 PHP 服务
- 不要手工修改宝塔生成的 `fastcgi_pass` socket 配置

### 9.2 页面刷新 404

前端 SPA 站点未配置 Vue Router History 模式的回退规则。在对应站点的 Nginx 配置中确保包含：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

### 9.3 Composer 报 `putenv()` 等函数未定义

说明当前 PHP 的 `disable_functions` 里还有 `putenv`。注意这与 `php artisan` 无关：Symfony Console 调用 `putenv()` 前都做了 `function_exists` 判断，禁用后只是跳过；真正会崩的是 Composer 内置的 xdebug-handler，它无条件调用 `putenv()`。处理顺序：

1. 先确认命令用的是哪个 PHP：`which php`、`php --ini`（看 `Loaded Configuration File` 指向哪个安装目录）。
2. 在宝塔 → PHP → 设置 → 禁用函数中，删掉 `putenv` 与 `proc_open` 两项并保存，然后重启 PHP（见 1.2 节）。
3. `php -r "var_dump(function_exists('putenv'), function_exists('proc_open'));"` 两项都应为 `true`。
4. 若面板里已经没有这两项、命令行仍报错，说明命令行解析到了另一个 PHP 版本：用 `which php` 看路径，再把计划任务与进程守护改成该版本的绝对路径。

`symlink` 不需要放开：Composer 与项目代码都不使用它。也不要为了绕开报错清空整个禁用函数列表。

### 9.3.1 计划任务跑了但队列不动 / `schedule:run` 显示 DONE 却没效果

这是 `proc_open` 仍被禁用的典型表现。Laravel 的 `ScheduleRunCommand` 捕获每个事件的异常后只写日志、不改退出码，所以终端上仍是 4 条 DONE、退出码 0，实际什么都没执行。

排查：

```bash
cd /www/wwwroot/你的项目/backend

# 1. 事件根本没起来的话，这里能看到 Process 的 LogicException
tail -n 100 storage/logs/laravel.log | grep -i "proc_open\|Process class"

# 2. 直接确认 CLI 侧 proc_open 可用
/www/server/php/83/bin/php -r "var_dump(function_exists('proc_open'));"

# 3. 绕过调度器直接跑队列，应当输出 status=drained
/www/server/php/83/bin/php artisan queue:drain
```

若第 2 步为 `false`，回到 1.2 节在面板里删掉 `proc_open`，保存后重启 PHP，再确认命令行的 `php` 与站点是同一个安装目录。

### 9.4 上传文件过大

在宝塔“PHP → 配置修改”中同时增大 `upload_max_filesize` 和 `post_max_size`，并重启 PHP。若仍返回 HTTP 413，在宝塔站点设置中调整上传限制；不要为了这一项替换完整 Nginx 配置。

### 9.5 定时任务未执行

- 检查宝塔计划任务日志是否正常
- 执行 `php artisan schedule:run` 手动测试
- 确认 `.env` 中 `QUEUE_CONNECTION=database`、`CAIWU_BUSINESS_QUEUES` 和 `CAIWU_SCHEDULE_QUEUE` 配置正确，且 `127.0.0.1:8100` 有独立 Relay 进程监听

### 9.6 路由或配置更新不生效

上线后依次执行：

```bash
cd /www/wwwroot/你的项目/backend
php artisan route:clear && php artisan config:clear && php artisan cache:clear
php artisan route:cache && php artisan config:cache
```

然后重启 PHP-FPM（宝塔 → PHP → 重启）。
