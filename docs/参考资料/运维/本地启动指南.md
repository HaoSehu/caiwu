# 启动指南

## 环境要求

- PHP 8.2+
- Composer
- MySQL 8
- Redis
- Node.js 20.19+（`frontend-admin-v3` 与 `frontend-user-v4-console` 的 package 约束）

本地联调统一使用 `127.0.0.1`，不要混用 `localhost`。

### 数据库连接口径

本地开发**连接的是开发环境数据库**（`backend/.env` 的 `DB_HOST`/`DB_DATABASE` 指向开发库），不是生产库：

- `docs/DATABASE.md` 由 `php backend/scripts/export_database_structure.php` 按当前 `.env` 直连导出，默认反映开发环境库结构。
- 需要对照生产库结构时，在指向生产库的 `.env` 下单独重跑该脚本，不要手工编辑 `docs/DATABASE.md`。
- 本地不要对生产库执行迁移、初始化或 `--reset`；生产升级统一走 `db:upgrade`（见[数据库升级规范](../数据库/数据库升级规范.md)）。

## 后端

```bash
cd backend
composer install
php artisan key:generate
php artisan migrate      # 仅本地开发直接建表；生产升级走 db:upgrade
php artisan app:serve
```

> 生产与预发布环境的数据库升级统一使用 `php artisan db:upgrade`，见[数据库升级规范](../数据库/数据库升级规范.md)。

### 缓存与 Redis 配置

本地开发默认 `CACHE_STORE=file`（`.env` 中配置），单进程运行时足够。

**生产环境必须设置 `CACHE_STORE=redis`**：

- 分布式锁（`Cache::lock`）在 file 驱动下不支持跨进程互斥
- 支付回调、订单创建、返利计算等关键业务依赖 Redis 锁保证幂等
- Redis 不可用时这些操作可能并发冲突导致数据错误

检查 Redis 是否运行：

```bash
redis-cli ping  # 应返回 PONG
```

`php artisan app:serve` 是本项目本地后端统一入口，会拉起 Laravel HTTP、VNC Relay 和业务队列 Worker。不要用 `php artisan serve` 替代。

需要本地同时带调度时，建议让 Relay 独立运行：

```bash
cd backend
php artisan app:serve --with-schedule --without-vnc
php artisan vnc:relay
```

带调度时，`app:serve --with-schedule --without-vnc` 不再另起业务队列 Worker；每分钟心跳会并行消费业务队列与 `automation` 队列，并为两类 Worker 分别加锁。Relay 单独进程退出不会影响 HTTP 和调度入口。

生产环境不使用 `app:serve` 常驻，PHP-FPM 指向 `backend/public`，宝塔每分钟执行：

```bash
cd backend
php artisan schedule:run
```

## 前端

推荐在仓库根目录使用 npm workspace 脚本：

```bash
npm run dev:admin-v3
npm run dev:user-v3-www
npm run dev:user-v4-console
```

也可以进入子项目：

```bash
cd frontend-admin-v3
npm run dev

cd frontend-user-v3-www
npm run dev

cd frontend-user-v4-console
npm run dev
```

当前真实前端目录：

- `frontend-admin-v3`：管理端，TDesign Vue Next，默认端口以 Vite 配置为准。
- `frontend-user-v3-www`：官网与用户入口，TDesign Vue Next。
- `frontend-user-v4-console`：新版用户控制台，TDesign Vue Next。
- `app_flutter`：Android 原生 App，Flutter + TDesign Flutter，**不入根 npm workspace**，需要单独的 Flutter SDK。
- `shared`：跨端共享包。

## Android App（`app_flutter`）

前置：

- Flutter SDK ≥ 3.32（本仓库验证 Flutter 3.47.9 / Dart 3.13.7）
- Android SDK（compileSdk 36）与 JDK 17+
- 本机后端：`backend/` 执行 `php artisan app:serve`

国内镜像与 JDK 环境变量（示例，按本机路径调整）：

```bash
export JAVA_HOME="C:/Program Files/Amazon Corretto/jdk21.0.13_0"
export PATH="/d/dev/flutter/bin:$PATH"
export PUB_HOSTED_URL="https://pub.flutter-io.cn"
export FLUTTER_STORAGE_BASE_URL="https://storage.flutter-io.cn"
```

启动：

```bash
cd app_flutter
flutter pub get

# 模拟器默认指向宿主机 10.0.2.2:8000
flutter run --dart-define=API_BASE=http://10.0.2.2:8000/api

# 真机改局域网地址
flutter run --dart-define=API_BASE=http://192.168.x.x:8000/api
```

VNC 功能需要后端 relay 放行 App Origin（默认值两端已对齐，自定义时同步改）：

```env
# backend/.env
VNC_RELAY_APP_ORIGINS=caiwu-app
```

App 端对应变量为 `--dart-define=VNC_ORIGIN=https://your-origin`，且 `php artisan vnc:relay` 需在运行（`app:serve` 默认会拉起；单独运行见[部署与调度指南](部署与调度指南.md)）。

## 构建与验证

```bash
# 全部当前前端
npm run build:frontends
npm run typecheck:frontends
npm run verify:frontends

# 单项目
npm run build:admin-v3
npm run build:user-v3-www
npm run build:user-v4-console

# Android App（独立工程，不走上列 npm 脚本）
cd app_flutter && flutter analyze && flutter test && flutter build apk --debug
```

文档或配置类改动至少自检内容是否与当前目录、脚本和代码一致。

## 数据库初始化与迁移

初始化新库和旧库迁移属于高影响操作，不由代理自动执行：

```bash
python backend/scripts/install_db.py
python backend/scripts/migrate_legacy_dump.py --dump "你的dump文件.sql" --dry-run
python backend/scripts/migrate_legacy_dump.py --dump "你的dump文件.sql"
```

执行前必须确认目标库、备份和 `.env`。
