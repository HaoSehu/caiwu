# 媒体库远程存储插件方案

- 适用范围：媒体库的存储层（上传落盘、删除、URL 生成）、`addons` 域四个存储插件、本地与远程共存及双向迁移。
- 关联规格：无。媒体库当前没有独立产品规格文档，行为以代码与 [DATABASE.md](../../DATABASE.md) 的 `media_files` 定义为准。
- 关联计划：[媒体库远程存储插件-2026-10-28.md](../../执行计划/进行中/媒体库远程存储插件-2026-10-28.md)。实施步骤、迁移字段、接口与时序留在该计划，本文只回答「为什么这样做、边界在哪、为什么不选别的」。

## 背景与问题

### 现状（逐条带锚点，均取自实际代码）

1. **上传写死本机磁盘**：`backend/app/Services/Content/MediaFileService.php:82-124`。`:86` `public_path(self::MEDIA_ROOT)` 定根目录，`:87` 建目录，`:89` `guardDiskSpace()` 卡磁盘余量，`:94` `$file->move()` 把文件搬进 `public/media`，`:109-119` 再写 `MediaFile::create()`。没有任何注入点、策略或磁盘选择。
2. **删除只处理本地文件**：`:175-186`。`:177` 用 `resolvePublicUploadPath()` 反解绝对路径，`:179-181` 命中且 `is_file()` 才 `@unlink`，`:183` 删行。文件不在本地时静默跳过——远程对象不会被删除。
3. **全仓没有存储抽象**：`backend/app` 下 `Storage::` 零命中；`backend/config/filesystems.php` 只有 `local`（`:7-12`）与 `public`（`:14-20`）两个 disk，且 `:10` 注释写明「不注册 /storage/{path} 路由：业务代码零 Storage:: 使用，开放即是无中间件暴露面」。Laravel 的 filesystem 抽象在当前架构里是**未被使用的能力**，不是既有通道。
4. **URL 依赖「文件真实存在」**：`backend/app/Support/UploadUrl.php:13-39`。空串返回 `null`；`http(s)` 开头的绝对地址走 `:21-31`，只有在命中托管前缀（`/media/`、`/uploads/`，见 `:48-53`）**且** `uploadedFileExists()`（`:41-46`，本质是 `is_file(public_path(...))`）为真时才改写，否则**原样返回**；非 http(s) 且不命中托管前缀同样原样返回（`:34-36`）。

### 问题陈述

- **容量与可用性绑死单机磁盘**：媒体文件与代码同机，磁盘写满会直接让上传失败（`guardDiskSpace()` 就是为这条写的）。
- **无法按文件或按分组分流**：首页视频、文章封面、品牌素材全部落在同一目录、同一条规则下。
- **迁移只能人工**：把历史文件搬到对象存储，需要手工下载、上传、改库、改引用，没有可重复执行的通道。
- **没有一个既能接远程、又不改本地既有行为的落点**：三个直接后果——要么改造 `upload()` 全路径（回归面覆盖全部本地逻辑），要么在外部旁路（必然出现两套不一致的 `media_files` 语义）。

## 目标与非目标

- **目标**
  1. 媒体库支持可插拔的远程存储，新增厂商只加一个插件目录，不改媒体库核心。
  2. 本地与远程**共存**：可按单个文件、按分组策略、按全局默认三级决定落哪。
  3. 提供双向**一键迁移**：本地→远程、远程→本地，分批执行、进度可见、失败可续。
  4. 本地存储的既有行为**逐字不变**：文件名规则、磁盘守卫、URL 生成、重扫、引用检查、缓存失效时机全部照旧。
  5. 四个插件（FTP / 七牛云 / 腾讯云 COS / 阿里云 OSS）共用一套契约、一套目录约定、一套配置结构。
- **非目标**（每条附理由）
  1. **不新增第八个插件域**：`backend/app/Services/Integrations/Plugins/PluginDomain.php:23` 定义 `ADDONS = 'addons'`，`:79` 是白名单映射；`addons` 就是「功能扩展」，加域等于改插件体系本身。
  2. **不引入 Flysystem / AWS SDK**：`backend/composer.json` 的 require 只有 `laravel/framework`、`laravel/sanctum`、`laravel/tinker`，仓库当前零存储依赖；引入即扩大升级与安全面（取舍见「备选方案与取舍」）。
  3. **不做插件市场与在线安装包**：插件仍从磁盘目录扫描安装（`PluginScanner` / `PluginInstaller`），不做 zip 下载与执行。
  4. **不允许插件注册路由、菜单、权限码、迁移、调度**：`docs/参考资料/集成/插件/README.md:613-620` 的安全边界；`addons` 域尤为严格（`:17`）。
  5. **不改管理端既有媒体库交互**：`frontend-admin-v3/src/pages/content/media-library.vue` 的列表、上传、删除、重扫保持原样；驱动选择与迁移面板是增量入口。

### 共存与迁移的结论（实施细节见计划）

- **三级选择**：单文件（上传请求可选 `driver`）→ 分组策略（`settings` 的 `media` 组 `policy_json`）→ 全局默认（`item_key='storage_driver'`）。解析不到、值为空、插件未启用，一律回落 `local` 并记 warning——远程不可用不得让媒体库不可用。详见计划 §2.1。
- **归属记录**：`media_files` 新增 `disk`（`varchar(24)`，默认 `'local'`）与 `object_key`（`varchar(500)` 可空，本地行为 `NULL`）。远程行 `path` 与 `url` **同值存完整外链**，`object_key` 存对象键。本地行的四个字段与今天完全一致。详见计划 §2.2。
- **双向迁移**：触发方式为管理端两个动作（`POST /v2/admin/media-migrations` 起批、`GET .../{id}` 轮询），范围三选一（全部 / 勾选 ids / 复用列表筛选），顺序固定「先上传→再改库→再删源」，`delete_source` 默认 `false`，失败只记 `failures[]` 不回滚已完成项。详见计划 §2.4。
- **一致性**：远程行 `path===url` 不变式 + 迁移前先跑与 `checkReferences()` 等价的查询，命中非 `settings` 与 `content_articles` 的引用即拦下人工裁决；迁移批次结束时 `Cache::forget('media:hero-videos:list')`。详见计划 §2.5。

## 关键约束

### 1. 配置与凭据从哪来

- **插件凭据**走插件配置表：`secret: true`（或 `type=password`，两者等价，README `:159`）的字段由 `PluginConfigRepository::encodeSecrets()` 加密落库（`PluginConfigRepository.php:381-388`，`Crypt::encryptString`），读取时 `resolvedConfig()`（`:24-36`）解密，管理端只回显 `secretPreviews()`（`:75-90`）的掩码，`revealSecret()`（`:117`）单独走限流路由。必填缺失由 `assertRequiredFields()`（`:236-254`）在保存时拦截。
- **媒体库策略**走 `settings` 组 `media`：`SettingService::getGroupSettings()/saveGroupSettings()`（`SettingService.php:130/171`）是既有出入口。注意 `isPluginOwnedSettingGroup()`（`:618-620`）对插件归属组有过滤，`media` 不属其中，**值域校验必须自己写**，不能指望通用设置层。
- **两条链路不得混用**：插件配置只存「怎么连」，`settings` 只存「用哪个」；任何一边缺失都应回落到 `local`，而不是报错阻断上传。

### 2. 插件运行时通道的现状（本方案最大的机制风险）

- `addons` 域**没有领域 adapter**：`PluginRuntimeRegistry::makeAdapter()`（`PluginRuntimeRegistry.php:728`）只服务五个契约，其余返回 `null`。因此存储插件不能被 `resolveEntries()`（`:466`）当作驱动解析。
- 可用通道是 `execute()`（`:81-124`）：校验域与标识（`:83-89`）→ 查插件并要求已启用（`:95-105`）→ 交给 `executePlugin()`（`:145`）组装 `domain/slug/key/action/payload/config/context`。宿主可直接 `execute('addons', 'ftp', 'storage.put', [...])`。
- 但 `docs/参考资料/集成/插件/README.md:17` 原文是「受控 addon action 通道**未开放**，不要声明 admin/client/public entry」，`backend/plugins/addons/demo_style/config.php:24-27` 的注释也写明「受控 addon action 通道如未来立项，须带权限码、白名单与审计后再恢复」。**结论**：本方案把「宿主在服务层直调 `execute()`」作为路径（与 `IntegrationPluginService::testEmail()`（`:226`）与 `testSms()`（`:248`）的既有写法同构），但「action 白名单、审计落点、是否对外开放为管理端入口」必须另行裁决，登记为 P-11。

### 3. 插件能力声明的限制

- `requires` 只接受 `core` 与 `php`：`PluginCompatibility.php:21-26` 的 `SUPPORTED_KEYS`，`:53` 对其它键直接抛错。**不能声明 `ext-ftp`**，替代做法是插件运行时 `function_exists('ftp_connect')` 自检，缺失即返回 `dependency_missing` 的中文失败。
- `capabilities` 当前只有 `upstream` 域被消费（README `:86-96`）。存储插件声明 `media.storage` 仅作自描述，**不能指望平台据此启用行为**。
- `info.extra.driver_binding` **不声明**：四个插件同时启用时同一个 `binding_key` 会互相覆盖（`PluginInstaller::syncDriverBinding()` 的 identity 不含 `plugin_id`）。当前用哪个驱动由 `settings` 承载。

### 4. 远程不可用时的失败与回退

| 场景 | 行为 |
| --- | --- |
| 上传时远程写入失败 | `upload()` 抛出可读中文错误，**不建 `media_files` 行**，不产生半条记录 |
| 远程写入成功但建行失败 | 记 error 日志并尽力 `storage.delete` 清理孤儿对象；清理失败也不阻塞响应，交由只读审计命令报告 |
| 删除时远程返回对象不存在 | 按成功处理（`missing=true`），继续删库行；远程返回连接级失败则**保留库行**，让管理员重试 |
| 插件被禁用但库中仍有该驱动的行 | 列表与预览照常（`path` 是完整外链，`UploadUrl::resolve()` 原样透传），**不 500**；迁移与再次上传时回落 `local` |
| `settings` 策略指向已卸载的 slug | 保存时拒绝（P-12 明确校验落点）；历史脏值运行时回落 `local` 并记 warning |
| 回退 | **禁用插件即回到纯本地**：解析链在插件未启用时直接返回 `local`，无需回滚数据 |

### 5. 必须保持不变的既有行为（7 条）

1. 本地文件名生成规则：`MediaFileService.php:91` 的 `sprintf('%s_%s_%s.%s', prefix, His, Str::random(8), extension)`。
2. `guardDiskSpace()` 只在本地分支执行，语义与阈值不变（`:495-508`）。
3. `checkReferences()` 的匹配字段与中文文案（`:209-211`、`:223-225`）。
4. `reindexMediaDirectory()` 只扫 `public/media`、只认 `/media/%`（`:235-244`）。
5. hero-videos 缓存失效时机：仅在创建/删除/重扫新增后调 `bustHeroVideoCache()`（`:121`、`:185`、`:288-290`）。
6. 两个托管前缀 `/media/` 与 `/uploads/`（`UploadUrl.php:48-53`）。
7. 管理端 5 条媒体库路由的路径、方法与权限码：`backend/routes/v2-admin.php:350-352` 的写操作走 `CONTENT_MANAGE`，`:360-361` 的读操作走 `CONTENT_LIST`；常量定义在 `backend/app/Support/AdminPermissions.php:135`（`'content.list'`）与 `:137`（`'content.manage'`）。

## 四个插件的设计方案

### 共同契约（四插件一致，逐插件不重复）

- **目录**：`backend/plugins/addons/{ftp,qiniu,tencent_cos,aliyun_oss}/`，结构为 `{Name}Plugin.php`（入口，命名空间根部）+ `config.php` + `lib/{Name}Client.php`（唯一外部 IO）+ `lib/{Name}Signer.php`（纯函数可单测）+ `lib/{Name}Support.php` + `logic/{Name}.php`（`execute()` + `match` 分发）。依据 README `:23-34` 与 `:45`（入口类必须在插件命名空间根部）。
- **入口契约**：`execute(array $request): array` + `healthCheck(): array`（被 `PluginRuntimeRegistry::healthCheck()`（`:647`）调用）；失败一律返回 `success=false` 加中文 `message` 与 `data.code`，不抛裸异常。
- **动作清单**（四家同名同义，宿主只认这六个）：`storage.test` / `storage.put` / `storage.get` / `storage.delete` / `storage.exists` / `storage.url`。
- **`storage.url` 的用途**：存储站点换域名或协议（http→https）后，按 `object_key` 与当前配置**现算外链**，不重传文件、不发网络请求。同一 `object_key` 与同一配置下，其结果必须与 `storage.put` 返回的 `url` 全等；`object_key` 归一规则（`resolveObjectKey` / `normalizeObjectKey` + `applyPrefix`）也必须与 `put` 完全一致。失败码两条：`object_key_invalid`、`public_domain_missing`（拼出的地址缺协议或无 host；COS/OSS 因有桶默认域名兜底，仅在该兜底也不可用时返回）。宿主侧入口是 `RemoteMediaStorage::url()`，供 `php artisan media:storage-rewrite-urls` 使用。
- **禁止项**：文件二进制**不得进 payload**——`executePlugin()` 会把 payload 写入 `integration_plugin_runtime_logs`（`PluginRuntimeRegistry.php:52` 的 `RUNTIME_META_MAX_BYTES = 16384`，截断且不脱敏）。只传本地绝对路径 + 对象键；`local_path` 由平台构造，插件侧用 `realpath` 复核必须位于 `public_path('media')` 或 `storage_path('app/tmp')` 之下且 `is_file()`。
- **统一配置键**（四家共有，位置固定）：`notice`（`type=notice`，不参与保存，README `:155`）、`object_prefix`（默认 `media`，不得以斜杠结尾）、`public_domain`（`type=url`）、`timeout`（`number`，5–120，默认 30）。校验分两层：字段级由 `assertRequiredFields()`（`PluginConfigRepository.php:236-254`）与前端 schema 渲染承担；语义级（域名可访问、桶存在、能否写入）由 `storage.test` 承担。
- **超时与体积**：`StoreMediaFileRequest` 限 `max:102400`（100MB）与 8 种 `mimetypes`（`backend/app/Http/Requests/Admin/V2/MediaFile/StoreMediaFileRequest.php:13-31`）——**单次请求上传，不分片**，与既有上传上限对齐。

### FTP 插件（`backend/plugins/addons/ftp/`）

**元信息与安装/启用**

`info`：`domain='addons'`、`slug='ftp'`、`key='ftp'`、`name='媒体库 FTP 存储'`、`version='1.0.0'`、`entry=FtpPlugin::class`、`capabilities=['media.storage']`、`extra=['requires'=>['core'=>'>=1.0.0']]`；不声明 `driver_binding`、不声明 `admin/client/public entry`。安装：目录放入 `backend/plugins/addons/` → `POST /v2/admin/integration-plugins`（`v2-admin.php:393`）→ `PUT .../{plugin}/config`（`:395`）填连接参数 → `PATCH .../{plugin}/status`（`:396`）启用。启用后媒体库驱动的候选列表才包含「FTP」。

**连接参数与校验规则**

| 字段 | 类型 | secret | 必填 | 校验规则 | 失败提示 |
| --- | --- | --- | --- | --- | --- |
| `host` | text | 否 | 是 | 非空 ≤190；不含协议前缀与路径 | 服务器地址不能为空 |
| `port` | number | 否 | 是 | 1–65535，默认 21 | 端口需在 1-65535 之间 |
| `username` | text | 否 | 是 | 非空 ≤100 | FTP 用户名不能为空 |
| `password` | password | **是** | 是 | 非空；空提交保留旧值 | FTP 密码不能为空 |
| `root_dir` | text | 否 | 否 | 以斜杠开头，不得含 `..`，默认 `/media` | 远端根目录必须以斜杠开头且不能含 `..` |
| `passive` | switch | 否 | 是 | 默认开 | — |
| `use_ssl` | switch | 否 | 是 | 默认关；开启走 `ftp_ssl_connect` | 服务器不支持 FTP over SSL |
| `public_domain` | url | 否 | 是 | `http(s)` 开头，无查询串、无结尾斜杠 | 外链域名必须是 http(s) 地址 |
| `object_prefix` | text | 否 | 否 | 默认 `media`，不得以斜杠结尾 | 对象前缀不能以斜杠结尾 |
| `timeout` | number | 否 | 是 | 5–120，默认 30 | 超时需在 5-120 秒之间 |

**上传 / 读取 / 删除如何对接媒体库**

| 动作 | 入参 | 成功返回 | 关键失败码 |
| --- | --- | --- | --- |
| `storage.test` | 无 | `ok` + `endpoint` + `root_dir` + `writable` + `latency_ms` | `connect_failed` / `auth_failed` / `mkdir_failed` |
| `storage.put` | `local_path` / `object_key` / `mime_type` / `content_length` | `object_key` / `url` / `size` | `connect_failed` / `upload_failed` / `size_mismatch` |
| `storage.get` | `object_key` / `target_dir` | `temp_path` / `size` | `not_found` / `download_failed` |
| `storage.delete` | `object_key` | `deleted` / `missing` | `connect_failed`（对象不存在按 `missing=true` 成功） |
| `storage.url` | `object_key` | `object_key` / `url` | `object_key_invalid` / `public_domain_missing` |

- 上传：拼 `root_dir` 与 `object_key` → 逐级建目录（已存在忽略）→ 二进制上传 → 回读 `ftp_size()` 与本地 `filesize()` 比对，不等即判失败并尽力删掉半个文件。
- 读取：**不代理读取**，`storage.get` 仅供迁移下载到 `storage/app/tmp`；站点预览完全走 HTTP 外链。
- 删除：`ftp_delete()`；FTP `550`（不存在）按成功；连接级失败整体失败，保留库行待重试。
- 与媒体库的接线：宿主在 `upload()` 的远程分支调 `storage.put`，在 `delete()` 的远程分支调 `storage.delete`；插件不感知 `media_files`。

**外链 URL 生成逻辑**

`rtrim(public_domain, '/')` 拼 `/media` 再拼 `object_key`，最后按路径段做一次 `rawurlencode`（保留斜杠）。FTP 协议本身没有 HTTP 外链，**外链完全依赖 `public_domain`**：`root_dir`（FTP 视角的根）与 `public_domain` 背后的站点目录是否一致，无法由插件校验，属 P-01。

## 推进与验收

### 五阶段

| 阶段 | 交付物 | 完成标准 | 验证方式 |
| --- | --- | --- | --- |
| 一、宿主接线 | 存储解析器、远程存储服务、`upload()` 与 `delete()` 两个分支点、`media_files.disk/object_key` 迁移 | 驱动恒为 `local` 时，媒体库行为与改动前**逐字一致** | 手工回归上传/删除/列表/重扫/引用检查；`composer analyse` |
| 二、首个插件（FTP） | `backend/plugins/addons/ftp/` | 三环验证通过（上传、外链可打开、删除后远程消失） | 见「三环验证」第 1 行 |
| 三、三个对象存储 | `qiniu` / `tencent_cos` / `aliyun_oss` | 各自三环验证通过，且四插件目录/配置/返回结构完全同构 | 见「三环验证」第 2–4 行 |
| 四、迁移能力 | 迁移起批与轮询接口、批次 Job、引用替换、只读审计命令 | 本地→远程、远程→本地各跑通一轮，失败项可重试 | 见「迁移验证」 |
| 五、管理端增量入口 | 驱动选择、迁移面板 | 既有列表/上传/删除交互零回归 | `frontend-admin-v3 && npm run build` 加手工回归 |

每阶段独立可回退：一、二阶段完成后禁用插件即回到纯本地；四阶段 `delete_source` 默认 `false`，未显式打开时源文件始终保留。

### 三环验证（上传 / 预览可打开 / 删除同步）

| 对象 | 上传 | 预览可打开 | 删除同步 |
| --- | --- | --- | --- |
| FTP | 后台选「FTP」驱动上传一张图片 | 复制外链在无登录态浏览器打开，返回 200 且内容一致 | 媒体库删除该文件 → 用 FTP 客户端查远端，文件已不存在；库行已删除 |
| 七牛云 | 同上 | 同上（私有空间需先按 P-03 裁决） | 同上，用控制台或 `storage.exists` 复核 |
| 腾讯云 COS | 同上 | 同上（公共读策略需先按 P-04 裁决） | 同上 |
| 阿里云 OSS | 同上 | 同上 | 同上 |

每环必须记录「操作、观察值、脱敏后的外链原文」，不接受「看起来正常」。

### 迁移验证（两轮）

1. **本地 → 远程**：选 3 个本地文件（含 1 个被设置为文章封面的），起批迁移到指定插件；核对 `disk` / `object_key` / `path` / `url` 四列、`settings` 与 `content_articles` 的引用已替换、旧本地文件在 `delete_source=true` 时被删除、`delete_source=false` 时仍保留。
2. **远程 → 本地**：把上一步的 3 个文件迁回；核对 `disk='local'`、`object_key=NULL`、`path` 回到 `/media/xxx`、`url` 由 `UploadUrl::resolve()` 重新生成、远程对象在 `delete_source=true` 时已删除。

两轮都要覆盖失败语义：断开网络或填错凭据使单个文件失败，确认批次继续执行、失败项进入 `failures[]`、已完成项未被回滚。

### 外链订正验证（换域名/协议后）

1. **订正前**：`php artisan media:storage-audit`，记录远程行的 `disk` / `object_key` / `path` / `url` 与「不变式违规」条数（应为 0）。
2. **空跑**：`php artisan media:storage-rewrite-urls`（默认 dry-run）。期望输出每行 `- #<id> <disk> <status>: <old> -> <new>`；改了 `public_domain` 后应为 `pending_updated` 且 `new` 是目标域名，汇总「待写入 N 条」「失败 0 条」。**此时库值必须一字未变**（再查一次库确认）。
3. **写库**：`php artisan media:storage-rewrite-urls --execute`，期望「写入 N 条」「未变化 0 条」「失败 0 条」，退出码 0。
4. **幂等**：同命令再跑一次，期望全部 `unchanged`、`写入 0 条`（`--json` 里 `"unchanged": N`）。
5. **引用连带**：订正前先把一个远程文件设为文章封面（或写进 `settings`），`--execute` 后核对 `content_articles.cover_image` / `settings.item_value` 已同步为新外链，`media_files.path === media_files.url`。
6. **浏览器复核**：新外链在管理端媒体库预览可见、复制到无登录态浏览器打开返回 200（这一步才是 P-15 的真正闭环）；再跑一次 `media:storage-audit` 仍为 0 违规。
7. **失败语义**：把插件 `public_domain` 清空（或断开网络），单驱动应整批 `url_failed` 并给出中文原因，库值不变、退出码非 0；恢复配置后重跑恢复为 `unchanged`。

### 命令门禁

`cd backend && composer analyse && composer format:check && composer audit:plugins`。依据 `backend/phpstan.neon.dist:11-19`（`paths` 已含 `plugins`，level 5）与 `composer.json` 的 scripts 定义；插件注册审计走 `plugins:audit-registrations`（实现类 `backend/app/Console/Commands/PluginRegistrationAuditCommand.php`）。

## 备选方案与取舍

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 远程行 `path` 存完整外链（本方案） | 不动 `UploadUrl`、`AdminMediaFileResource` 与前端；预览与复制天然可用 | `path` 列语义被扩宽，「复制路径」会复制成 URL | **采用** |
| 改 `AdminMediaFileResource` 让 `url` 优先取列值 | `path` 语义保持纯净 | 触及核心 Resource；`MediaFileService::toMediaArray()`（`:328-343`）是第二处同逻辑，需同步改，回归面更大 | 记为后续可选重构，本次不做 |
| 引入 Flysystem 与 S3 适配器统一四家 | 代码量小、生态成熟 | 需新增多个 composer 依赖（当前零存储依赖）；FTP 适配器对被动模式与编码支持需另配 | 不采用：与最小范围修改冲突 |
| 远程文件先落地本地再异步上传（双写） | 上传接口行为与今天完全一致 | 本地磁盘仍被占用，与「部分文件只存远程」的目标矛盾，且需要第二套后台任务 | 不采用；仅作 FTP 大文件超时的兜底提案（P-05） |
| 用 `driver_binding` 表达当前驱动 | 复用既有绑定表 | 四个插件同一 `binding_key` 会互相覆盖（`PluginInstaller::syncDriverBinding()` 的 identity 不含 `plugin_id`） | 不采用，改用 `settings` |

## 影响面与风险

| 面 | 影响 | 缓解 |
| --- | --- | --- |
| 数据 | `media_files` 新增 2 列；远程行 `path` 语义变化 | 迁移可空、有默认值；本地行四字段不变；`path===url` 不变式由只读审计命令守护 |
| 兼容 | 本地路径逐字不变；插件禁用即回退本地 | 分支点放在方法最前，本地分支不改一行；解析失败回落 `local` 并记 warning |
| 性能 | 上传多一次网络往返；100MB 上限下单次请求可能逼近 PHP 执行时间 | 插件超时可配（5–120）；超限行为见 P-05 |
| 安全 | 插件凭据、外链可公开读取 | 凭据加密落库、不明文回显；`local_path` 二次 `realpath` 校验防越权读盘 |
| 可用性 | 远程故障时上传失败 | 只影响走远程的写入；列表、预览与删除本地文件不受影响 |
| 部署 | 需要 `ext-ftp`；生产 PHP 扩展清单未核实 | P-13 明确复核动作；缺失时 `storage.test` 返回 `dependency_missing` 而非白屏 |
| 回滚 | 已迁移文件不会自动迁回 | 迁移方向对称、可反向执行；`delete_source` 默认 `false` 保证源文件留存 |
| 内容可达性 | 远程外链多为 `http://`（FTP 尤其），而三端 CSP 的 `img-src`/`media-src` 只放行 `https:`，外链直连 200 但浏览器拒绝渲染；且管理端是 https 页面，**即使放宽 CSP 仍会被混合内容策略二次拦截**（Playwright 实测：`img-src … http:` 后 http 页面 `naturalWidth=3942` 正常渲染，https 页面仍报 `Mixed Content` 且 `naturalWidth=0`） | 唯一可行路径：站点侧提供 HTTPS 域名、`public_domain` 改 `https://`，按 `object_key` 订正存量行 `path`/`url`。放宽 CSP 已在浏览器中证伪。见 P-15 |
