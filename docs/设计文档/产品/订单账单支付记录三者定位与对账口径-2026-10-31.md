# 订单、账单、支付记录三者定位与对账口径

本文回答一个反复被问错的问题：同一个用户、同一笔钱，订单、账单、收支明细各管什么，谁不能替代谁，对账时该拿哪张单子和哪个月份去比。三者不是同一条数据的三种视图，而是三类不同性质的单据，混用会让对账结论失真。

本文按公有云财务的通用口径描述三者职责与对账规则。账户侧概念（支付者、使用者、操作者 UIN，赠送金余额与冻结金额，近 18 个月在线查询窗口）是该口径的表述方式：本仓库以用户主键承载支付者与使用者、以现金账户承载可支配余额，字段命名差异不影响职责划分与对账结论。

## 一、订单

**功能定位**：订单在用户下单的那一刻由计费系统生成，是「这一笔交易本身」的单据。它承担四类用途——财务对账时定位交易、售后工单里描述买了什么、发票申请的凭据、出问题时定位到具体资源实例的凭据。订单是业务交易的唯一标识，向下串起费用计算、账单、支付与退款全环节。

**记录内容**：

| 分组 | 记录内容 |
| --- | --- |
| 交易主体 | 订单号、产品、资源类型、规格、数量、单价、付费方式、实付金额 |
| 人 | 创建人、付款人 |
| 时间 | 创建时间、付款时间 |
| 分类 | 订单类型（新购、续费、升级、降级等）、付费模式 |
| 状态 | 待支付（含失效时间，超时自动取消）、已取消（不可重新支付）、已过期；支付成功后进入资源分配流程 |

**分工边界**：订单只负责这一笔交易本身——规格是什么、金额多少、资源归属哪个 ID、什么时候生效、能不能开票或申请退费。订单**不负责**汇总周期消费，**不记录**账户余额变动。需要知道「这个月一共花了多少」或「账户里钱怎么动的」，都去看账单和收支明细。

## 二、账单

**功能定位**：账单反映一段时间内的消费金额与资源详情，是对账凭据。它支撑对账、成本分析、分账管理，并按产品、项目、计费模式、地域、标签等维度做汇总。

**记录内容**：

| 层级 | 口径 |
| --- | --- |
| 账单概览 | 当期总应收、总实收、总优惠，一个账期一行 |
| 多维度汇总账单 | 按产品、项目、计费模式、地域、标签交叉汇总的费用分布 |
| 资源账单 | 按资源实例归集的费用，回答「哪个资源花了多少」 |
| 明细账单 | 按计费项展开的最小颗粒度费用行 |

**字段结构**：支付者 UIN、使用者 UIN、操作者 UIN、产品名称、子产品名称、计费模式、交易类型等；预付费资源账单记录会带订单 ID，可与订单互相回溯。

**出账时间**：每月 1 号 19:00 生成上月完整账单，**出账前的费用仅供参考**，不作为对账依据。

**统计周期**：只影响按量计费资源的费用归属月份，不影响包年包月资源的归属。包年包月按购买当期一次性归集，按量计费按实际使用时间归集。

**分工边界**：账单只负责「一段时间内实际消费了多少钱、花在哪些资源和计费项上」，决定费用归集到哪个月、哪个产品、哪个标签，用于月度对账与成本分析。**消耗账单涉及费用分摊，仅供成本预估，不可用于对账**。

## 三、支付记录（收支明细）

**功能定位**：支付记录依托账户体系实时记录账户的收入与支出活动，是账户活动的信息流。用户可在费用中心「收支明细」中查找每月支出的摘要与细目。

**记录内容**：

| 分组 | 记录内容 |
| --- | --- |
| 流水主体 | 每笔资金流水的金额、交易类型 |
| 余额快照 | 交易后的赠送金余额、冻结金额（元） |
| 冻结与解冻 | 包年包月新购按「下单 → 冻结 → 发货 → 解冻 → 扣费」执行，可在收支明细中筛选查看 |
| 数据范围 | 在线查询近 18 个月，更早的数据需下载至本地查看 |

**分工边界**：支付记录只负责「钱在账户里怎么动」——充值、冻结、解冻、扣费、退款的资金流向与余额变化。它**不承担规格等信息，不做月度消费归集**。

## 四、总结

### 4.1 三者横向对比

| 维度 | 订单 | 账单 | 支付记录（收支明细） |
| --- | --- | --- | --- |
| 回答的问题 | 这一笔交易买了什么、多少钱、资源归谁 | 这一段时间消费了多少钱、花在哪些资源和计费项上 | 钱在账户里怎么动的、余额变成多少 |
| 时间属性 | 点状：一个时刻发生的一笔交易 | 段状：一个账期内的消费归集 | 点状：一次资金动作一行 |
| 核心标识 | 订单号 | 账单号 + 账期月份 | 流水号 |
| 主要用途 | 交易凭证、售后定位、发票依据、资源凭据 | 月度对账、成本分析、分账管理 | 资金流向追溯、余额核对、冻结解冻查证 |
| 不能替代谁 | 不能替代账单做周期汇总，不能替代收支明细做余额核对 | 不能替代订单做单笔交易凭证，不能替代收支明细做资金流水 | 不能替代订单提供规格信息，不能替代账单做月度消费归集 |

### 4.2 三者衔接逻辑

一笔业务从发生到入账，三者按固定顺序接力：

1. **下单生成订单**——用户确认购买，计费系统生成订单，记录规格、数量、金额与资源归属，此时订单为待支付。
2. **支付时资金动作落入收支明细**——支付动作发生时，账户侧写入一条资金流水，记录金额、交易类型与变动后余额；包年包月新购按「下单 → 冻结 → 发货 → 解冻 → 扣费」逐步落流水。
3. **下单完成后生成账单并按账单月份归集费用**——交易闭环后生成账单，费用按账单月份归集，预付费资源账单记录带订单 ID 以回溯到订单。

三者的关系是：订单是**发生**，收支明细是**资金动作**，账单是**归集**。一笔订单可以对应一条或多条资金流水，一张账单可以汇总多条订单与流水。

### 4.3 统一对账口径

| 规则 | 内容 |
| --- | --- |
| 时间口径选择 | 按扣费周期或计费周期选择交易时间与账单月份的对应关系，不以订单创建时间强行对齐账单月份 |
| 收支明细口径 | 收支明细**不含**代金券与代付金额，只统计真实资金流入流出 |
| 账单口径 | 账单**不含**代付金额 |
| 对账取值 | 对账统一使用**现金支付 + 赠送金支付**两类，代金券与代付不进入对账金额 |

对账时若发现账单与收支明细对不上，先按上表排查是否把代金券或代付金额计入了其中一侧，再排查交易时间与账单月份的归属口径是否一致——绝大多数差异来自这两处，而不是资金本身丢失。
