# 订单页与账单页优惠金额展示规范

适用用户端 frontend-user-v4-console 与管理端 frontend-admin-v3 的订单页、账单列表页、账单详情页。

## 版本修订

- v2（2026-10-31）：费用明细区块的归属由账单详情改为订单详情，固定在订单详情页最下方；账单侧只记录资金事实，不再出现任何金额拆分。v1 中「账单详情按原价 → 逐项优惠 → 实际支付金额展示费用明细」的条款作废，按本版执行。
- v2 同时把列头文案与运行代码对齐：列表页时间列统一为「创建时间」「结束时间」；管理端订单列表与管理端账单列表不单独设「支付渠道」列，支付渠道在支付记录与关联支付单中查看。
- v1 的实付金额同源口径、减项符号口径、金额格式口径继续有效。

## 一、页面结构

三页共用一套金额口径：实际支付金额在三页取同一个数值，用同一套格式化规则输出，任何页面都不得在前端做二次加减后再展示。优惠拆分只存在于订单详情的费用明细区块，账单侧只做资金事实记录。

### 1.1 订单页

用户端订单列表（`/client/orders`）

- 区块自上而下：页面标题区 → 筛选区 → 表格区 → 分页区。
- 列顺序：订单号、产品/服务、计费模式、实付金额、状态、支付渠道、创建时间、结束时间、操作。
- 实付金额位于第 4 列，列头「实付金额」，右对齐，单元格只放金额本身。
- 窄屏（<768px）表格转卡片：卡片内独立一行「实付金额：¥88.00」。
- 列表不出现原价、优惠券、会员折扣、优惠金额、优惠合计、折扣率、满减，也不出现任何负数金额。

用户端订单详情（`/client/orders/:id`）

- 区块自上而下：页头（面包屑 + 返回）→ 实付金额条 → 订单信息卡（页签：基础信息 / 产品配置 / 关联信息）→ 费用明细区块（页面最下方）。
- 订单信息区内的金额位只有一个：实付金额条里的「实付金额 ¥88.00」。金额条本身是页签之外的一条独立区块，与下方字段卡上下相邻构成「金额条 + 字段卡」两层，不嵌进字段栅格——栅格槽位是「12px 次要标签 + 14px 主文本值」，24px 金额塞进去既撑不开行高也抢不到层级。
- 金额条必须留在页签之外：放进「基础信息」页签内，切到「产品配置」时金额位会整块消失，违反「金额位始终可见」。
- 费用明细区块独立于页签之外，不随页签切换隐藏，滚动到页尾即可见；区块内不再重复实付金额。

管理端订单列表（财务管理 / 订单）

- 区块同上：标题区 → 筛选区 → 表格区 → 分页区。
- 列顺序：订单号、用户、产品/服务、类型、配置（仅升级单出现）、计费周期、实付金额、数量、状态、关联账单、创建时间、结束时间、操作。
- 实付金额右对齐，列头「实付金额」。

管理端订单详情

- 区块自上而下：概览指标卡 → 业务信息页签（基本信息 / 产品与配置 / 支付记录）→ 费用明细区块（页面最下方）。
- 概览指标卡中与金额有关的指标只保留「实付金额」一项；基本信息内不设金额区块。
- 费用明细区块与用户端同位置同顺序，仅外边距随本端设计体系。

两端差异：管理端多「用户」列、退款与补单入口；金额相关区块的行序、文案格式、取值范围两端完全一致，不设端点差异。

### 1.2 账单列表页

用户端账单列表（`/client/invoices`）

- 区块自上而下：页面标题区 → 筛选区 → 表格区 → 分页区。
- 列顺序：订单号、商品/服务名称、下单时间、实付金额、状态、操作。
- 首列双层：上行订单号，下行账单号；行主键仍是账单号。
- 实付金额位于第 4 列，列头「实付金额」，右对齐。
- 窄屏卡片：「实付金额：¥88.00」。

管理端账单列表（财务管理 / 账单）

- 列顺序：账单号、用户、账单项目、类型、计费周期、创建时间、实付金额、状态、结束时间、操作。
- 实付金额列头「实付金额」，右对齐，是全表唯一加粗的数值列。

两端一致：账单列表每条只显示实付金额，不展开优惠明细，不出现原价、优惠券、会员折扣、优惠合计。

### 1.3 账单详情页

账单只回答三件事：付了多少钱、怎么付的钱、关联了哪张账单与哪笔支付单。

- 区块自上而下：页头（面包屑 + 工具栏）→ 账单概览条（账单号、账单类型、账单状态、下单时间 + 实际支付金额）→ 支付记录（支付方式、支付状态、支付流水号、支付金额）→ 关联信息（关联订单、关联支付单）。
- 「实际支付金额」是账单概览条内唯一的金额位，突出显示；出现退款时另设退款信息区块，退款金额与退款时间只在该区块出现。
- 账单详情不出现原价、优惠券、会员折扣、优惠合计、任何减项金额行、任何金额拆分。

两端差异：管理端多退款操作与补单入口，账单概览条与支付记录的金额文案格式两端一致。

### 1.4 费用明细区块（订单详情，页面最下方）

位置

- 归属订单详情，是订单详情页的最后一个区块，位于「关联信息」之后。
- 区块顺序固定为：订单信息区（基础信息 → 产品配置 → 关联信息）→ 费用明细区块。三个既有区块的自身内容与内部顺序不变，费用明细只在其后追加。
- 不隶属于任何页签、折叠面板或弹层，不随页签切换而隐藏。
- 用户端与管理端同位置同顺序，差异只在间距与容器样式。

行顺序

行数随实际存在的优惠项变化，自上而下固定：

1. 原价：用计算式表达金额构成，形如「¥30.00/月 × 12 个月 = ¥360.00」。
2. 优惠券：显示优惠券名称与减项金额，形如「新人折扣 -¥30.00」。
3. 会员折扣：显示会员等级与减项金额，形如「v1 -¥60.00」。

行内布局与符号

- 每行左侧为名称，右侧为金额，同一行水平排布，金额列固定右对齐、共用同一右基线。
- 减项金额统一带负号，负号写在货币符之前，形如 `-¥30.00`，不得写成 `¥-30.00`。
- 原价行右侧是完整计算式（单价、计费单元、数量、等号、结果金额），其余行右侧只有金额。
- 区块标题固定为「费用明细」。

缺项处理

- 无优惠券：不保留空行、不保留占位文案、不留空白间距，会员折扣直接上移为第二行。
- 无会员折扣：该行整行不渲染，行序顺延，末行即原价或优惠券行。
- 两项都无：区块内只有原价一行。
- 其他优惠项缺失时同样按顺序顶替，行序顺延，不做补位。

### 1.5 账单侧保留与去掉

保留

- 实际支付金额：账单付了多少钱，账单概览条与支付记录各出现一次，取值一致。
- 支付方式、支付状态、支付流水号、支付时间：怎么付的钱。
- 关联账单：账单号、账单类型、账单状态、下单时间。
- 关联支付单：支付单号、渠道、金额、时间，可从账单直接跳转。
- 退款信息：有退款时展示退款金额、退款时间、退款方式。

去掉

- 原价、商品总额、费用明细区块。
- 优惠券名称与优惠券金额、会员等级与会员折扣金额、优惠合计。
- 任何减项金额行、任何负数金额、折扣率、满减。
- 账单侧不重复订单侧的计算式，不做金额再拆分。

## 二、字段说明

### 2.1 三页通用字段

| 字段 | 含义 | 展示规则 |
| --- | --- | --- |
| 订单号 | 生成账单的订单编号 | 纯文本，不截断；账单列表首列上行；空值显示「—」 |
| 下单时间 | 订单创建时间 | `YYYY-MM-DD HH:mm:ss`；空值显示「—」 |
| 商品/服务名称 | 账单或订单对应的产品名称，多商品时取合并名称 | 单行省略，悬停显示全称；空值显示「—」 |
| 账单号 | 账单唯一编号 | 账单列表首列下行、账单详情概览条；空值显示「—」 |
| 实付金额 | 该笔订单或账单实际支付的金额，三页同一数值 | 始终显示，不隐藏、不折叠；金额为 0 或空时显示 `¥0.00`，不用「—」 |
| 实际支付金额 | 账单详情中实付金额的展示名 | 与实付金额同值，仅文案不同；账单概览条突出显示 |
| 账单状态 | 待支付 / 已支付 / 部分已付 / 已取消 / 已退款 | 状态标签，颜色随状态；空值显示「—」 |
| 支付方式 | 余额支付、渠道名称等 | 纯文本；多渠道混合支付时按实际构成分行；空值显示「—」 |
| 支付流水号 | 第三方或内部支付单号 | 等宽字体，可复制；空值显示「—」 |

### 2.2 费用明细区块字段

| 字段 | 含义 | 展示规则 |
| --- | --- | --- |
| 额度与单位 | 单位时间或单位计量的价格与计费单元 | 形如「¥30.00/月」「¥360.00/年」「¥0.50/GB」；计费单元随计费周期变化 |
| 数量 | 购买的周期数或计费数量 | 紧跟单位，形如「× 12 个月」「× 1 年」「× 720 GB」 |
| 原价 | 单价 × 数量的结果，即未优惠前的商品总额 | 始终显示，是区块的第一行；与实付同为 0 时仍显示 `¥0.00` |
| 优惠券名称 | 抵用券的名称 | 作为该行左侧名称直接显示；无名称时回退为「优惠券」 |
| 优惠券金额 | 该券抵扣的金额 | 只显示绝对值并加负号；为 0 或空时不渲染该行 |
| 会员等级 | 会员折扣对应的等级名 | 作为该行左侧名称直接显示；无等级名时回退为「会员折扣」 |
| 会员折扣金额 | 会员身份带来的减免金额 | 只显示绝对值并加负号；为 0 或空时不渲染该行 |

### 2.3 无优惠与空值处理

| 情形 | 处理方式 |
| --- | --- |
| 单个优惠项为 0 或空 | 该行整行不渲染，不保留空行与占位，下方行序自动上移 |
| 两项优惠都为 0 或空 | 不渲染任何优惠行，区块内只剩原价一行 |
| 只有一项优惠 | 渲染两行：原价行 + 该优惠行，行序按固定顺序顺延 |
| 优惠名称为空 | 左侧回退为品类名「优惠券」「会员折扣」，金额照常显示 |
| 金额为空或非数字 | 按 0 处理：原价行显示 `¥0.00` 并保留，优惠行为 0 则整行不渲染 |
| 文本为空 | 显示「—」 |
| 原价等于实付 | 原价行照常显示，不因「无优惠」而省略区块 |

### 2.4 计算关系与校验

- 第一层：单元价格 × 数量 = 原价。原价行的计算式必须自洽，等号右侧等于左侧乘积。
- 第二层：原价 − 各项优惠合计 = 实际支付金额。费用明细区块内逐行可直接相减核对，实际支付金额取订单信息区那一处数值，不在区块内重复。
- 三层口径一致：订单列表、订单详情、账单列表、账单详情展示的实际支付金额必须是同一个数值。
- 校验：原价减各项优惠与实际支付金额的差额绝对值超过 0.005 视为数据异常。异常时按原始数值原样展示，不做前端修补，也不在费用明细区块内新增提示行或占位行。

## 三、展示文案

### 3.1 格式总则

- 货币符用半角 `¥`，紧贴数值，符号与数字之间不留空格：`¥88.00`。
- 千分位分隔，固定两位小数：`¥1,234.50`。
- 减项符号写在货币符之前：`-¥30.00`；禁止 `¥-30.00`、`30¥`、`30元`。
- 标签与数值同一行，中间一个半角空格：`实付金额 ¥88.00`。
- 冒号一律半角：`实付金额：¥88.00`。
- 计算式用半角运算符，运算符两侧各留一个空格：`¥30.00/月 × 12 个月 = ¥360.00`；乘号用 `×`，不用 `*`。
- 文案句尾不加句号。

### 3.2 各位置文案

| 位置 | 文案样式 |
| --- | --- |
| 订单列表列头 | `实付金额` |
| 订单列表单元格 | `¥88.00` |
| 订单列表窄屏卡片 | `实付金额：¥88.00` |
| 订单详情金额位 | `实付金额 ¥88.00` |
| 账单列表列头 | `实付金额` |
| 账单列表单元格 | `¥88.00` |
| 账单列表窄屏卡片 | `实付金额：¥88.00` |
| 账单详情概览条 | `实际支付金额 ¥88.00` |
| 账单详情支付记录 | `支付金额 ¥88.00` |
| 费用明细区块标题 | `费用明细` |
| 费用明细原价行 | `原价  ¥30.00/月 × 12 个月 = ¥360.00` |
| 费用明细优惠券行 | `新人折扣  -¥30.00` |
| 费用明细会员折扣行 | `v1  -¥60.00` |

### 3.3 费用明细区块完整文案序列

有优惠券且会员折扣，两行优惠：

```text
费用明细
原价    ¥30.00/月 × 12 个月 = ¥360.00
新人折扣                        -¥30.00
v1                              -¥60.00
```

核对：`¥360.00 − ¥30.00 − ¥60.00 = ¥270.00`，与订单信息区的「实付金额 ¥270.00」一致。

只有会员折扣，无优惠券，行序顺延为第二行：

```text
费用明细
原价    ¥30.00/月 × 12 个月 = ¥360.00
v1                              -¥60.00
```

核对：`¥360.00 − ¥60.00 = ¥300.00`。

只有优惠券，无会员折扣：

```text
费用明细
原价    ¥30.00/月 × 12 个月 = ¥360.00
新人折扣                        -¥30.00
```

核对：`¥360.00 − ¥30.00 = ¥330.00`。

无任何优惠，区块只有一行：

```text
费用明细
原价    ¥30.00/月 × 12 个月 = ¥360.00
```

核对：`¥360.00 = ¥360.00`，实付同为 `¥360.00`。

计费周期变化时的原价计算式：

| 计费方式 | 文案样式 |
| --- | --- |
| 按月 | `¥30.00/月 × 12 个月 = ¥360.00` |
| 按年 | `¥360.00/年 × 2 年 = ¥720.00` |
| 一次性 | `¥360.00 × 1 项 = ¥360.00` |
| 按量 | `¥0.50/GB × 720 GB = ¥360.00` |

### 3.4 账单侧文案

```text
实际支付金额 ¥270.00
支付方式 余额支付
支付流水号 2026103112345678
关联账单 BILL202610310001
```

账单侧只出现实际支付金额、支付方式、支付流水号、关联账单号与关联支付单号，不出现原价、优惠券、会员折扣、优惠合计与任何减项金额。

### 3.5 视觉层级

- 区块标题「费用明细」：14px、字重 600、主文本色，与下方明细留 8px 间距。
- 原价行：名称与计算式 14px、字重 400、主文本色；结果金额紧跟等号，同字号。
- 优惠行：名称 14px、字重 400、主文本色；金额 14px、成功色，负号与金额同色。
- 缩进：优惠行相对原价行左缩进 16px，用缩进表达「原价之下逐项扣减」的从属关系。
- 对齐：所有金额列右对齐、共用同一右基线；名称列左对齐。
- 分隔：区块与上方内容之间用 1px 分隔线隔开，分隔线上下各 12px 间距。
- 层级结论：原价是基准行，优惠行是递减行，实际支付金额在订单信息区以大号字重突出，构成「基准 → 递减 → 结果」的阅读顺序；账单侧不参与这条层级，只保留结果值。
