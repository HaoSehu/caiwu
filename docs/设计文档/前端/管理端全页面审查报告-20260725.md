## 二、性能审计

### 🔴 高严重度

**P1. MiddleChart.vue ECharts 实例内存泄漏**

- **位置**：`src/pages/dashboard/base/components/MiddleChart.vue`
- **说明**：`monitorChart` 和 `countChart` 两个 ECharts 实例在 `onBeforeUnmount` 和 `onDeactivated` 中均未调用 `dispose()`。仅取消了 `resizeFrame` 和 unwatch，图表实例永不释放。每个实例约 5-15MB。
- **建议**：在 `onBeforeUnmount` 和 `onDeactivated` 中调用 `monitorChart?.dispose()` 和 `countChart?.dispose()`。

**P2. ProductCatalog.vue 2705 行单体巨石组件**

- **位置**：`src/pages/products/components/ProductCatalog.vue`
- **说明**：单文件包含分类树面板、商品表格、商品编辑抽屉（4 个 tab）、配置项对话框、批量归类、拆分商品、主机名规则。所有响应式状态在同一个 setup scope 中，任何变更触发全组件 patch。
- **建议**：拆分为 8 个 composable + 7 个子组件（详见下文代码质量部分）。

### 🟡 中严重度

**P3. ECharts 仅被仪表盘使用但打包为独立 vendor chunk**

- **说明**：ECharts (~250KB gzip) 仅在 dashboard 页面使用，但仪表盘是默认首页（`redirect: '/admin/dashboard'`），所有用户首次加载都会拉取。
- **建议**：考虑将仪表盘默认页改为更轻量的页面，或将 ECharts 改为更细粒度的动态导入。

**P4. 全部表格无虚拟滚动**

- **说明**：23 个 `t-table` 使用点均无 `virtual-scroll` 属性。当前 pageSize 最大仅 100，暂无明显风险。但如果未来出现不分页的大数据表格，需引入虚拟滚动。

### 🟢 低严重度

**P5. 路由懒加载覆盖率 100%**

- ✅ 全部 42+ 条路由使用 `() => import(...)` 动态导入，无同步 import。

**P6. 打包配置良好**

- ✅ `resolveManualChunk` 拆分为 8 个 vendor chunk，策略合理。
- ✅ `minify: 'esbuild'`、`cssCodeSplit: true`、`sourcemap: false` 生产配置合理。
- ✅ `addEventListener` / `requestAnimationFrame` 清理正确。

## 三、布局架构 & CSS 体系审计

### 🔴 高严重度

**L1. mobile-overlays.less 与 layout.less 移动端弹窗样式严重重复**

- **位置**：`src/style/layout.less` L175-L235 vs `src/style/mobile-overlays.less` L13-L72
- **说明**：两文件都定义了 ≤768px 下的 `.t-dialog` / `.t-drawer` 覆盖样式，功能高度重叠但细节不一致（padding、!important 使用不同）。
- **建议**：合并到单一文件，删除重复规则。

**L2. 5 个页面无手机端响应式规则**

- **位置**：`staff/index.vue`、`roles/index.vue`、`logs/`、`settings/`、`notifications/`
- **说明**：这些页面仅适配到平板（1024px 或 768px），在 ≤480px 手机端不可用。
- **建议**：补充移动端断点规则。

### 🟡 中严重度

**L3. JS 与 CSS 断点不一致（991px vs 1024px）**

- **位置**：`SideNav.vue` L84 `MIN_POINT = 991` vs `layout.less` L51 `max-width: 1024px`
- **说明**：992-1024px 区间内 JS 认为不 compact 但 CSS 已解除最小宽度限制。

**L4. layout.less 730 行过于庞大**

- **说明**：混合了布局结构、组件覆盖、移动端响应式、菜单主题、滚动条样式等 5 类不相关样式。
- **建议**：拆分为 `_layout-structure.less`、`_menu-theme.less`、`_mobile-responsive.less`、`_tdesign-overrides.less`。

**L5. `color-scheme: light` 硬编码**

- **位置**：`src/style/reset.less` L3
- **说明**：告知浏览器仅支持亮色模式，但 setting store 支持 `theme-mode` 动态切换。浏览器原生控件始终为亮色。
- **建议**：改为 `color-scheme: light dark` 或随 `theme-mode` 动态设置。

**L6. Less 变量体系薄弱，9 种不同断点值无统一管理**

- **说明**：`variables.less` 定义了 4 个断点但全项目零使用。实际代码用了 9 种不同断点值（1280/1200/1024/768/640/560/480/420/360）。

**L7. 布局嵌套过深（10+ 层 DOM）**

- **位置**：`LayoutContent.vue` L2 顶层 `<t-layout>` 及 `SideNav.vue` 空占位 div
- **说明**：`LayoutContent` 内多余的 `<t-layout>` 和 SideNav 的 `side-nav-placeholder` div 可用 CSS 替代。

### 🟢 低严重度

**L8. z-index 层级体系基本合理**

- 移动 sidebar(1999) > 遮罩(1998) > TDesign popup(1000+) > 桌面 sidebar(200) > tabs(100) > header(10)
- 设置面板(z-index:100)可能被侧边栏(z-index:200)遮挡，需实测确认。

## 五、交互模式 & 信息架构审计

### 🔴 高严重度

**I1. 全局无批量操作**

- **说明**：全项目 `t-table` 无 `selectedRowKeys` / `@select-change` 用法。无法批量操作订单、用户、工单、内容。
- **影响**：管理员处理多条记录时效率极低。

**I2. useListPage 默认吞错误**

- **位置**：`hooks/useListPage.ts` L54
- **说明**：`catch (error) { if (onError) onError(error); }`——未提供 `onError` 时错误静默吞掉。列表空白无法区分"无数据"和"加载失败"。
- **建议**：默认至少 `console.error`，并暴露 `error` ref 供模板渲染错误态。

**I3. 零列表排序功能**

- **说明**：23 个表格无一配置 `sorter: true`。管理员无法按金额、时间、数量排序。

**I4. 续费/升级订单路由使用错误权限码**

- **位置**：`router/modules/admin/finance.ts` L43、L56
- **说明**：`meta: { permission: 'invoice.list' }` 应为 `order.list`。

### 🟡 中严重度

**I5. 财务管理菜单 7 项平级无分组**

- **说明**：全部订单/普通订单/续费订单/附加配置/账单/充值/新客户各占一行。
- **建议**：将订单子类型收敛为 tab 参数，减少菜单噪音。

**I6. 日志中心菜单 11 项实际为同一页面**

- **说明**：11 条路由指向同一组件 `logs/index.vue`，通过 Tab 切换。菜单中渲染为 11 个独立项。

**I7. 产品编辑表单缺少固定保存栏**

- **位置**：`products/edit.vue`
- **说明**：保存按钮无 `position: sticky`，长表单中需滚动到底部。

**I8. 顶部搜索组件为死控件**

- **位置**：`layouts/components/Search.vue`
- **说明**：输入框失焦清空，无 API 调用或路由跳转，纯视觉占位。

**I9. 筛选无防抖，空状态无重试按钮**

### 🟢 低严重度

**I10. 面包屑不显示动态标识**

- **说明**：详情页面包屑仅显示"用户详情"而非"用户详情：张三"。

**I11. 所有 hidden 路由均有程序化入口，无孤立页面** ✅

## 七、无障碍专项审计（Section 508 / WCAG 2.1 AA）

### 总体判定：存在系统性无障碍缺陷

| 指标 | 数据 |
|------|------|
| ARIA 属性使用点 | **仅 2 处** |
| skip-to-content 链接 | **0** |
| aria-live 区域 | **0** |
| aria-describedby 关联 | **0** |
| autocomplete 属性 | **0** |
| 语义化 `<main>` | **0** |
| 表格 caption | **0** |
| `:focus-visible` 样式 | ✅ 已实现 |
| `<html lang="zh-CN">` | ✅ |

### 🔴 高严重度

**A1. 无 `<main>` 地标，无 skip-to-content 链接**（WCAG 1.3.1 / 2.4.1）

- 键盘用户需 Tab 遍历上百个菜单项才能到达内容。

**A2. 全站 35 个页面无 `<h1>`-`<h6>` 语义标题**（WCAG 1.3.1 / 2.4.6）

- 仅登录页有 `<h1>`，其余页面完全依赖 TDesign 组件 title prop。

**A3. 图标按钮普遍缺少 aria-label**（WCAG 4.1.2）

- Header 折叠按钮、设置按钮、首页按钮、用户菜单按钮均无 `aria-label`。

**A4. 登录表单缺少 autocomplete 属性**（WCAG 1.3.5）

- 账号无 `autocomplete="username"`，密码无 `autocomplete="current-password"`。

**A5. 表单错误无 aria-describedby 关联**（WCAG 3.3.1）

- 屏幕阅读器无法感知表单验证错误。

**A6. ECharts 图表无文字替代**（WCAG 1.1.1）

- 仪表盘饼图和折线图对屏幕阅读器完全不可见。

**A7. 拖拽排序/右键菜单无键盘替代方案**（WCAG 2.1.1）

- 标签页拖拽排序、右键上下文菜单仅鼠标可操作。

**A8. 弹窗/抽屉无焦点管理**（WCAG 2.4.3）

- 打开后焦点不移入，关闭后不移回。

### 🟡 中严重度

**A9. 状态仅靠颜色传达**（WCAG 1.4.1）

- 虽有文字标签但颜色仍为唯一视觉区分手段（StatusTag、日志级别、用户状态）。

**A10. 登录页页脚对比度不达标**

- `#94a0b2` 前景在 `#f5f7fb` 背景上约 2.7:1，低于 4.5:1 要求。

**A11. 内容编辑页 heading 跳级**

- 5 个 `<h3>` 直接使用，跳过 h1/h2。

**A12. 必填字段无 `aria-required` 标记**

### 11.2 复审新发现

#### 🔴 高严重度（3 项）

**R1. LogDetailDrawer.vue 邮件 HTML 直接拼入 iframe srcdoc**

- **位置**：`src/pages/logs/components/LogDetailDrawer.vue` L315-L330
- **说明**：`buildContentPreviewDoc()` 将邮件 HTML 内容原样放入 `srcdoc`，未经任何消毒。虽然有 `sandbox` 禁止脚本，但 CSS 注入和外链资源仍可执行。
- **建议**：引入 DOMPurify 对 HTML 白名单消毒后再放入 srcdoc。

**R2. 密码修改弹窗无 autocomplete 属性**

- **位置**：`src/layouts/components/Header.vue` L76-L83
- **说明**：三个密码字段应分别设置 `autocomplete="current-password"` / `"new-password"` / `"new-password"`，当前全部缺失。

**R3. 标签页系统无最大数量限制**

- **位置**：`src/store/modules/tabs-router.ts`
- **说明**：`tabRouters` 数组无限增长，无上限保护和溢出处理。

#### 🟡 中严重度（4 项）

**R4. email-template-detail 模板 HTML 消毒不完整**

- **位置**：`src/pages/notifications/email-template-detail/index.vue`
- **说明**：模板变量值通过 `escapeHtml()` 转义（✅），但模板本身的 HTML 结构不做过滤直接拼接。

**R5. 路由配置 eager: true 导致所有路由配置同步加载**

- **位置**：`src/router/index.ts`
- **说明**：`import.meta.glob('./modules/**/*.ts', { eager: true })` 使所有路由模块同步加载，虽体积可忽略但阻止了 tree-shaking。

**R6. permission store 循环依赖风险**

- **位置**：`src/store/modules/permission.ts` L14 → `import { store } from '@/store'`
- **说明**：`store/index.ts` 又 `export * from './modules/permission'`，形成循环。

**R7. 标签页首页路由硬编码**

- **位置**：`src/store/modules/tabs-router.ts`
- **说明**：`homeRoute = [{ path: '/dashboard/base', ... }]` 路径硬编码，路由变更需同步修改。
