# 当前数据库结构说明

- 文档性质：参考资料 / MCP 实时结构速览
- 对齐时间：`2026-04-19`
- 读者画像：需要快速了解当前实库结构的后端、前端、DBA、联调人员
- 数据来源：MCP 直连 MySQL `information_schema` 与业务库 `idc`
- 数据库：`idc`
- 当前表数量：`41`
- 说明：
  - 本文是当前结构的可读化摘要，不是完整 DDL 导出。
  - 字段、主键、JSON 字段分布来自实库实时查询。
  - 当前未发现数据库级外键约束，表关系主要由业务字段维护。

## 1. 结构概览

### 1.1 主链路

当前库的核心业务链路比较清晰：

`users -> products -> orders -> payments / invoices -> services`

配套模块包括：

- 账户与流水：`user_accounts`、`account_transactions`、`balance_logs`
- 分销与返佣：`referral_rewards`、`referral_account_logs`、`referral_withdrawals`
- 优惠券：`coupon_campaigns`、`coupons`、`user_coupons`
- 内容与工单：`content_articles`、`content_categories`、`tickets`、`ticket_replies`
- 通知与系统日志：`notification_logs`、`email_logs`、`sms_logs`、`automation_logs`、`operation_logs`

### 1.2 结构特征

- 核心业务表普遍带有 `remark`、`operator`、`trace_id`，审计意识较强。
- 多处使用 `json` 字段保存价格快照、配置项、通知参数、附件和上下文。
- 用户资金相关字段同时存在于 `users` 与 `user_accounts`，目前是兼容并存结构。
- 工单、支付回调、服务开通、通知发送都保留了较明显的业务追踪字段。

## 3. 重点表结构

### 3.1 `users`

用户主表，除账号信息外还承载余额、分销、实名字段。

关键字段：

- 标识与账号：`id`、`email`、`phone`、`password`、`nickname`
- 基础资料：`company`、`qq`
- 支付资料：`alipay_real_name`、`alipay_account`
- 分销关系：`referral_code`、`referrer_user_id`、`member_level_id`
- 资金字段：`balance`、`credit_limit`
- 分销金额：`total_sales_amount`、`referral_frozen_amount`、`referral_available_amount`、`referral_withdrawing_amount`、`referral_withdrawn_amount`
- 实名字段：`is_verified`、`real_name`、`id_card`、`verification_status`、`verification_message`、`verification_certify_id`、`verified_at`
- 登录与维护：`last_login_ip`、`last_login_at`、`admin_note`
- 生命周期：`created_at`、`updated_at`、`deleted_at`

### 3.2 `user_accounts`

账户子表，集中存储余额与返佣账户维度。

关键字段：

- 主键：`user_id`
- 余额：`cash_balance`、`credit_limit`
- 返佣余额：`referral_frozen_balance`、`referral_available_balance`、`referral_pending_withdrawal_balance`、`referral_withdrawn_balance`
- 并发控制：`version`
- 时间：`created_at`、`updated_at`

### 3.3 `products`

商品主表，包含定价、配置项、SEO 字段、供应商关联。

关键字段：

- 分类：`product_group_id`、`product_type`
- 基础信息：`name`、`description`
- SEO：`meta_title`、`meta_description`、`meta_keywords`
- 定价与配置：`pricing`、`setup_fee`、`config_options`、`purchase_requires`
- 供应与库存：`stock`、`supplier_id`、`supplier_product_id`、`supplier_product_name`
- 开通能力：`provision_module`、`auto_setup`
- 状态：`status`、`sort_order`
- 生命周期：`created_at`、`updated_at`、`deleted_at`

### 3.4 `orders`

订单表，保留商品、优惠券和配置快照，是交易主链路的中心表。

关键字段：

- 标识：`id`、`order_no`
- 关联：`user_id`、`product_id`、`service_id`
- 快照：`product_name_snapshot`、`product_type_snapshot`
- 订单维度：`type`、`billing_cycle`、`quantity`
- 优惠：`coupon_id`、`user_coupon_id`、`coupon_code`、`coupon_snapshot`
- 金额：`amount`、`discount`、`paid_amount`
- 配置快照：`config_snapshot`、`config_pricing_snapshot`
- 状态与时间：`status`、`paid_at`、`created_at`、`updated_at`
- 审计：`remark`、`operator`、`trace_id`

### 3.5 `services`

服务实例表，代表开通后的实际资源或订阅。

关键字段：

- 关联：`user_id`、`product_id`、`order_id`
- 资源信息：`name`、`domain`
- 计费：`billing_cycle`、`amount`、`locked_pricing`
- 状态：`status`、`expires_at`、`auto_renew`、`suspended_reason`
- 开通结果：`provision_data`
- 审计：`remark`、`operator`、`trace_id`
- 生命周期：`created_at`、`updated_at`

### 3.6 `payments`

支付记录表，承接订单或账单支付。

关键字段：

- 标识：`id`、`payment_no`
- 关联：`user_id`、`order_id`、`invoice_id`
- 支付渠道：`gateway`、`trade_no`
- 金额：`amount`
- 支付状态：`status`、`paid_at`
- 回调原文：`callback_raw`
- 审计：`remark`、`operator`、`trace_id`
- 生命周期：`created_at`、`updated_at`

### 3.7 `invoices`

账单表，支持账单号、到期日、支付金额和订单关联。

关键字段：

- 标识：`id`、`invoice_no`
- 关联：`user_id`、`order_id`
- 账单类型：`type`
- 金额：`amount`、`paid_amount`
- 状态：`status`
- 时间：`due_date`、`paid_at`、`created_at`、`updated_at`
- 审计：`remark`、`operator`、`trace_id`

### 3.8 `settings`

系统配置表，结构极简。

关键字段：

- 主键：`id`
- 分组：`group_key`
- 配置键：`item_key`
- 配置值：`item_value`

## 5. JSON 字段分布

当前包含 JSON 字段的表如下：

- `automation_logs`: `meta`
- `coupon_campaigns`: `weekdays`、`billing_cycles`、`product_ids`
- `coupons`: `billing_cycles`、`product_ids`
- `invoice_items`: `meta_json`
- `notification_logs`: `params_json`
- `operation_logs`: `context`
- `orders`: `config_snapshot`、`config_pricing_snapshot`、`coupon_snapshot`
- `payment_callbacks`: `payload_json`
- `payments`: `callback_raw`
- `products`: `pricing`、`config_options`、`purchase_requires`
- `roles`: `permissions`
- `servers`: `module_config`
- `services`: `locked_pricing`、`provision_data`
- `sms_logs`: `params`
- `ticket_replies`: `attachments`

## 6. 结构观察

- `orders`、`payments`、`invoices`、`services` 共同构成交易主链路，但数据库层未设外键，应用层一致性要求较高。
- `users.balance` 与 `user_accounts.cash_balance` 并存，后续涉及余额变更或账务重构时需要优先确认真实写入口。
- `products.pricing` 与 `services.locked_pricing`、`orders.config_pricing_snapshot` 说明系统采用了“下单时快照锁价”的思路。
- `payment_callbacks.payload_json` 与 `payments.callback_raw` 同时存在，支付回调链路审计数据较完整。
- `content_articles`、`products`、`content_categories` 已包含较完整的 SEO 字段，适合继续对接站点 SEO 改造。
